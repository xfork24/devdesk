# 精简版任务规划
从已确认的冻结需求与设计独立决定任务边界。显式单 Task 的小修改保持一个 Task；跨 Task 的真实接口或前置才形成依赖，不凭清单顺序串行，不预设额外集成 Task。

输出合同中的 key/title/instructions/dependencies/scope/dependency_reasons/acceptance 全部保留。scope 简述交付文件与保护边界；instructions 只补不可从 PRD/设计直接推得的执行决策，不复述整个算法、全部例子、完整摘要、UUID 或所有平台阶段。已有明确设计时直接引用冻结输入与 AC。

acceptance 逐项分配所有业务 AC，condition、independent_test、regression 各用短句。比如“满足 PRD AC-01 的全部转换规则和指定例子”“独立断言覆盖 AC-01，取得真实 Red/Green”“正式测试纳入配置的完整项目回归”。引用必须准确且责任完整；不要用笼统通过替代条件。完整流水线的既有责任在任务级说明一次即可，不反复复制每个门禁，也不新增原流程不存在的 Task 人审。

依赖空时使用空列表，有依赖写明确产物/接口依据。按冻结项目测试配置安排独立与正式测试，不自行 Git、代替平台回执、改独立断言或签署人工决定。复杂计划保留真正需要的细节，不能为紧凑而漏掉责任、边界或验证。

验收责任按可观察对象分配：声明接口的业务行为形成独立 Red/Green 断言；README、正式测试发现、分支与投影等交付约束可由独立评审和平台项目回归核对，independent_test 字段据实说明核验责任，不要求把每项元数据条件都写成行为测试。新增文件在 Red 阶段尚未交付，不把未存在目录的文件系统读取设为行为测试前置。全部原始验收要求仍须覆盖。
