# Independent Review

## 使用当前阶段的证据

核对受评材料的冻结版本、相关上游输入和本步骤 Spec。需求关注可验收行为，设计关注接口、边界、失败模式和实现可行性，任务计划关注覆盖、依赖和责任。其他评审场景按当前合同核对相应代码或候选。复审逐项验证原问题是否关闭。

## 形成独立判断

沿验收条目、接口和异常路径检查实质内容。标出问题位置、影响、严重程度、建议及重新验证条件，区分阻断问题、非阻断建议与未知事项。已知内容缺陷交付带证据的拒绝结论，缺少必要事实时指出缺少的材料。

## 按端口提交

正式内容评审使用当前端口的 `required_checks`，每个 key 恰好一次，并提供 `passed` 和定位证据。以 `approve`、`summary`、`checks` 表达结论，按当前响应封套提交。使用交付自检核对冻结定位。评审结论和后续人类决定分别记录，覆盖仅在当前合同允许时由人类作出。
