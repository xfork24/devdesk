# Task Planning

## 设计可执行的任务图

依据已确认的 PRD 与设计分解工作。显式单 Task 或范围内的一次小变更保持单项任务。根据接口与产物建立直接依赖，边上记录具体理由；无依赖使用空列表。明确文件和行为边界，独立的任务保持可并行。

## 分配验收责任

每项任务填写 `key`、`title`、`instructions`、`dependencies`、`scope`、`dependency_reasons` 和 `acceptance`。使用 `condition` 指向确切 AC，使用 `independent_test` 和 `regression` 说明验证责任。接口行为由独立断言覆盖，README、测试发现、分支等交付要求按适用的评审和回归核对。新增文件在 Red 前可能尚未交付，计划须支持真实的业务失败。

## 提交之前

走查无环性、依赖可获得性、全部 AC 的覆盖，以及各任务的交付所有权。任务说明只补上游材料无法推得的执行决定；引用确切输入代替复制完整文档。平台按已确认的图创建任务。
