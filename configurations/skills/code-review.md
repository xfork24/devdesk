# Code Review

## 确定评审对象

读取当前范围的完整 Diff、冻结需求与设计、Task 边界和已有测试。先确认比较端点及对应版本，再核对正确性、接口兼容、失败恢复、测试覆盖与必要文档。评审保持独立和只读。

## 按阶段使用证据

Task 评审核对真实 Red/Green、用例有效性以及未改写独立测试。Feature 评审关注汇合后的完整差异、跨 Task 接口和组合行为，按发现追查各 Task 的原始证据。不要求后续项目回归、PR 或试合并候选已经生成。

## 提交结论

报告每个问题的位置、严重程度、影响和修订建议。判定缺陷时保留 `approve: false` 和确切证据。人类例外仅能依据当前政策作用于其明确签署的材料。
