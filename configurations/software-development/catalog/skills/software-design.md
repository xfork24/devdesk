# Software Design

## 从需求推导设计

核对已确认的 PRD、工作区和测试配置。从现有系统的模块、接口、数据和状态出发选取可实现的最小方案。记录关键取舍、外部依赖、所有权和故障边界。涉及多任务时明确接口交接及可并行边界。

## 保持关键决定可验证

按 Design Document Specification 的标题组织正文。使用短示例或签名说明接口行为，标明需要保持的约束、失败后的状态和重试条件。用 AC 编号连接独立行为测试及项目回归。复杂度决定篇幅，需求规则与指定例子由 PRD 持有。

## 交付前核对

检查方案能在冻结工作区及项目语言下实现。把实际观察和未核实假设分开，列出需要决定的问题。保留评审、测试、人审及版本门禁的原有职责。
