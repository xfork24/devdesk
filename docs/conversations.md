# 讨论与经验

本文描述会话域的操作语义：自由讨论与工作流会话的边界、运行时交互、提案采纳、权限改绑检测与经验恢复。命令合同见 [本地协议](protocol.md)，会话对象定义见 [领域规范](domain.md)。

## 会话范围与工作类型

会话有四种范围：Global（跨项目）、Project、Feature、Task。Agent 会话按工作类型分三类：**Workflow**（业务步骤执行）、**Discussion**（自由讨论）、**Orchestration**（编排或经理工作台）。会话创建时冻结 RuntimeBinding（模型连接与参数、Agent 配置、权限锁、运行时安装、接入锁和适配器内容身份）。配置源后继不会改写旧绑定；冻结环境失效时必须核对或创建后继会话，不能按显示版本标签自动换环境。

Agent 身份用 AgentID（Agent 实例）表达：全局身份可跨项目积累经验，项目身份不能用于全局讨论。切换身份立即清空旧会话列表并作废在途请求。

## 自由讨论与工作流会话的边界

工作流步骤会话（正式会话）**禁止自由输入**：任务只能来自冻结的工作流执行意图，发送内容必须与冻结任务的规范渲染逐字节一致——不能通过 `conversation.send` 提交伪造的 task、任务指令或来源；补充输入沿用原步骤任务。界面会把正式会话引导回执行页。编排会话不挂载业务代码视图，控制器经受限编排工具操作，不直接写 owner 的 worktree。

同一会话同时只能有一个活动轮次；轮次以 client_message_id 幂等；终态轮次不可撤销。轮次终态由内核裁定：需要供应商的静止观察与消费证明，或真实的停止与写撤销证据；错误进入待核对，输入绝不重发。

## 运行时交互

执行中可能出现两类等待人的交互：

- **工具审批**：允许本次调用或拒绝/取消（经系统凭据与权限边界后放行）。
- **澄清问题**：Agent 提出的选项问题，逐题回答（可选择项或自定义答案）。

回答单调收敛，不可撤销已回答的问题；交互记录与回答作为事实保存。

## 提案

讨论产出的结构化材料用 Proposal（v2）表达：保存交付类型、标题、值与输入引用。可从完成轮次提取（`proposal.extract`）或手工创建、修订。**采纳（adopt）**要求目标范围的当前修订等于提案的 expected_revision——防止把基于旧版本的提案应用到已更新的对象；采纳只建立类型化材料，创建 Feature/Task 需要明确的平台操作。工作流步骤的产物不走提案，由步骤输出合同接收。

## 权限改绑检测

向追随目标权限的讨论会话发送输入时，内核检测目标权限绑定是否变化：未变则直接执行；变化则编译新档案、克隆绑定并经三段式切换生成**后继会话**（见 [运行时权限](permissions.md)）。原命令与消息 ID 保持幂等，界面跟随有效会话；已冻结的工程执行与技术重试保留原权限，不被新绑定改写。

## 经验

会话在完成等关键点自动保存快照（消息、轮次状态、文档、运行时绑定），并按 AgentID 登记经验记录。经验是**只读历史材料**：

- 跨项目查询不切换活动项目、不启动源 worker、不修改任何库；不可用项目单独上报。
- 快照详情带完整性校验（integrity: verified），可展开摘要与内容。
- `experience.restore` 把历史快照导入为新会话的**上下文**：恢复讨论可以从历史继续，但不恢复执行状态、不改写代码/配置/文档修订——导入的材料只是背景。

经验定位可以把来源条目跳转到原项目/Feature/Task（跨项目时先切换项目）。

## 独立项目经理工作台

项目管理中的经理工作台以 `manager.open` 绑定单个项目，可以选任意具备所需工具和实际 Harness 能力的 Agent 精确修订及授权上下文。没有 Feature/Task、根实例使用 Rust 驱动时仍可对话。工作台不取得根实例调度权；当前实例的调度/计划变更仍须对应根控制授权。没有未消费用户输入时不主动触发新的工作台模型轮次。

原生工具按冻结 Capability 注入，`project.*` 提供完整记录类别、分页目录、分块正文/产物及实际资源报告；概览标记 overview_only，列表/正文返回总量、续读位置和摘要。调用固定项目服务，参数不能改项目。系统凭据字段遮蔽，不向经理开放凭据库、任意 RPC、SQL 或文件路径读取。

`configuration.*` 复用 UI 的精确源变更集。预演权限绑定到 Controller/会话/epoch，允许同一会话后续 Turn 使用预演，实际应用仍记录确切 Turn/调用。默认授权允许项目配置创作；共享目录修改另需冻结策略的 `configuration.global.write`。共享发布+项目采用走 `configuration.transfer.stage/apply/status/cancel`，沿用跨库恢复管线并保留原 Actor。停用共享定义前核对全部项目快照。

配置修订和实例 create/rebind/remove、权限绑定、Skill 包导入可组合预演/应用。后继修订、未来采用与当前运行变更分别明确处理；历史和其他消费者保留原引用。经理不能换绑当前会话的 Harness/Sandbox 权限目标。自身实例换绑/移除后先交付工具回执，再撤销旧会话；后继组合由人类入口重新采用。新权限/Capability 源不会改变本次调用的冻结权限。

项目重新采用经理 Agent 或 Permission Context 时，先保存接续意图并停止、核对旧 writer，再以快照创建后继。旧 Controller、会话和工具回执保留，不靠重新打开工作台掩盖未知执行。工作台已有但尚未消费的用户输入按原身份处理，不把空闲工作台变成自动根调度器。
