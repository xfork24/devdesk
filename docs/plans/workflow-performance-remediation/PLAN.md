# 工作流性能与可靠性修复计划

状态：待实施。制定日期：2026-11-18。本次仅制定计划，不恢复已暂停的测试、工作流、模型调用或容量矩阵。

调研源码基线：`5ccafc4`，调研开始时工作区干净。本计划承接 [联合验收的问题清单](../integrated-workflow-performance-acceptance/OPEN-ISSUES.md) 和 [原后续修复计划](../integrated-workflow-performance-acceptance/FOLLOW-UP-PLAN.md)，作为下一阶段的实施安排；原计划和历史验收记录保留原文。下文的 S0–S8 是本计划的阶段编号，R1–R14 沿用原问题编号。

## 1 目标、依据与范围

本轮优先解决剩余读取与平台衔接成本、真实页面请求放大、经理调度效率及时间预算可靠性。先集中修复并完成定向验证，再冻结候选安排必要的真实链路；不为每个问题重复新开完整 Feature。步骤物理存储先测量再决定结构改造，正式 100 浏览器容量作为独立的条件阶段。

依据：

- [联合验收报告](../integrated-workflow-performance-acceptance/ACCEPTANCE.md)、[性能基准](../integrated-workflow-performance-acceptance/PERFORMANCE.md)、[执行记录](../integrated-workflow-performance-acceptance/EXECUTION.md)。
- [运行性能验收合同](../workflow-runtime-performance/ACCEPTANCE.md)、[单 Host 并发验收合同](../single-host-concurrency/ACCEPTANCE.md)。两份合同的指标、数据规模、轮次及正确性要求继续有效。
- [仓库指南](../../../AGENT.md)、[SQLite 结构](../../../sql/README.md) 以及本次只读核对的当前代码。待实施内容不代表现有接口或已验证能力。

计划交付分为三层，分别判定：

| 层次 | 交付与完成要求 |
|---|---|
| 修复和专项验证 | R13 工具修复、R14 热路径优化、R5 本机页面定位、R8 策略优化；R2 完成设计及相应实现。每项有复现、改动、负向回归和同条件结果；未达标项继续开放。 |

## 2 当前事实与问题承接

### 2.1 历史成绩的使用边界

下表均为原报告记录的 macOS arm64、8 逻辑 CPU、16 GiB 共享机器成绩，本次未重新测量。r32 使用冻结 r29 Web；调研源码基线不能视为 r32 二进制身份，也不能直接把后续其他机器上的数值与其计算因果加速比。

| 现场 | 已有证据 | 本轮含义 |
|---|---|---|
| 稳定 Human 等待 | 同探针 CPU 从单核 24.2732% 降至 0.3302%，r32 采样 60.57 s | 已取得的单场景改进，保留为回归项，不重复开发等待态优化。 |
| 同一 Feature9 历史的经理视图 | 各 30 样本，r27→r32 P95 499.97→26.60 ms，响应均 24902 bytes，源恢复 180→0 | R9 已修；缓存命中/绕过、数据及页面身份必须匹配后才能比较。 |
| 同一历史的完整 control API | 3363134 bytes；r27→r32 P95 418.81→587.76 ms，表解码 330→229 | R14 仍需定位，不能以解码次数减少宣告响应全面提速。 |
| 短原生 0/100 协议客户端 | r32 各 21/23 次往返，P95 100.86/248.52 ms；慢项含 execution.inspect、artifact.read | 仅探索样本；100 前端合同 P95 门槛为 500 ms，不能套用 0 前端的 200 ms 判定正式失败或通过。 |
| Feature9 长流程 | 315 次原生往返 P95 1320.05 ms；排除辅助构建重叠的子集仍为 694.20 ms | 长历史成本不能被短流程成绩替代，R14 必须包含复杂历史场景。 |
| Feature9 发布 | 最终 21/22；等待实际远端合入时达到冻结 1800 s，经理自主恢复后重复发布被 lease 拒绝 | R2 预算尚缺；R11 已有严格回执复用实现和隔离链证明，真实经理异常恢复尚缺。 |
| Feature10 审批观察 | materials 含当前评审执行及上下文，evidence 为空，观察器断言退出 | R13 是工具合同问题，原退出 1 保留，不由此认定合法审批请求无效。 |
| 100 页面探索 | 排队/点击超时失败，发生器进程树 RSS 总和约 20.6 GiB | 页面与发生器成本未分清；不能直接断言 Host 瓶颈或 OOM，不能用 HTTP/SSE 代替页面成绩。 |

## 5 工作包与专项验收

### S0：冻结输入，修复 R13

1. 记录当前源码/差异、实际 Host/Web/配置/脚本内容身份、SQL 基线、数据种子和资源预算；使用专用数据集、私有二进制和独立端口。将构建、造数、采样分开。后台与 Web 身份分别登记，UI 变化只使受影响证据重新验证。
2. 原报告证据位于 macOS 临时目录，本次环境未取得该目录。执行前先核验可用归档；若缺失，依据当前代码构造脱敏、合法的最小夹具，明确其为重建复现，不能声称重放 Feature10 原请求或恢复原现场。
3. 建立“生产合法性、材料审阅充分性、页面展示、观察器结构检查”合同矩阵。合法性以生产路径为准；人类签署仍须核对必需原件、当前执行、上下游及版本，不能把删除非空断言解释为降低审阅要求。
4. 共享观察辅助逻辑放在现有 `workflow_observer.py`，修复两个实际探针及页面核验中的分类假设；先耐久保存完整有界请求、身份和 URL，再输出结构化核验结果。缺依据、过期或越权时不得签署，保留可诊断失败；观察器不补请求、不代调度、不扩大原期限。
5. 将旧仅测试 validator 的有关覆盖迁入生产命令路径/真实 SQLite 回归，删除或消除分歧，不用测试旧实现通过代替生产证明。

**退出用例：** 当前执行引用仅位于 materials、仅位于 evidence、两类都有；合法空分类；缺当前执行/必需输出/上游；错项目/根；旧 execution/input_digest/output；错 session/turn；待批期间计划或材料变化。正向可展示核验，负向保留且不签署。两个探针都必须验证“保存早于检查失败”，现有四项 manager_activity 工具回归继续通过。本阶段无需模型、GitHub 或完整 Feature。

### S1：修复 R14，测清读取与平台空档

1. **从调用者分层。** 追踪普通页面、经理原生工具、明确的输入/合同/原件读取和兼容 control。静态搜索加实际请求账本确认频率、大小与缓存行为；完整 control 只有确认消费者后才能迁出热路径，不能仅改名为重接口。
2. **固定复现。** 使用相同只读数据库和参数，分别测小历史、复杂长历史、大小分组的 artifact.read/execution.inspect/control；每个目标方法先取至少 200 个定位样本，分开冷/热及显示缓存命中/绕过。记录源恢复、SQL 行/字节、资源读取、解码、JSON 编码、发送和发生器队列。
3. **缩小实际工作量。** 普通调用只取分页头、状态、版本、可用动作和必要摘要；输入正文、合同及产物按确切执行/ref 懒读或按原合同分块。移除同请求重复恢复/解码/编码；不可变内容或显示缓存绑定 Host、项目、资源及版本，授权与提交重新读权威事实。完整原件继续可读。
4. **检查平台衔接。** 沿请求可读→登记→派发→实际结束→结果接纳→写回→事件投递定位空档；检查补扫等待、已就绪结果重复读取、慢 Git/Docker 占满短交付及批次串行等待。只优化已授权技术工作、通知、去重和公平，不让 Host 选择下一业务节点。
5. **逐项验证收益。** 单方法对照后做同参数 0/100 协议各 120 s 短轮；保留慢项目、取消、停止、worker 代次/计划变更、迟到结果及后台持续推进。短轮不包含新的完整 Feature。

**退出条件：** 普通读零完整工程恢复、零隐式业务写；跨项目/根拒绝、原输出完整可读、分页/分块内容一致、快照版本对应，缓存和迟到响应不改变权限或草稿。报告所有目标路径的 P50/P95/P99、bytes 和成本计数；已优化的目标必须有可解释收益。其他同方法 P95 退化不超过 `max(10 ms, 基线的 10%)`，且绝对门禁另行核对。200 样本和 120 s 只算专项，不能关闭正式逐方法 SLA。

### S2：R5 本机页面、事件与发生器定位

1. 固定实际待发布 Web，覆盖执行页、经理页、上下文/材料、阶段/子流程及跨项目导航。逐动作记录计划/实际发送、RPC 数及 bytes、同键并发、完整正文读取、可见状态版本、操作可用时间及主线程长任务。
2. 检查重复组件读取、事件失效范围、隐藏标签页轮询、列表/子流程展开及无关区域重绘；依据瀑布修复，沿用现有共享请求和背压。隐藏/折叠期间可停止无效刷新，恢复时仍须补读最终版本。
3. 用每页 1 次读取动作/s、每 10 s 一次修改、每 20 s 一次导航的比例做 1/10/25 页面各 120 s 定位；动作安排固定种子且记录实际 RPC。50/100 仅在资源和发送队列可维持时继续，不以延长超时或减少动作换通过。
4. 单列 Host、Docker/worker、发生器、Chromium 的 CPU/RSS/队列；进程 RSS 总和作为诊断指标，不能当作唯一物理内存或 OOM 证明。发生器失速时保存未发送动作和资源现场，停止该阶梯，报告已证实的最高并发。
5. 联合验证不同目标耐久写/原版本冲突、项目和订阅隔离、隐藏/恢复、慢订阅者、断线重连、草稿保留及后台吞吐。回读须在 Host 停止前核对确切资源、版本和最后内容，清理阶段另记。

**退出条件：** 每个定位问题均有实际页面复现和同条件前后样本；普通页面不拉全历史、同键请求有界、最终版本和可用操作收敛。协议与页面成绩分开，后台保持实际派发/产物/接纳；未达到的并发和资源条件继续开放，不能以 100 个 SSE 或低 HTTP P95 关闭 R5。

### S3：R8 经理调度，补 R4 通知链

1. 复用已存轨迹和新短链，按 Actor、执行、operation、等待原因分解经理 Turn、模型服务、执行者、平台 I/O、待接纳、Human 及发布等待；建立关键路径和非重叠区间，不把 41 Turn 的 1831.53 s 减去 RPC 总和当作纯推理时间。
2. 标记无新事实的重复读取、重复通知、没有新增业务判断的控制回合，以及已授权连续技术转换；基于现有 segment 精确节点和额度设计采用策略。并行派发只适用于依赖已满足、资源独立且经理实际授权的工作。
3. 技术异常、版本/输入/计划变化、未知副作用、配额或 Human 边界必须停下并回流经理；独立测试、评审和业务取舍保留。无变化时登记实际对象/事件/期限等待，不通过忙轮询减少可见延迟。
4. 需要策略变更时发布新的 Skill/Capability/Agent/Workflow/Standard 必要闭包修订；旧冻结任务保持原引用。不得按步骤名或业务 key 在内核硬编码下一步。
5. 用现有 publication 创建观察验证“经理可读→页面原件可定位→经理自主通知”的局部链。核对候选、PR、原调用/请求/观察身份及时间；明确其是历史创建凭据，不是当前远端状态、最终回执或合入授权。重复事件不重复无变化通知。

**退出条件：** 先以可控端口、真实 Host/SQLite 覆盖合法 segment、越权/跨根、Human 阻断、取消/代次撤销、未知不重发和异常回流；稳定后必要时做真实经理短链。同业务图/输入/模型/预算对比 Turn、重复读取、派发/接纳空档和关键路径，0 外部调度指导、0 Human 代接纳。不预设必须减少多少 Turn 或整体快几倍；无收益就继续开放对应优化。

评审拒绝后的研判、三种返工方式、业务返工额度和人工例外属于 [独立计划](../review-rejection-and-approval/PLAN.md)。本项只处理重复回合成本及接口衔接，不另建返工/审批规则；R2 时间预算也不替代业务返工额度。

### S4：R2 时间预算设计与实现，补 R11 可靠性证据

**先形成计时合同。** 在已有等待区间并集上明确每类时间的起止、计费范围、持久事实和期限动作，所有有限值由冻结配置/合同确定：

| 时间类别 | 必须作出的设计决定 |
|---|---|
| 活动预算 | 模型执行、平台本地处理、派发前排队分别归属谁；哪些等待可扣除，哪些必须计入，不能把本机拥塞归到外部服务。 |
| Human/外部事实等待 | 审批、发布合入、父子等待如何开始/结束；重叠等待只扣一次，重复通知不重置起点；等待仍受明确期限约束。 |
| 平台操作 deadline | 实际 I/O、断连、无可核对结果何时截止；到期先停止/撤权并核对未知效果，不假定未生效。 |
| 总墙钟 | 从何时起算、覆盖哪些重试/子调用和停机时段；必须有限且不因重试、重启或改名自动重置。 |
| 无进展 watchdog | 何种事实是有效进展；纯日志、轮询或不相关事件不能续命；与合法人工/外部等待期限区分。 |
| 时钟及重启 | 进程内用单调时钟；跨进程保存可恢复的时间事实，明确时钟跳变处理和停机计费，不跨进程相减单调时间。 |

**再实施。** 在 domain/core 定义类型化合同、状态转换和可控时钟测试接口，适配器提供持久化及实际停止/核对端口；更新相关 Schema、必要新配置修订和现行文档。旧冻结计划继续原语义，采用新策略须走明确后继/计划变更。若需要 SQL 变化，声明新基线并遵守 S5 的兼容规则；不直接改用户库。

**专项验收。** 可控时钟覆盖活动/人工/平台等待、父子重叠、重复唤醒、总墙钟、watchdog、Host 重启、旧版本恢复及到期与合入/取消竞争。真实 SQLite 覆盖 OCC/幂等和故障恢复，真实 Docker 仅验证必要停止/撤权；无需真的等待 1800 s。

R11 沿用现有 retry_of、原意图、确切候选合入观察和当前授权核对：已生效发布只能复用原回执，不重新调用 Git/GitHub；未知仍先核对。同根/节点/计划/输入/参数不匹配、当前授权撤销或观察不完整均拒绝。保留原取消、物理 operation 和失败；显式控制副本的夹具与真实经理自主恢复分开报告。R2 关闭要求实现和边界验证均完成，不能只提高旧超时或无限停表。

### S5：R3 物理步骤存储

1. 分别扩展冷实例数、单实例 DAG 步骤数、单实例历史尝试数至十倍；保持活动并发、页大小、当前闭包、正文分组和读写动作相同，不能用大量冷 queued 实例代替大 DAG。
2. 测解析/编码、物理写字节及 WAL、事务占用、连接/锁等待、热查询、checkpoint 和 RSS；区分读放大、JSON 改写和索引不足，不把资源逻辑版本独立当作完成。
3. 对比保留 JSON 的有界读取/索引与头、当前步骤、历史分离的单一权威方案。结构改造仅在成本归因及原合同规模/绝对门禁显示必要时进入实现；设计写清资源键、版本、原子读写集合、事件、幂等、父子/上游失效、未知/迟到回执和重启规则。
4. 当前为 global24/project59，数据集标记 `devdesk-profile-runtime-v2`；现行仓库拒绝不兼容数据且不自动迁移。任何新 SQL 基线默认继续明确拒绝旧库，显式迁移如有需求另立范围，不偷偷转换用户数据，不长期双写两份权威执行事实。

**退出条件：** 测量/设计交付与实际结构修复分开判定；不改造时记录依据及仍开放项。若改造，真实 SQLite 强制交错证明兄弟步骤独立提交、同资源冲突、多对象原子性、取消/重试、迟到结果、历史/原件及重启正确，外键/quick_check 通过；同条件十倍规模时满足相关延迟和增长门禁，提交字节/事务/WAL 收益可解释。

### S6：R6 精确计时与页面关联

优先复用现有 span/原生计时。仅在定位或验收需要时补充有界观测：事务 begin/COMMIT 返回、提交结果/事件游标、原生写回、SSE 接收以及页面渲染目标版本。观测失败不改变业务提交结果；不保存第二套业务权威、不写业务正文或凭据。

必须区分“COMMIT 调用已返回”“事件可见”“客户端收到”“页面显示”，原 registration/result/Event.time 字段仍标为 COMMIT 前。跨进程明确同步/采样误差或给出保守区间，不宣称不存在的精确耗时；嵌套 span 不重复累加。补逐事务占用和连接等待，不能把请求聚合 span 改名冒充其分布。

**退出条件：** 成功/回滚、提交后通知前崩溃、重连、重复/乱序事件、观测丢失均可追踪到确切项目/资源/版本；缺失/失败样本入账，启用/关闭观测的开销有同条件对照且不破坏资源及延迟门禁。精确边界未取得的指标继续标为未证明，不阻碍其他已有可靠边界的结果交付。

## 6 统一验收口径

以下是原合同门槛，不是本次实测结果。轻量原生调用按原合同的无外部执行、输入≤64 KiB/输出≤128 KiB 定义；较大原件按大小分组并单列平台衔接，不能整体改标“重调用”逃避考核。

| 指标 | 目标及适用边界 |
|---|---|
| 轻量原生 T6−T0 | 0 前端 P95≤200 ms/P99≤500 ms；100 前端 P95≤500 ms/P99≤1 s。T6 只声明写回原协议连接，不代表模型已消费。 |
| 平台衔接 | 就绪→本机派发 P95≤1 s；外部结束→接纳 P95≤250 ms/P99≤500 ms；接纳→写回 P95≤100 ms/P99≤250 ms。 |
| 普通读/持久化确认/冲突响应 | 读 P95≤200 ms/P99≤500 ms；写和冲突 P95≤300 ms/P99≤1 s。长操作确认与实际外部完成分开。 |
| 页面 | 导航→主要状态和可用操作 P95≤1 s/P99≤2 s；正常事件收敛 P99≤1 s，无故超过 3 s 失败；重连恢复 P99≤3 s。精确提交边界不足时不得宣告收敛合同通过。 |
| 有限读取/增长 | 正常执行摘要≤64 KiB，普通列表≤128 KiB；普通查询完整工程恢复/Workflow 编译/业务写事务均为 0。历史十倍的同负载轻量/摘要 P95≤1.5 倍且满足绝对门禁。 |
| 后台与等待 | 同预算 100 前端完成吞吐≥0 前端的 80%，持续有实际可推进工作；稳定等待 60 s Host 平均 CPU≤单核 2%。 |
| 配置加载防退化 | 保持零完整快照/零事务；受影响 W0–W7 用原入口定向对照，W4–W7 P95 退化≤max(10 ms, 基线的 10%)。 |
| 正确性/自主性 | 0 丢失更新、串项目、重复副作用、过期授权接纳、意外冲突/storage_busy；0 外部调度指导、0 Human 代接纳。L5 等明确构造的预期冲突另记。 |

正式百分位按方法/调用大小/页面/场景分别计算，每类原生至少 1000 样本；原合同规定的轮次、窗口、导航/冷启动样本继续有效。S1 的 200 样本、120 s 短轮和真实模型少量调用只用于定位/专项，不能宣布正式 SLA。逐方法报告 P50/P95/P99、最大值、样本量、失败/拒绝及 bytes；不得只发布混合成功子集或最好一轮。

开放到达负载保存预定发送、实际发送、完成和最终校验，未发送/排队过期/超时都计入分母；所有持久化修改在停机前耐久回读。保留构建/其他进程重叠和全部墙钟，诊断子集与整轮结果分别报告；不同业务需求、硬件、配置或预算的成绩不计算因果优化比例。
