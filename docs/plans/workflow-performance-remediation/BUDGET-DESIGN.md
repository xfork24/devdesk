# S3/S4 后续实现设计输入

状态：S3 已补离线调度成本统计；策略尚未改变。S4 已实现显式 time_limits v1 子集，接入 domain/core、Schema、SQLite 和调度；出厂默认仍不选择它。现行合同见[预算与并发](../../design/workflow.md)，下文其余分段政策仍是后续设计。完整 Feature、付费经理链路与正式容量矩阵未启动。

## 已实施的 v1 边界

`ExecutionBudget.time_limits` 显式包含 version=1、wall_seconds 和 human_wait_seconds；缺省 None 不改变旧源/预算的序列化。`StepExecution.time_budget` 保存原逻辑执行、首次开始、进程/UTC/单调锚点、Human 等待是否关闭及下一期限。总墙钟继承技术重试、返工和保留节点的计划替换，重启按 UTC 包含停机；不按新 execution ID 归零。它约束逻辑节点，尚不是整根/经理总预算。

v1 Human 期限只覆盖步骤 waiting_input/waiting_confirmation；确切输入/签署/决定关闭等待，再次实际请求可重新开始 Human 等待，总墙钟不重置。重复观察/通知不续期，已签署的门禁不能因重复请求重开。到期/时钟不确定时拒绝新派发、补充输入、签署、接纳或以技术重试续期，后台请求停止并保留待核对事实。等待/停止/签署和版本更新使用同一资源提交，不写计时心跳。

v1 的限期准入点是核心准备阶段的权威检查；其后与停止投影按原资源版本竞争。它不保证 COMMIT 返回一定早于截止点，提交瞬间的硬期限护栏与完整强制交错仍待后续政策实现。

进程内用原锚点加单调差值；不同进程不相减单调计数，重启早于最后持久锚点时进入核对。未倒退到持久锚点之前的跨重启 UTC 校正仍可能无法与真实停机区分，不能宣告任意时钟异常均已解决。出厂 Workflow 未发布采用此政策的新修订，默认 Feature 的旧预算问题不由 v1 接口存在自动关闭。

项目基线已升为 60，global 24、数据集标记及布局不变。旧 project 59 在初始化写入前明确拒绝，无迁移或用户库转换。步骤物理权威仍是原 steps JSON；本次版本变更是时间合同/执行事实/就绪索引变化，不是 R3 存储拆分。

## S3：先区分能力、采用方式和收益

当前 `workflow_segments.rs` 已支持精确节点、有界操作数、计划及驱动代次校验，现行编排 Skill 也已要求使用有界委托及事件等待。历史 r9 已实际采用 segment，因此不能把再次增加同义指令作为策略修复。

先在既有 `summarize_engineering_scene.py` 增加 `scheduling_metrics`：按原始 Controller/原生调用关联 Session，统计经理 Turn 的闭合区间并集、未闭合或时间异常、原生方法/状态、相同参数重复读取候选、业务 Actor 和 segment 授权数。范围为全部导出记录，不是自动推断出的单根关键路径。Turn 墙钟包含平台等待，不是纯模型推理；重复查询可能响应了新事件，不能仅凭相同参数判为无效回合。缺少的旧 Session/Turn 记录单列，失败、拒绝和未知状态均保留。

工具已用重叠区间、缺失时间、失败调用、历史 Session 和原输入不变的回归验证；真实停止后的 W1 数据导出及分析也已验证。该数据没有经理 Turn，正确报告为 0，1056 项业务动作属于 Rust driver，不能升级为 Agent 自主性证据。原 macOS 经理轨迹未取得，不据此宣告新策略收益。

策略改动的采用条件：

| 候选优化 | 必须先确认 | 实施边界 |
|---|---|---|
| 连续技术节点委托 | 实际重复控制回合发生在同一合法技术链，且无需新的业务判断 | 由经理选择确切 automatic 节点；依赖、输入、配额、独立测试和完成条件继续校验。Human、异常、计划变化或未知效果立即回流。 |
| 独立工作并发 | 多个工作已经就绪，资源/写入范围独立，串行空档位于关键路径 | 经理自行授权；不由 Host 根据业务名选择下一步，不扩大权限或并发预算。 |
| 减少重复读取/通知 | 对齐事件、交付游标和读版本后，确无新事实或新用户意见 | 有界读取和真实对象/期限等待；不取消必要的最终状态补读。 |
| PR 通知 | 现有 publication 创建观察完整，经理实际可读，根页可定位原件 | 明示历史创建事实、候选与来源；不当作当前远端状态、合入许可或最终回执。 |

只有真实成本归因显示现行方法不足，才发布新的 Skill/Capability/Agent 及必要闭包修订。不能改正在运行的冻结任务，也不能把可控 Harness 的调用数当作真实模型减少 Turn 的证明。R4 的真实通知、R8 的策略收益继续开放。

## S4：计时归属

保留现有 `ExecutionBudget.timeout_seconds` 和等待区间并集的旧语义；新的分段政策通过可区分、不可变的配置修订采用。下表是完整版的设计目标；已实施部分以本文件前述 v1 边界为准，不调整旧执行的 1800 s，也不扩大探针期限。

| 时间 | 建议归属 | 到期处理 |
|---|---|---|
| 活动时间 | 经理/步骤实际模型执行、本机登记/排队/派发、平台本地计算及未被权威事实分类的等待 | 请求停止并进入待核对；不把本机拥塞归到外部服务。 |
| Human 等待 | 已持久化的当前澄清/签署请求至实际回答/决定；重复通知不重置起点 | 按冻结期限给出等待到期原因；有 writer 时先停止并取得证明。 |
| 外部事实等待 | Kernel 已确认的指定外部条件，例如确切 PR 尚未合入；不是经理一句“正在等” | 独立有限 deadline；过期先核对结果，不认定未生效。 |
| 平台操作期限 | 从原物理意图/operation 的实际启动边界计算，包含断连和未知结果 | 使用原 operation 停止/核对；不能另开副作用规避期限。 |
| 总墙钟 | 从逻辑工作首次真正开始起算，包含技术 retry、等待及 Host 停机时间 | 有限且不可由重复通知、重启或新 execution ID 重置。 |
| 无进展 watchdog | 自最近一次规定的业务或执行进展起算；日志、token、普通轮询及无关项目事件不续命 | 与合法 Human/外部等待分开；触发后保留原因并停止/核对。 |

活动预算、等待期限、总墙钟和 watchdog 同时成立。等待可暂停活动计费，但不能暂停总墙钟，也不能豁免自身 deadline。父子/人工/暂停重叠区间取并集，不重复扣除。

## 逻辑预算身份和持久化

1. 逻辑预算绑定实际实例、稳定 node_id、业务 round 和首次预算来源；技术 retry 继承已用时间与来源，不因新 sequence/execution ID 归零。业务返工是否建立新活动额度由独立返工合同决定；根总墙钟继续累计。
2. 保存首次开始、分类等待的实际来源与起止、已关闭计费区间、最近有效进展、冻结政策引用及明确 deadline。使用既有治理事实/资源级提交，不保存展开配置副本。
3. 等待开/闭、进展、停止和结果接纳与有关版本/事件在同一事务中提交。无变化的 tick 不写计时心跳；重复命令不重复扣费，OCC 冲突不能自动改变原业务请求。
4. 调度使用持久化下一期限和低频补扫，不能为执行总墙钟重新把稳定等待变成 75 ms 忙扫。读取 deadline 只提供唤醒，实际动作重新验证权威身份/计划/epoch/worker/输入及当前状态。
5. 完成、取消、计划替换或后继采用时封存原预算事实，迟到观察不能给新执行续期或清空旧消费。计划采用必须明确旧区间如何继承；不读取当前默认值覆盖旧冻结执行。

## 时钟及重启

进程内区间使用单调时钟；跨进程持久化 UTC 时间和原身份，不能相减两个进程的单调计数。重启后停机期间计入总墙钟，活动时间仅按可证明的暂停/等待扣除；不能默认 Host 离线等于外部 writer 停止。

相对上次可信事实的时钟倒退或无法确定的区间显式进入时间核对，不用负时长或新的起点放宽预算。对于进程内可检测的墙钟跳变，用单调锚点避免刷新预算；重启后无法辨别时钟跳变和真实停机时，不伪造精度，保留边界和待核对原因。

## 发布竞争与 R11

预算到期和远端合入是独立事实。先观察到超时也不能推断发布未生效；先观察到合入也不能跳过当前授权与本地接纳。复用现有严格 retry_of、原意图、候选、参数、合入观察及物理回执核对，已生效结果不再次调用 Git/GitHub。原取消、物理 operation 和未知事实不改写。

不得把“PR 已创建”当作“已合入”，也不能把历史创建观察作为当前外部状态；核对不完整时继续未知状态。真实经理能否自主处理此异常仍须局部链补证，隔离夹具不是该证明。

## 必须通过的专项

- 可控时钟：正常活动、父子/人工等待重叠、重复通知、合法长期等待、无进展、墙钟和平台 deadline，边界相等与越界分别测试。
- 真实 SQLite：最后时刻的完成/超时竞争、重试继承、重复提交、并发计划采用、回滚、通知丢失后重启，不能重复扣费或重复副作用。
- 时间异常：进程内跳变、重启后倒退、未知外部 writer；无法证明的区间不宣告成功或停稳。
- 发布：合入后回执丢失、超时后发现已合入、缺观察/旧授权/错候选拒绝；R11 的原始失败和既有隔离证据保留。
- 必要实际 Docker 停止/撤权；稳定等待 CPU 回归。无需真实等待 1800 s 或重跑完整 Feature。

R2 已落地 v1 子集，外部事实/平台 deadline、watchdog、整根预算及出厂采用仍未完成；R3 尚未测完，R8 尚无同条件策略收益，R4/R11 尚缺相关真实经理链。各项继续开放，不能把类型/接口及局部测试升级为整体修复结论。
