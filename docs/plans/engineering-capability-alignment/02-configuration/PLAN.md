# S2：配置图、原子创作与运行时修订选择

状态：待实施。依赖：S1 的统一用例/主体和存储边界。[总体路线图](../PLAN.md)

## 1. 目标与对象边界

同一组配置服务覆盖 UI 和 Agent：创建、读取、后继修订、停用、依赖查询、预演、提交、绑定选择。资源发布与工作采用分开；Project 默认、Feature/Task 冻结、运行实例计划是不同生命周期，不先为减少概念将它们合并成一种可变对象。

保留 `type / identity / revision / scope / refs / data` 和现有强类型内容。修订号是身份的一部分；业务内容合法性不比较 schema/renderer 版本。旧新修订只要使用同一已实现原语、结构和规则合法，就能共存和选择。

## 2. 共同配置管线

1. 解析信封和对应领域内容，拒绝未知字段/原语、畸形引用和超限内容。
2. 提取**有类型的依赖边**：from、字段路径、关系、预期目标 type、目标精确 revision、scope 约束、冻结语义。
3. 在候选完整图中验证存在性、类型、可见性、停用策略和边的业务约束；再调用各对象专门规则与 Workflow 编译。
4. 输出结构化诊断：错误码、源引用、字段路径、目标引用、原因、可修复建议；诊断可被 UI 和 Agent 同时消费。
5. 根据明确操作生成不可变源修订和选择事实，CAS 提交，并登记 Actor、命令指纹与变更结果。

依赖提取需要覆盖：根级 refs，Workflow 的 executor/角色/端口/Spec/子流程，PermissionContext 的步骤及工具授权，Catalog 的 provider_ref，外部工具的 integration_ref，Skill package 的工具依赖，项目和工作绑定等。不能只扫描 refs；也不能扫描所有 JSON 字符串并把偶然等于某 ID 的说明文本当作依赖。

图保留边的语义：Workflow DAG、递归子流程、Skill 递归依赖按对应规则禁止循环；普通引用、历史 lineage、反向 usage 边不能不加区分强行执行全图 DAG。Standard 继续只冻结它声明负责的规范范围；运行依赖闭包比 Standard 规范快照更广，两者共享边定义而不强行变成相同集合。

## 3. 通用配置变更集

提供 `configuration.change.preview/apply` 应用用例（名称为设计建议），操作包括 Create、Revise、Retire、SelectBinding，以及对相应领域对象调用的受控特有操作。源配置与 Agent instance/项目绑定的生命周期有差别，不能用无类型 `set(path,value)` 写任意状态。

- 在预演时为新对象/修订分配稳定身份，允许同一批的新对象相互引用；先形成候选全集再验证，解决发布顺序和相互引用问题。
- preview 固定原始操作、基准修订/目录代次、读取依赖和目标内容摘要，返回受影响选择、存量执行和需要停止的范围。
- apply 只接受同一操作和预演令牌；重新核对读集、写集、授权及依赖，存在冲突则拒绝并返回差异，不按当前 latest 静默重解释。
- 同库一事务提交全部源修订及选择，失败零可见写入；相同 command_id 重放返回同一结果。
- 跨全局/项目库采用可恢复操作记录：固定源修订先准备，完成复制及目标验证后一次切换目标选择；未提交候选不能出现在普通可用目录中。重启核对每个步骤并幂等恢复，不宣称跨 SQLite 原子事务。只读预演可以跨库，写入按明确归属拆步骤。
- 授权绑定到当前 Actor 的已生效权限，候选配置不能通过新增自己的 Permission/Capability 来授权本次变更。涉及运行状态的采用另走运行变更协议。

## 4. 修订选择与删除语义

- 查询提供身份历史、修订内容、usage/影响、当前可采用性和拒绝原因；“目录当前代次”“对象最新版”“已选精确修订”“运行冻结”分开显示。
- UI RevisionSelect 可主动展开选择任何合法历史修订，默认推荐 latest 只是展示选择；不能只追加已经固定的旧版选项。停用版本仍可读，新的采用按规则拒绝。
- 允许在旧修订基础上创建草稿并生成新的线性后继；提交检查该身份当前 head，不能默默覆盖并发修改。若不引入分支语义，就明确要求先合并到新 head。
- 编辑 Skill 为目标 Agent 创建 Skill → Capability → Agent 后继，并按用户明确范围切换绑定。共享 Skill 的其他消费者不自动更新；保留原引用。
- 删除 = 停用、必要时显式换绑/移除实例；已冻结引用与历史保留。反向依赖不满足时返回精确引用路径，不隐式级联删除。物理 GC 另案。
- 模板 bundle 是可选发布集合，不要求其中所有配置一起升级；运行库允许多个修订。正常编辑不要求全模板重置或整体推进所有身份。

## 6. 验收与限制

同时发布 Skill/Capability/Agent、Spec/Delivery/Workflow/Standard 两组有依赖修订；比较 UI、直接应用用例的诊断和结果。并发两个编辑者、停用被使用对象、预演后其他人换绑、模板代次改变和跨库中断均有针对性回归。

用任意未来整数元数据而不改变结构测试合法性；改变为未知原语或畸形结构必须拒绝。此处不测试“增加 Rust 不认识的新结构字段仍能执行”。测试配置自洽不应固定出厂 ID、步骤数量和正文哈希；产品默认流程测试可单独验证其产品行为。

本阶段不开放任意通用 RPC 给 Agent，S5 在同一服务上增加受控工具外观。运行资源真实可用性由 S3 提供；预演结果区分结构合法、组合合法、资源就绪和可立即执行，不混成一个 valid 布尔值。
