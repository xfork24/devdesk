# W4–W7 配置加载优化实施与验收

日期：2026-11-16。W4–W7 已实施，在隔离 worktree 验证。权威源继续使用规范化 JSON 与确切修订；本轮改变读取视图、请求生命周期和可丢弃缓存，不增加持久化配置投影或迁移。

## 实施范围

| 工作包 | 当前实现 |
|---|---|
| W4 | 轻量索引、版本分页与确切 refs 批量正文；列表默认 head、版本选择器按需历史；defaults/project configuration 的 selection 视图；Standard 详情、使用位置独立读取；精简预览复用 baseline，展开后取正文；Workflow 不重复下载两份目录。 |
| W5 | 64 项/估算 8 MiB 的浏览器缓存、请求合并；连接/数据路径/Host/项目/配置序列隔离；mutation 与 SSE 失效；source_epochs 拒绝迟到倒退响应；取消属于切页和组件生命周期，版本刷新保留仍有效的页面与草稿。 |
| W6 | 保存标识、声明目录立即展示；账号/安装身份探针后复用模型元数据，5 分钟 TTL、15 秒失败退避；一次主动刷新只消费一次；16 项/估算 1 MiB 后台服务可跨短暂离页继续发现；导航最多 2 个并发轻量预取。 |
| W7 | 快照内模板成员、head/历史 head、停用索引；默认组合、Standard 与预览、权限支持矩阵缓存。每快照 16 项/估算 4 MiB，进程合计 32 MiB；完整源输入指纹、方法与参数参与键，权限结果再包含安装登记与后端资产身份。 |

HTTP 取消可跳过排队及尚未进入编译的读取；已经开始的同步工作仍可能完成。缓存不是写入或执行授权依据，发布、采用、权限和执行继续在权威事务内校验。模型发现只使用已登记程序，不因打开配置触发安装；身份探针不启动程序或访问系统凭据库。

## 对照条件

基线为 main `d8a316d3a281e58a013374d5a6f5f7696932e7b2`，已含 W0–W3。期间 main 的并行功能更新先整合到 feature，再冻结对应基线，避免把这些更新计作加载收益。优化版本为 `93542d9caa795c72a3254b485d640cc053e391a9`。Host 测试二进制、Web 内容身份、测量脚本摘要及 SQLite 输入清单保存在证据目录。

两组使用同一份在线备份输入，各场景另复制全新兼容数据集；同机、Node 24.13.0、Rust 1.99.1、相同 Chromium、1440×1000。debug/release 分别对照；构建与回归结束后串行采样，16 个正式采样窗口未观测到构建进程重叠。离线入口不启动调度器、模型推理或 Git/GitHub 操作，实时目录明确使用相同夹具。

每页面/场景 30 次。warm 是同一页面进程反复 A→B→A（含首次访问），cold 每次重新加载 JavaScript/浏览器配置缓存，服务端处于同一已启动状态。cold 不代表 30 次全新 Host 冷启动；RPC 第一个样本与冷查询构建阶段另保留。

UI 时间从导航开始，到项目保存控件可用、其他配置页实际对象出现、或讨论角色可选，再等待两帧；包含浏览器点击/渲染开销。RPC 数据完成时间另存，350 ms 静默窗口只用于隔离样本，不计入 UI 时间。RPC 数不含 capabilities GET、静态资源和明确的轮询；零 RPC 不等于零渲染耗时。
