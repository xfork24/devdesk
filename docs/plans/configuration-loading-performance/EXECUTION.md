# 配置加载 W0–W3 实施与验收

2026-11-16。对应 [原计划](PLAN.md) 与 [优化前分析](ANALYSIS.md)。历史分析和计划保持原文；本报告记录本轮实现、回归和同条件比较。

## 实施范围

| 工作包 | 已实现行为 | 主要入口 |
|---|---|---|
| W0 计时与基线 | 可选启动/RPC 阶段日志、调用次数、响应字节、请求编号和 Server-Timing；可复制数据库的离线 RPC/Chromium 采样入口 | `adapters/performance.rs`、`host/loading_performance.rs`、`tests/performance/` |
| W1 配置专用读取 | 配置源及必要治理元数据独立读取；确切引用、类型、head、来源索引；不可变 Arc 快照与有界缓存；只读连接用 data_version 检测提交 | `core/configuration_catalog.rs`、`adapters/configuration_cache.rs`、`source_store.rs` |
| W2 读取与同步协调 | 目录查询复用固定视图；共享源与项目源只读组合；项目自有 Role 保持全局可发现性；目录不进入定义写锁、不写同步事务；工程命令仍同步确切源 | `host/configuration_read.rs`、`core/catalog_sync.rs` |
| W3 事件和轻量启动 | 事件按游标有界 SQL 读取、提交后通知及低频补读；配置版本通知显式 opt-in；轻量 ui_bootstrap/project_directory；讨论目录和经验摘要避免恢复工程历史；空闲工具恢复先查询 pending hint | `host/main.rs`、`adapters/store_changes.rs`、`experience_index.rs`、`web/src/App.tsx` |

源格式和 SQLite 基线保持现有合同：`source_definitions` 仍为唯一配置事实源，global 18 / project 48，数据标记仍为 `devdesk-profile-runtime-v2`。无迁移或新增持久化展开表。底层保留缓存按估算字节计账，单项 32 MiB、进程 128 MiB；只读连接最多 8 个，共享/项目组合视图最多 8 个、单项编码大小最多 4 MiB。超出预算时读取但不保留；逐出不推进逻辑提交序列，已有读者可继续持有旧 Arc。

新读取流程：

```mermaid
flowchart LR
  Read[目录请求] --> Pin[捕获已提交配置快照]
  Pin --> View[组合共享与项目只读视图]
  View --> Project[原查询投影与来源标签]
  Project --> Response[序列化响应]
  Write[配置事务提交] --> Invalidate[失效快照并推进配置版本]
  Invalidate --> Notify[提交后通知]
  Notify --> SSE[按游标补读事件和配置版本]
  SSE --> UI[轻量启动及编辑器刷新]
```

前端对普通工程事件比较配置版本，避免重载整个配置页面；版本变化时刷新读取函数身份，保留编辑器草稿与反馈。回归中同时修复了预览成功清空保存反馈、权限刷新临时卸载展开区域、项目后台预览清空表单及迟到读取覆盖较新结果的问题。项目预览仅在实际输入变化时清空旧结果，后台同输入刷新保持表单可操作。

## 比较条件

- 优化前取本地 main `23186db`，仅加入 W0 诊断及离线测试入口；优化后实现提交为 `649e06f`。这样排除了期间 main 的运行时与标签重构造成的源码差异。
- 同一台机器、Rust 1.99.1、Node 24.13.0，同样的 Chromium、1440×1000 视口和查询/导航顺序。debug 与 release 分别比较。正式采样串行执行，不与构建或回归测试并行。
- 每组从同一数据库备份复制：global 192 个源、213 条治理记录；项目 194 个源、224 条治理记录、1 个 session、3 个 turn、3 个 execution、6 个 snapshot、17 条 conversation event。保留全部历史，不通过缩减数据获得收益。
- RPC 每种查询 30 次，包含业务结果 JSON 编码，不含浏览器传输；五类页面各 30 次导航。浏览器数据就绪时间取本次导航关键 RPC 的最后完成时间；排除持续 session/experience/status 轮询和用于判定安静窗口的额外等待。初始打开另存 cold 阶段，不混入重复导航分位数。
- 使用测试专用离线 Host、真实 RPC/SQL 与现有执行端口夹具，关闭 scheduler，不执行工程或付费模型调用。仅 `codex.auth.models` / `models.list` 的实时发现使用明确固定响应；以下页面结果表示本地配置数据链路，不代表真实外部模型发现的耗时。
- 原始样本、构建 SHA-256、输入数据库 SHA-256、阶段计数、HTTP 日志、截图和空闲 CPU 保存在临时证据目录。P50 为排序后的第 16 个样本，P95 为第 29 个样本；阶段包含嵌套关系，不能直接相加。

## 回归验证

- 权限 Schema、出厂目录、架构、Node CI 门禁、rustfmt、ESLint、TypeScript、Prettier、Web 构建和 clippy `-D warnings` 通过。
- `cargo test --workspace --locked`：329 passed，21 ignored，0 failed。默认忽略项包括显式性能入口及需要专用真实环境/认证的既有验收；本轮未增加跳过已有回归的规则。
- debug / release Chromium 全量各 76 passed，0 failed；权限预设元数据读取补齐后，另复测 Host 38 项、适配器单测 29 项、配置缓存 3 项，以及 debug/release 权限浏览器各 2 项，均通过。覆盖配置读协议、跨页面草稿、SSE 后台更新、预览等待、模板重置、源修订/历史、权限、Integration、Standard、项目切换、讨论和工程工作流。
- 两种构建 HTTP/SSE、认证/Host/Origin、持久化与重启、项目隔离检查通过；release 独立复制可执行文件检查通过。debug/release 的模板重置、数据集初始化/保留和运行准备入口检查通过，真实 Docker MCP 浏览器用例通过。
- 新增定向约束：配置/事件读取不解码故意损坏的无关工程历史；提交/回滚和仅事实提交的缓存行为；只读连接发现外部提交；通知回调在锁释放后读取；逐出不改变提交版本；目录不等待定义写锁；13 类旧/新读取结果一致；共享源及项目自有 Role 新修订无需读取时写库即可发现。

W4–W7 继续按原计划推进：完整响应仍较大，Standard 详情/预览和权限支持计算仍有开销，浏览器共享请求缓存、按需正文、实时模型发现缓存与有界预取尚未实施。本轮规模验证针对上述约 200 个源的真实备份和历史隔离结构门禁，未将 2,000/10,000 源的压测结果作已验证声明。

## 内容一致性与交付

使用相同源备份，分别启动冻结的优化前/后 release Host，逐项比较两页 configurations、Standard 目录、defaults、workflows、project_configuration、workspace、model_providers、permission_resources 和空 events，共 10 组结果全部一致。只移除新增版本元数据，并归一化各自临时数据集路径；记录正文、顺序、历史和来源标签保持比较。

受控性能对比对应 `23186db + W0 探针` 与 `649e06f`。采样结束后，分支另整合 main 的讨论展示提交 `4ed2020`；该整合保留已测提交为祖先，配置读取实现未变，并追加 debug/release 各 18 项讨论/配置集成验证，全部通过；整合后的风格、类型、构建和 clippy 检查通过。源数据和原工作区内容不用于测试写入。
