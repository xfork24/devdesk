# 项目经理通过事件自主推进工作流改造计划

状态：实现和真实默认 Feature 验收完成。方案制定于 2026-11-16；实施基线为 main aa7328d，独立分支 codex/event-driven-project-manager。原始方案基线为 b75439d。下文保留实施方案；P0 至 P6 的实际实现、42 个默认节点验收、最终构建只读复核及 debug 浏览器保留的一项超时见 [实施记录](EXECUTION.md)。

目标是让项目经理持续承担一次 Feature 的交付责任：用户启动后，经理依据冻结工作流和实际执行事件，自主安排、检查、返工和完成工作。工作流继续定义任务合同与约束，Rust 内核继续校验权限、证据和人工确认，运行时提供可靠的事件投递、执行及恢复。

## 目标与范围

完成后的默认使用方式是：用户提交业务需求并启动一次 Feature；经理自行推进根流程及 Task 子流程；用户在规定的业务确认点作出决定，必要时回答真实的业务问题。用户无需补发“继续”“现在派发某步骤”“先接纳再完成子流程”等调度指令。

启动后的流程协调统一由项目经理主动负责：调度其他 Agent，接收并判断其结果，组织接纳与返工，处置异常，向人类说明进展和阻塞，提出业务问题与审批申请，并在回答或审批到达后自主继续。经理依据工作流和事实决定后继动作；人类、测试脚本及运行时代码不得在每一步为经理指定下一项业务动作。

运行时仍负责事实通知、事件唤醒、工具执行、权限校验、超时保护和技术恢复。通知表达“哪个结果或决定已到达”，不夹带“接下来执行哪一步”。授权内可恢复的业务异常由经理选择核对、停止、重试或返工；缺少权限、外部条件或人类决定时，由经理明确提出所需帮助并等待。经理自身或 Host 不可用时由运行时落实停止保护及可核对恢复，不能因此绕过预算、权限或结果未知的边界。

本次沿用 manual、rust、agent 三种根驱动，改造 agent 的执行方式。现有经理工作台的项目查询与配置创作继续独立于根调度授权；新事件能力不授予工作台根控制权。第一轮真实模型验收使用当前已支持根编排的 Codex Harness，不借此扩展 DSH 编排能力。

保留 Step 的任务、输入输出、Role、Skill、Spec、预算和依赖，也保留现有人工确认点。相同的工具参数与交付封套仍是机器合同；稳定的编排职责与方法通过配置装配，后续事件仅传递事实、引用和必要恢复信息。

项目经理页面承担面向人类的业务沟通。每次请求确认、澄清、异常处理或其他人类行动前，经理准备本次事项所需的全部相关材料、处理说明和证据链接，明确需要人类做什么。页面删除“调度与经理管理”配置区和底层工具调用状态列表，用完整的业务交互内容替换“查看确切请求”。

## 职责和运行结构

| 主体 | 决策与职责 |
|---|---|
| 用户与工作流 | 确定业务目标、冻结任务及依赖、交付要求、权限和人工确认点 |
| 项目经理 Agent | 读取事实，选择合法工作和并发安排，检查产物，决定接纳、返工、请求输入或人类决定，完成子流程与根流程 |
| Rust 内核 | 提供共同动作资格，核验真实调用身份、计划版本、输入输出、停止证明、权限和人工决定，接纳合法命令 |
| 运行时与 Harness | 投递事件，运行经理和业务执行者，交付真实工具回执，管理配额、超时和故障恢复 |

~~~mermaid
flowchart LR
    U[用户启动并提供业务目标] --> B[经理首次启动上下文]
    B --> M[经理读取事实并选择动作]
    M --> T[显式控制工具]
    T --> K[内核校验并保存意图]
    K --> W[Agent 工具和子流程执行]
    W --> E[提交事实与业务事件]
    H[人类确认或业务回答] --> E
    E --> D[有界事件投递]
    D --> M
    M --> Q[保存检查点并登记等待]
    Q --> D
~~~

事件不携带“下一步执行哪个节点”的结论。运行时提供状态变化与读取引用，经理通过现有 inspect、outputs.read、execution.inspect 等工具判断。动作资格仍由查询和真实提交共用的内核计算；事件中的旧状态不能作为执行许可。

## 事件与投递合同

### 结构化来源

拟议事件至少包含项目、根实例、相关实例与执行身份、源事件 ID、事实种类、源记录引用和修订。来源由事实生产者填写，正文有界，不复制完整计划、材料或会话历史。源记录与事件在同一业务事务中提交；幂等命令和重复回执不得产生重复逻辑事件。

复用现有项目 events 日志，补充可按根范围和游标读取的结构化索引。现有自由文本 detail 不能靠解析模型文本推断人类决定、执行成功或变更权限。子流程创建时建立根归属，子实例事件自动进入同一控制范围；不同 Feature、项目与已撤销 Controller 的事件不得混投。

| 事件类别 | 必须覆盖的事实变化 |
|---|---|
| 启动与恢复 | agent 驱动取得控制权、首次启动、合法恢复与后继会话建立 |
| 执行结果 | 产物封存、等待接纳、业务拒绝、失败、未知结果、实际停止和 writer 撤权 |
| 工作依赖 | 子实例建立与完成、父调用结果变化、Task 依赖满足、确切受阻配额或工作区资源释放 |
| 人类事项 | 步骤请求业务输入、真实用户消息、确认或决定批准与拒绝 |
| 计划与控制 | 计划应用、暂停、继续、取消、接管、驱动切换与权限撤销 |
| 技术期限 | 已登记的等待期限、预算耗尽、工具或执行超时，需要核对的恢复事实 |

日志新增、界面读取、token 流、租约正常续期及经理检查点保存本身不触发新的模型轮次。容量通知只面向实际受该容量阻塞的控制器；不得把每个调度 tick 都包装成“容量可能可用”。

### 单次投递与恢复

一个 Controller 在同一 epoch 内最多有一个活动经理 Turn 或尚未准入的投递。同一投递有稳定的 delivery_id，绑定来源事件范围、用户输入引用、Session、Turn 和 epoch。事件批次按数量和字节分页；截断时显式给出续读位置。

必须分别记录事件已登记、投递已准备、模型已准入或消费、经理已处理。准备发送和模型消费都不代表业务动作完成，也不立即确认所有事件已处理。经理确认处理位置必须绑定实际投递内容，不能越过未读取的批次。

经理运行中发生的新事件继续保存，在本轮结束后按有界批次交付。重启根据原意图与实际消费证明核对投递；已准入或结果未知的输入不得盲目重发。业务命令继续使用既有幂等与回执机制，事件重放不得重复产生业务执行或外部副作用。

事件保留原操作、Turn 和工具调用的因果引用。经理已经实际收到工具回执时，可合并该回执覆盖的本方动作通知，避免自己的 dispatch 或 accept 额外制造一次唤醒；回执尚未交付时继续保留恢复依据。合并只确认对应源事件，不能通过提升总游标跳过同时到达的执行结果或用户决定。

提交后通知用于降低等待，耐久事件和游标负责恢复。通知丢失后按游标补读；保留有界低频技术补扫。补扫只能恢复投递、回执和期限处理，不能代经理派发或接纳业务步骤。

首次接管一个已有根实例时，在一致性边界读取根引用、事件高水位和当前摘要，防止早于 Controller 建立的事件被遗漏。后继会话加载同一工作目标、检查点及未处理事件；原失败轮次和实际已完成动作继续保留。

### 首次上下文与后续事件

首次启动上下文包含初始 user_request、冻结工作流引用、根范围、冻结 Agent 与权限依据、实际预算、当前事实入口和已有检查点。稳定 Role 与 Skill 随会话冻结，编排方法不在每个事件批次中重新拼接。新会话或后继会话可以重新装配冻结上下文。

后续投递只包含事件、来源引用、分页信息和必要的运行控制元数据。用户输入保留独立持久化来源并绑定确切投递，运行事件与用户原话在权威记录中明确区分。即使底层 Harness 使用同一个文本输入通道，也不能因此给运行事件赋予 Human 身份。

## 经理检查点与显式等待

新增经理控制状态，记录当前工作摘要、已执行动作引用、待解决问题和等待对象。检查点是经理的工作记录，不能替代步骤状态、成功回执、授权或人类决定；恢复后必须重新读取当前事实和版本。

拟议增加一个原生控制工具 workflow.controller.wait，同时保存有界检查点、确认已处理投递，并登记等待条件。它只写控制器运行元数据，不推进业务步骤。读取沿用 query.orchestration 以及适当的 inspect 投影。工具名称、字段和权限映射在 P0 固定，不能提前视为现有 API。

等待参数使用类型化、限定在当前根范围的对象引用和事件类别，可以包含受预算限制的截止时间；不提供任意 SQL、脚本或自由过滤表达式。用户输入、计划变更、控制撤销、取消和严重执行异常不允许被等待过滤器屏蔽。

工具返回后经理结束当前 Turn。等待不会挂住原生工具调用或占用业务 worker 槽位，也不会把等待状态当作人类暂停。Controller 的授权生命周期与 runnable、running、waiting 等调度状态分别表达；failed、needs_reconciliation、budget_exhausted 等实际故障仍单独呈现。

等待登记与未处理事件检查必须原子完成。若投递之后已有相关新事件到达，返回“仍有待处理事件”并保持可调度，不能写入一个永远等不到下一次变化的状态。事件发生在登记等待之后时，由该事件正常唤醒。

经理在同一轮内可连续完成多个工具动作。若有独立可推进工作，应自行安排；只有当前需要其他执行者或人类行动时才等待。除根流程已经结束、合法暂停或撤权外，自然结束却未登记等待、无有效进展或遗漏当前可处理事项，应给出可诊断状态，并由测试判失败；运行时不得补发“请继续派发”的指导掩盖问题。

等待及事件数量不会重置预算。现有工具调用与 Turn 上限保留，新增检查点、重复事件、经理自身状态变更不能制造无限续轮。预算与进展绑定真实的新结果、人类输入和合法恢复；预算计时重构仍归运行稳定性方案处理。

等待中的经理仅在未处理事件、待交付回执或相关技术期限到达时进入调度待办；授权状态为 active 不能独自使项目长期保持忙轮询。正常租约维护与是否运行模型分开处理。

## 权限与人工确认

所有新增控制工具继续校验冻结 Capability、Harness Profile、实际 Controller、Session、Turn、worker operation、epoch、租约及当前根范围。检查点和等待不能扩大权限，不能修改自身授权，不能让失效会话恢复控制权。

既有 dispatch、accept、retry、rework、complete 继续走共同控制内核。接纳仍绑定 execution_id、input_digest 和确切 outputs；事件或经理摘要不能跳过 Spec、独立评审、真实测试及停止证明。

需求、设计和任务规划评审的人工确认点按当前冻结工作流保留。经理检查产物后请求确切决定，Human 作出决定后，由事件唤醒经理，再由经理显式接纳和推进。拒绝或返工使原确认不能用于新产物。

自主推进用例中的审批必须由经理主动通过 decision.request 提出，绑定确切材料和执行版本；人类界面或测试入口只展示该请求并记录真实决定。不能由外部脚本发现 waiting_confirmation 后代经理创建审批申请或直接确认来补足流程。批准或拒绝到达后均无需额外发送“继续”，经理自行判断并执行后续动作。

经理在有实质进展、异常、阻塞或需要人类决定时，主动给出基于真实引用的说明，交代已做动作、当前问题和需要的决定。向人类反馈与请求帮助属于经理职责；界面提供事件和回执的可读展示，不以运行时固定模板代替经理组织业务沟通。

人类问题的回答继续保留原文来源，并绑定确切的当前投递与 Turn。human_governance 的校验应随新投递关系调整；不能接受来自事件正文、经理检查点、历史摘要或模型补写的“用户已经同意”。

范围、验收标准、关键方案和受保护计划修改继续 preview、decision.request、Human 决定、apply。暂停、接管、切换驱动必须围栏旧投递、旧等待和原生调用，保留正在运行的业务 worker；未知结果仍先核对。

发布与外部仓库合入沿用冻结合同和当前平台边界。当前 git.publish 会等待真实 PR 合入观察；合入是外部事实，仍需实际有权的人类或既有仓库流程完成，不由经理或验收脚本获得额外合入权限。观察到原候选的真实合入后应继续事件推进。

## 项目经理页面与人类交互

### 经理准备的交互内容

每次面向人类的业务交互都绑定具体事项，包括产物审批、需求澄清、计划变更、异常求助和交付确认。经理在请求发出前读取相关事实，准备交互说明与材料引用。普通进展反馈使用相同的来源要求，并明确是否需要人类操作；仅提供信息时标明无需操作。

| 内容 | 页面必须回答的问题 |
|---|---|
| 本次事项与背景 | 当前要处理什么，为什么现在需要人类参与，属于哪个 Feature、Task 或阶段 |
| 需要的操作 | 请确认哪些内容或回答哪些问题，如何给出决定，确认范围与批准、拒绝后的处理分别是什么 |
| 全部相关材料 | PRD、Design Doc、Task Plan、评审报告、候选差异、测试或其他本事项所需材料的可读名称、用途、版本及直达链接 |
| 经理已经完成的工作 | 已调度哪些 Agent、做过哪些检查或返工，哪些工作已完成，哪些仍在等待 |
| 初审和验证结果 | 审核 Agent 的实际身份、审核的确切材料、结论与主要问题；适用的 Spec、独立性、测试和修复结果 |
| 事实与执行依据 | 相关作者和审核 Agent 的上下文、执行记录、评审报告及真实工具回执链接，能够核对本次说明 |
| 待决定问题与建议 | 未解决问题、风险、可选处理及经理建议，明确哪些判断仍需人类作出 |

经理按本次事项组织说明，不机械列出全部项目历史。必要的材料和结果在主内容直接列明，全文、较长上下文及原始回执通过精确链接按需读取。不能只给一个通用“执行详情”入口让用户自行寻找，也不能只展示工具名、内部 ID 或 JSON 参数。

PRD 确认的示例内容应能表达：“请确认本轮需求范围和验收标准；相关材料为本轮 PRD 与评审报告；已安排独立审核 Agent 初审，结论通过或列明未解决项；可查看该审核的上下文与执行记录；本次确认只针对列出的材料版本，确认后经理将按工作流推进，退回时可填写修改意见。”Design Doc、计划变更、异常求助等按对应事实组织内容。

交互内容由项目经理形成。运行时验证并解析引用，前端按结构展示和生成链接，不替经理生成“已完成初审”或其他业务结论。确实尚未形成的材料和未执行的审核应说明原因与当前进度，不能伪造材料链接、审核通过或人类决定；澄清事项可列出当时已有草稿和背景，明确其尚未定稿状态。

### 持久化与精确引用

P0 固定人类交互数据合同，覆盖事项说明、需要的操作、材料、已做工作、审核与验证、问题建议及证据引用。内容在请求发出前持久化，审批交互绑定 pending decision、计划、execution_id、input_digest 和确切 outputs；澄清或异常交互绑定其实际来源执行和问题。刷新、重启及后继会话读取同一份已发布内容，不重新拼接当前同名材料。

扩展 decision.request 的工具合同及领域记录时，把面向人类的说明与实际待批准 operation/arguments 分别表达并绑定。审批仍校验原始操作和精确参数，不能用易读说明代替授权依据；材料、请求参数或审批范围变化后，旧决定不得用于新的请求。

引用使用项目、实例、execution、output、Session、Turn 或记录的确切身份，复用现有 [ReadingLink](../../../web/src/components/reading.tsx) 及材料、上下文、执行记录读取入口。内核核对引用范围和来源关系，链接由前端依据已验证对象生成，不依赖模型编造 URL。历史版本必须打开原冻结材料和对应执行；引用失效、材料缺失或不可读时明确提示，不用最新同名内容替换。

材料列表需要覆盖本次确认对象及其必要上游依据，审核结论需要关联实际评审材料、被审版本、上下文和执行记录。模型审核意见与平台执行事实分别标明；引用一份评审报告不等于所有 Spec 或实际测试已经通过。

### 页面替换和删除范围

在现有项目经理协作入口直接展示事项说明、经理已做工作、审核结果、材料与证据链接，以及本次回答或决定入口。审批操作使用业务名称，例如“确认本轮 PRD”；拒绝或退回时可以提交意见，由经理依据真实决定组织后续处理。决定提交后保留本轮材料、说明与结果，展示当前处理状态，并由经理事件循环继续推进。

本次 UI 删除范围：

- 删除项目经理页面中的“调度与经理管理”及其经理配置、授权配置和调度模式切换控制区，不在本页改名为另一配置折叠区继续保留。
- 删除“查看确切请求”参数展开区，用前述完整交互说明与精确材料、上下文和记录链接替换。
- 删除最近工具调用状态流水，包括 workflow.decision.request、workflow.inspect、workflow.outputs.read、workflow.step.dispatch 等“等待人工决定”“已接纳”“已登记”列表行。
- 主页面不再堆放调度 mode、epoch、plan ID、工具参数等实现细节。必要的当前业务状态、阻塞说明和恢复求助由经理交互表达。

详细调用、原始参数、模型上下文和执行证据继续持久化，并从相应记录链接读取。删除的是项目经理页面中的配置与流水展示，不删除审计事实、权限校验或人工决定能力。必要的配置和管理能力使用项目配置或工作流程管理入口；项目经理不可用时保留可操作的故障与恢复入口。

页面首屏读取有界交互摘要和引用，材料正文及长记录按需加载，不扫描整个项目历史拼装卡片。审批、查看材料、返回本页、刷新和浏览器前进后退均保留当前事项身份；窄屏下材料标题、说明、操作和链接保持可读。

| P1 可靠事件基础 | 在 configured_runtime、orchestration、workflow_changes、workflow_driver、业务回执及人类输入等提交处补齐事件；adapters 实现有界读取、索引、消费和投递持久化 | 事实与事件同事务、根范围正确、重复来源去重、遗漏通知补读、真实停止和配额释放均有覆盖；无全图摘要热循环 |
| P2 经理执行循环 | 拆分 controllers 的上下文、事件投递和原生控制处理；接入检查点、原子等待及经理准备人类交互内容；适配 conversations、Harness 调用和 human_governance | 首次启动无需额外输入；事件到达三个时间窗口均不漏唤醒；重启不重复外部效果；审批前有真实材料及处理说明；故障不伪装成人类等待 |
| P3 配置与项目经理页面 | 新 Tool、Skill、Capability、Agent 及必要 Profile 后继修订，更新 manifest/defaults；query.orchestration 与 WorkflowController 展示人类事项、材料、初审结果和证据链接；删除指定配置区与调用流水 | 新配置可实际调用；人类在本页知道要做什么、看哪些材料、经理已做什么；原始审计可追溯；历史权限不变，manual/rust 与独立经理工作台回归通过 |
| P4 自动化自主推进验证 | 增强 orchestration 集成测试；加入来源审计、事件乱序和重复、人工门禁、子流程、重启；覆盖业务交互内容、精确链接和页面清理的 HTTP/Web 回归 | 无外部逐步控制命令；业务动作来自经理或其授权 segment；必需材料、审核和记录来源可核对；旧版或跨范围链接不能冒充本次依据 |
| P5 真实完整 Feature 验收 | 改造默认工程探针与独立证据核验，走真实 agent 启动；真实 Codex、Docker、Git、专用 GitHub 仓库，并从项目经理页面完成规定的人类交互 | 当前默认根流程和实际 Task 子流程完整结束；经理准备完整材料和审批说明；实际页面链接、评审、人工确认、TDD 和候选证据齐全；没有测试代操作 |
| P6 整合与文档 | 完整必要回归、实际失败项整理；同步 workflow-orchestration、protocol、domain、代码手册、测试入口和执行报告 | 计划与实际 API 一致，新的兼容边界明确，原权限和人工确认负向用例通过，所有完成声明有对应证据 |

P0 先完成，再依次实施 P1、P2。P3 和 P4 根据合同及真实接口补齐，P5 在自动化门禁通过后进行。每阶段保持独立可检查的变化和证据；本计划不要求并行 Agent 工作。

## 测试与证据

### 事件和故障边界

| 场景 | 必须验证的结果 |
|---|---|
| 首次启动 | 只有初始业务需求与启动命令，经理自行 inspect 和派发，不需要 orchestration.input 指导 |
| 等待竞态 | 事件在当前轮次运行中、登记等待的事务边界、进入等待后到达，都能被恰当处理；无事件丢失或两个活动 Turn |
| 重复与积压 | 同一源事件、重复通知和大量事件分页不重复推进；不同根实例不串扰 |
| 停止与容量 | 产物先到但 writer 后停止、Task 依赖后满足、资源后释放，都会再次提供必要事实；未知执行继续占用其配额 |
| 人工确认 | 没有人类决定时后继被阻止；精确确认后自动唤醒、经理接纳；拒绝、返工、旧版本确认及伪造事件不能越权 |
| 人类交互内容 | 审批、澄清和异常求助均有事项、操作说明、相关材料、已做工作与真实证据；审核结论不能由 UI 或测试补造 |
| 材料与记录链接 | 从经理页面可直达确切 PRD、Design Doc、评审报告、作者和审核上下文及执行记录；刷新、返回、历史版本、返工和跨项目边界正确 |
| 页面清理 | 项目经理页不再出现“调度与经理管理”“查看确切请求”或底层工具调用状态列表；详细记录仍可通过对应链接读取 |
| 子流程与独立工作 | 经理显式派发及完成子实例，再处理父调用；一个节点等待人类时，其余独立合法工作仍能推进 |
| 模式与权限变化 | 暂停、接管、切换到 Rust 或 manual 后旧投递与旧工具调用失效，现有业务结果保留 |
| 重启与断点 | 事件提交后、准备投递后、模型消费后、工具动作提交但回复前、等待登记后中断；保留原记录并正确核对，不重放未知副作用 |
| 无进展与预算 | 空闲 tick 不产生模型轮次；检查点和自发事件不能刷新预算；经理遗漏动作时明确暴露失败，测试不注入补救指令 |
| 业务无关性 | 更换节点名称、拓扑顺序、合法分支与依赖，调度仍由工作流和经理决定，不靠代码中的默认业务 key 选择后继 |

自动化集成测试可以用明确的可控 Harness 验证协议和状态不变量。替身只能代表测试经理一侧发出原生工具调用；测试驱动器只负责技术 tick、实际夹具回执及明确标记的 Human fixture 决定，不代经理调用 dispatch、accept、rework、complete。

### 完整 Feature 的两类验收

自主推进与人工治理作为两个独立维度报告。默认 Feature 使用原冻结的人工确认策略，允许真实的人类确认与必要业务回答。另用无人工门禁的合法自动流程验证严格无人值守；不得为了无人值守成绩删除默认 Feature 的确认节点。

默认完整 Feature 的准入和证据要求：

1. 使用专用空数据集和专用 GitHub 验收仓库，冻结 Host、探针、配置与镜像身份；不使用当前用户数据或恢复中的 Feature。
2. 项目配置选择 agent，通过正式启动入口冻结初始需求。业务需求可声明功能、验收和允许改动范围，不能夹带具体控制工具、调度顺序或遇到某状态应如何操作的提示。
3. 启动后默认用例的 controller_input 为零。若专门覆盖澄清，则只允许真实问题对应的人类原文回答，独立列出；业务确认和真实 PR 合入也分别留痕。
4. 探针只观察进展、收集证据和转交真实人类业务决定。禁止补发执行指导、直接派发或接纳、重试或返工、修改任务输入或计划、切换驱动、批准例外或豁免。出现需要这些救助的情况，保留现场并判失败。
5. 审计全部 invocation、workflow_decision、controller_input、计划历史和原生工具请求及回执。每次业务推进须能追溯到当前经理投递或其已授权 segment；同样检查是否存在绕过经理的 Human 控制动作。不能只靠提示词搜索或最终状态判断自主性。
6. 核对真实产物、独立评审、精确人类确认、原有 TDD 增量 Red/Green、候选版本、测试和发布观察。节点数量从实际冻结图推导，不通过缩减默认流程获得通过。
7. 核对真实经理输入：后续事件批次不含重复的长篇编排 instructions，初始需求确实进入业务 Agent 和子流程，启动后无需测试绑定 business_facts 或执行指导。
8. 基线自主用例不接受 takeover/resume 救助后改称完整自主通过；故障恢复作为另一个用例，清楚标明中断、恢复来源和实际停止证明。
9. 每个审批请求均有经理的真实 decision.request 调用，业务问题与异常说明来自经理对话；测试入口不得自行生成申请、替经理解释异常或直接确认以推进用例。核验引用与实际事实，不逐字断言模型措辞。
10. 覆盖结果拒绝、授权内恢复、人类批准和拒绝后的经理行为：经理主动组织后续处理；实际人类回答或决定本身是唯一新增输入，不追加逐步调度指导或“继续”消息。
11. 从项目经理页面核对并处理 PRD、Design Doc 和 Task Plan 等规定确认：每次可见业务操作说明、全部相关材料、经理已做动作、实际初审结果以及上下文和执行记录链接；逐一验证链接目标与当前确认版本一致，决定后经理自动继续。
12. 覆盖材料缺失或不可读、未进行初审、初审拒绝、产物返工和旧审批卡片等情况；页面如实说明状态，不伪造已完成工作，不以同名新材料替代旧版本。截图或页面文字本身不能替代引用与实际调用证据。

改造 engineering_evidence 及对应离线回归，使其验证当前合同和新的输入来源数量，保留确切执行、权限、独立评审和真实测试的检查。为“插入逐步指导”“以 Human 直接接纳”“伪造确认来源”“删除人类门禁”等篡改证据建立负向用例，确保核验器确实会拒绝。

定向测试通过后，按改动执行 Rust workspace、Schema、默认目录、架构、风格、HTTP 和 debug/release 浏览器必要回归。真实模型、Docker/Git 与 GitHub 证据单独出具，协议夹具成绩不能替代真实 Feature 验收。纯计划交付只核对文档链接和代码事实。

## 与其他方案的边界

[执行性能与稳定性方案](../workflow-runtime-performance/PLAN.md) 负责底层查询提交、调度交付延迟、分段预算与 Host/Docker 稳定性；[单 Host 并发方案](../single-host-concurrency/PLAN.md) 负责共享存储和 100 前端合同。本次负责“谁作出业务推进决策”和经理的事件、检查点及等待语义，复用共同端口与通知，不新增全局或项目锁，也不另建权威写入通道。

本次新增事件读取和投递必须有界，使用游标和相关范围；不把完整状态恢复与序列化比较作为正常唤醒机制。共享存储重构尚未落地的部分不能被本次功能成绩宣称为已完成，也不以完整并发重构作为编排语义验证的前提。

实施基线的 SQL 为 global 19 / project 49；本次根范围事件索引使用 project 50，global 保持 19。沿用仓库“不自动迁移、删库或转换旧开发数据”的合同；同版本重启恢复属于必须验收的能力，旧版本数据的采用不隐含在此次升级中。

出厂配置通过新不可变修订开放所需工具和方法，只对显式采用的新工作或合法后继会话生效。历史 Skill、Capability、Agent、计划和权限引用不能原地覆写；人工采用后继继续走现有停止与冻结边界。

## 最终完成条件

默认 Feature 从一次启动走到根流程及全部实际 Task 子流程完成，经理持续根据事件作出可追溯的控制工具调用；用户只承担冻结合同规定的业务决定、真实澄清和外部仓库操作。每次人类交互都能在项目经理页面直接看清需要做什么、对应哪些材料、经理已经做了什么和实际审核结果，并可直达确切材料、上下文和执行记录。指定配置区与工具流水已移除。事件丢通知、等待竞态、重启、重复输入和控制撤销均有验证，权限、人工确认及证据门禁保持有效。

只删除模板、替换提示词、跑通简化图、放大预算或由脚本补推成功，均不足以完成本计划。
