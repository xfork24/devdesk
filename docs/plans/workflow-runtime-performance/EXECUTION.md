## 已实施的改动

| 问题 | 实际修改与保持的约束 |
|---|---|
| 一次评估在每个步骤前复制全部状态 | 将回滚检查点推迟到步骤实际可能修改共享状态之后。未派发、等待确认/接纳及已结束步骤不创建整库检查点。可能失败的实际推进保留完整回滚；普通显式派发由原事务回滚保护。 |
| 为运行计数和空阶段恢复全部历史 | 增加 workflow 专用 SQL 运行计数及 pending 提示，通过现有池读取；无待办时跳过会话、控制器调用、平台工具、计划变更、委托和 Rust 驱动阶段的全量恢复。未知结果但未撤权的 writer 仍占用额度。提示不授予执行权。 |
| 外层/内层重复驱动 | Host 不再重复执行 `Engine::tick` 已处理的仓库与会话推进；删除工作流意图处理末尾的无条件再次评估。传入项目额度只扣其他项目，本项目占用由会话驱动核对。定时器跳过已错过的 tick，不积攒补跑。 |
| 结果已产生但回复等后续调度 | 经理调用先持久化真实结果，再在同一次驱动中交付。失败传输保留成功结果和待交付状态，后续只重试回复。成功平台回执不再同时发送一份重复的文本正文。 |
| 冻结权限重复编译 | 同一快照内按完整权限选择与 ExecutionScope 复用编译结果，下一快照清除该类 memo 并重新核对资产。不同写路径/工作类型隔离，缓存不能代替当前执行授权。 |
| 无变化控制器也写回 | 仅在控制器数据变化时更新记录，避免无意义 revision/通知。已停止步骤不再反复改写其结束时间。 |
| 经理失败/取消仍显示 active | 投影真实失败原因；取消经理 Turn 同事务暂停绑定控制器并提升 epoch，未执行的旧原生调用不能继续派发。失败/取消后的后继会话仍要求原 writer 停止证明。 |
| Host 在动作提交与原生结果登记之间中断 | 从原 `call:action` 身份、参数及旧 Actor 代次恢复耐久回执，即使控制器已经撤权也保留原动作成功事实，不重执行、不伪装为未应用。不可交付的原 worker 标记 unavailable。 |
| 经理超时归因不清 | 超时原因分列墙钟、已登记平台请求到回复登记的区间并集和其余区间；重叠调用只计一次。登记口径不等同于精确模型停顿，其余区间也不等同于模型推理。冻结的墙钟预算不变，没有提高 600 s 或无限暂停计时。 |
| Docker 创建失败不可诊断 | create 显式采集有界 stderr，仅输出识别的安全类别；核对容器不存在且 worker/输入尚未启动时记技术未应用。inspect/daemon 无法核对仍保留未知，不盲重发。 |
| Host 退出信息丢失 | 启动器记录 PID、进程组、session、收到的信号、子进程退出码；保留信号转发与退出回收。HTTP/运行日志共同判断存活，旧数据库 running 不是存活证明。 |
| 缺少运行阶段测量 | 复用既有 Trace/Span，增加 workflow tick、运行读取、实际步骤检查点、原生交付、Docker create/inspect/attach 观测。`DEVDESK_PERF_LOG=1` 开启；不记录业务参数、环境变量或正文。 |

没有引入新的通用连接池、CAS、持久化展开配置表或 SQL 基线。本分支仍使用继承的旧事务保护，不能单独移除 writer 锁。

## 同条件 release 对照

优化前为 `d3ae7d4` 加同一性能探针；优化后为该基线加本分支实现补丁。证据记录源码补丁、未跟踪源文件、探针及各冻结二进制 SHA-256。两边均为 release，固定测试 ID/时间源与同一 64 步输入；构建结束后顺序采样。不是 debug→release 的比较。

正式采用证据目录内 `accepted-prefix.txt` 指向的 **r4**。采样每 500 ms 检查 Cargo/rustc，r4 未观测到重叠。这里的组件指标不包含浏览器、模型或真实原生桥往返；30/20 个样本属于组件定位结果，不满足原生 P99/100 前端合同的样本量。

单位 ms，P50 / P95：

| 场景 | 样本/版本 | 优化前 | 优化后 |
|---|---:|---:|---:|
| 运行占用计数，保留 64 步流程 | 1000 | 6.4212 / 7.0122 | 0.0056 / 0.0065 |
| 64 个未派发步骤的一次评估 | 30 | 100.6233 / 104.6430 | 10.3481 / 11.1737 |
| 无待办的委托阶段 | 30 | 8.9926 / 9.2796 | 0.0053 / 0.0092 |
| 无待办的计划变更阶段 | 30 | 9.2453 / 11.4980 | 0.0054 / 0.0064 |
| 真实历史备份的只读冷恢复 | 20 | 384.494 / 391.351 | 269.097 / 280.391 |

64 步评估 P50 约改善 9.7 倍；真实历史冷恢复约减少 30%。运行计数的 1000 次完整工程恢复降为 0；空委托/变更各 30 次完整恢复及写事务都降为 0。64 步评估**仍有每次一次旧 Store 事务/完整恢复**，没有把该剩余成本说成已消除。

历史对照使用当前工程的在线 SQLite 备份，仅调用只读恢复函数，不运行调度器、迁移、模型或原 worker。备份有 13 个 session、43 个 Turn、43 个 execution，不是 D1/D3 大历史或容量场景。两边完整恢复值的摘要相同：`0bf66733e67700e8ba9ef2d86f1c88e4f680e3d78beab1395b841ccf2ee505d4`；备份主文件 SHA-256 在测量前后不变。优化后每次该快照观察到 10 次权限编译、145 次复用；旧版无对应 span，不能把缺失计数解释为零编译。

无效实验保留但排除：首次历史比较冻结二进制过晚，共享 Cargo target 覆盖了 before，两个副本相同，已废弃重采；另外两轮与并发分支编译重叠，也不计入上表。只有 `accepted-summary.json` 和 r4 原始样本支持上述成绩。

## 剩余联合门禁

1. 通用旧 `transact` 的一次全状态加载、克隆、序列化比较仍存在；共享存储迁移就绪后，workflow 用例按完整读写集合接入有限提交，同库一致切换，不能自行添加第二套 CAS 或提前删锁。
2. 多项目的外部慢 I/O 隔离、公平调度、SSE 和执行页读取仍与并发计划联合推进。本次消除重复阶段与回复多等一轮，不宣称已将所有 Docker/Git I/O 异步化。
3. 原生 bridge T0 到实际回复写入已有真实 Codex 场景及时间线，见 [运行验收](LIVE.md)；稳定的每类 1000 样本、100 前端、历史 10 倍、长稳及资源门禁仍未完成，不能用组件或单流程样本宣布轻量 SLA 和完整容量通过。
4. 分段活动预算、平台 deadline/无进展 watchdog 仍需显式配置合同及新修订；本次只改善链路和给出准确的登记口径诊断，不改变旧冻结策略。
