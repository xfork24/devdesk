## 2 时间线与指标口径

每次调用关联 Host 实例、数据集/项目、root/child instance、step execution、Turn、worker operation、controller epoch 和 tool request/reply；无业务正文、凭据、环境变量或完整宿主路径。

至少记录以下边界：

| 边界 | 含义 |
|---|---|
| T0 | 原生协议请求在 bridge 可读；尚未持久化的等待也计入平台耗时。 |
| T1 | 请求/意图耐久登记完成。 |
| T2 | 调度取得该待办，完成版本/权限校验并准备派发。 |
| T3/T4 | 实际工具/外部操作开始与结束；分别记录 Git、Docker create/inspect/start、协议初始化。 |
| T5 | 工具结果及状态接纳提交完成。 |
| T6 | 回复写入原 worker 协议连接；回复登记提交另记，不能混淆“已登记”与“Agent 已收到”。 |
| T7 | 后继技术状态就绪/派发；需要经理决策时，模型处理单独计时。 |

同时记录调度唤醒延迟、单阶段/单轮耗时、SQL 行数/字节、连接等待、事务等待与占用、源恢复/编译次数、序列化字节、队列长度、CPU/RSS、WAL 和停止证明。进程内耗时使用单调时钟，跨进程/重启使用关联身份和明确的采样边界，不能直接相减不同进程的单调时钟。协议没有接收确认时，T6 只声明完成写入，不能宣称模型已消费回复。

纯本机轻量调用的端到端为 T6−T0。对包含外部执行的调用，保留完整墙钟与实际外部区间，逐样本计算平台残余，不能直接相减不同分布的 P95，也不能把排队归入外部执行时间。嵌套 span 不重复相加。

每种方法/调用大小/场景分别报告 P50/P95/P99、样本数、失败与超时；正式分位数每类至少 1000 个样本。不足样本只作探索结果，重试不得抹掉首次失败。负载发生器记录计划发送、实际发送与完成，未发出和排队过期也进分母。

## 3 性能门禁

轻量调用指无模型/网络/容器启动/Git 执行，输入不超过 64 KiB、输出不超过 128 KiB 的 `workflow.inspect`、有界 `workflow.outputs.read`、结构 `spec.lint` 等。较大正文和重计算按大小分组，继续考核调度及交付阶段，不能通过全部标记“重调用”绕过门禁。

| 指标 | 目标 |
|---|---|
| 轻量原生工具往返 T6−T0，0 前端 | P95 ≤ 200 ms，P99 ≤ 500 ms。 |
| 轻量原生工具往返 T6−T0，100 前端 | P95 ≤ 500 ms，P99 ≤ 1 s；没有无解释的分钟级空档。 |
| 后台就绪到本机派发 | P95 ≤ 1 s；慢项目不得使其他可推进项目饥饿。 |
| 外部操作结束到回执接纳 T5−T4 | P95 ≤ 250 ms，P99 ≤ 500 ms；耗时内保留结果观察、版本检查和提交。 |
| 接纳完成到原生回复 T6−T5 | P95 ≤ 100 ms，P99 ≤ 250 ms。 |
| HTTP 摘要/驱动状态/普通步骤页 | P95 ≤ 200 ms，P99 ≤ 500 ms；零隐式业务写入。 |
| 执行页可用与事件收敛 | 首屏 P95 ≤ 1 s、P99 ≤ 2 s；事件 P99 ≤ 1 s，其他约束沿用并发合同。 |
| 历史增加 10 倍 | 相同活动负载与页大小下，轻量调用/摘要 P95 ≤ 原来的 1.5 倍，且仍满足绝对门禁。 |
| 后台完成吞吐 | 100 前端下 ≥ 同预算 0 前端基线的 80%；统计真实完成数，不能以空轮询频率代替。 |
| 停止控制 | 控制请求到停止调度 P95 ≤ 1 s；worker 实际撤权/退出单列并符合冻结停止期限，拿不到证明不能显示已停稳。 |
| 稳定等待 | 无可执行待办、仅等待人工决定或暂停时，60 s 平均 Host CPU ≤ 单核 2%；重启恢复与低频补扫单列。 |
| 资源 | 连接等待、短写事务、CPU/RSS、缓存/队列及 WAL 上限沿用并发合同；不得靠无限并发或无限缓存通过。 |

外部工具实际执行时间不要求满足轻量调用往返，但其前后平台区间必须满足门禁。大文件 Git 快照、慢 daemon 和模型服务分别报告，不以名称笼统合并成“验收”。

结构门禁：

- 活动计数、待办查询、经理摘要、分页读取和空轮询：0 次完整工程恢复、0 次全状态克隆/序列化比较、0 次历史闭包重编译；普通读 0 次写事务。
- 同一轮不重复驱动同一已观察批次；无变化不写控制器，已交付调用不反复扫描全部历史。
- 待办量与 SQL 返回行数受页大小约束；10 倍历史不增加被恢复的历史对象数。相同冻结引用复用不可变对象，但执行授权仍在提交前核对。
- 保持 main 配置读取零完整快照/零事务门禁；W4–W7 固定场景与同基线重复测量，P95 不恶化超过 max(10 ms, 基线的 10%)。不能牺牲已有配置优化换取后台成绩。

## 4 正确性与故障矩阵

| 场景 | 必须证明的结果 |
|---|---|
| 并发派发/接纳/审批/停止 | 相同控制版本只能形成一个合法结果；过期 plan、epoch、输入/产物摘要拒绝，配额不超发，已批准文档不被后继修改偷换。 |
| 两个相同命令与不同参数重放 | 同参数只产生一个耐久结果与外部意图；同 ID 不同参数拒绝；跨项目不复用回执。 |
| 旧全状态写与新提交切换 | 影子与交错测试证明无丢失更新；没有旧写者不推进版本的旁路。只删除锁不构成通过。 |
| Docker create 明确拒绝 | 真实非法资源配额或不可用挂载产生可公开类别；容器不存在/输入未发送有证明，记技术未应用，不误报业务失败。 |
| Docker create/inspect 不可核对、daemon 断开 | 保持未知结果，未确认前不得重发输入；恢复后按稳定操作身份核对并停止旧 writer。 |
| create 成功但回执丢失 | 唯一容器身份可恢复，不创建第二个写入者。实际 attach、消费输入和初始化阶段分别可见。 |
| Host 正常关闭、SIGTERM/SIGHUP、SIGKILL | 在意图后/派发后/结果后/回复后等边界中断，分别核对重启后的结果；正常关闭取得停止证明，强杀不伪造证明。无消费过的输入被自动重发。 |
| 经理平台等待与超时 | 控制可重复平台等待，活动预算与总墙钟按版本语义正确计时；平台 deadline/无进展 watchdog 会停止并给出原因，不能无限豁免。 |
| 租约与迟到回复 | 租约过期或 takeover 后旧 worker 不能写入新 epoch；回复绑定原请求，后继 Session 不消费旧回复。 |
| 慢项目与满队列 | 慢外部 I/O 不阻塞其他项目/前端；取消、结果交付及租约维护有预算，队列有界且保留持久化待办。 |
| 通知丢失、乱序、重复与重连 | 由耐久游标/待办补扫收敛，无重复业务效果；100 订阅者不产生 100 次完整历史扫描。 |
| 暂停与恢复 | 不再派发后继动作；立即停止取得实际撤权证明并保留产物。展示区分用户停止与业务失败，恢复采用核对后的后继动作。 |
| Agent 自主边界 | 业务决定由实际 Agent/既有授权 segment 作出；监管只做技术操作与用户授权的人工审批，性能优化不增加业务自动批准。 |

确定性故障注入和实际 Docker/Host 验证分开报告。Docker 原始历史 exit 1 的具体原因未知，不因新增测试通过就宣称已经追溯修复该次失败。

## 5 交付与判定

沿用仓库现有 Rust、Host、浏览器及协议测试入口，新增执行性能测试与上述竞态测试；实现时在执行报告给出实际可运行命令。定向验证先覆盖变更边界，最终跑相关完整回归及配置加载回归。

日志、JSON/JSONL、时间线、SQL 计划、采样、截图、备份及补丁身份放专用临时证据目录，计划目录只保存 Markdown。长期执行报告记录构建/数据身份、样本量、全部失败、指标与证据清单；脱敏记录不得含凭据及业务全文。
