# Workflow 通用执行合同

本合同落实已经批准的 [计划](PLAN.md)。业务名称、方法和验收策略是配置；执行协议、权限落实和证据真实性是平台能力。只交付一套新合同，不兼容或迁移旧开发数据。

## Workflow 与步骤

Workflow v4 保存 Stage、Step、显式输入输出和完成规则。Stage 可提供默认 Role；Agent Step 可以覆盖。有效 Role 必须在 Project 中绑定到属于同一 Role 身份的具体 Agent。编译器收集整个子流程闭包需要的 Role；启动时显式绑定这些身份，子流程继承同一份冻结绑定。

Step 执行器仅有 agent、tool、workflow、control。Agent 引用 Role，工具引用真实工具修订，子流程引用确切 Workflow 修订。control 是无副作用的屏障，可配置人工确认。阶段、步骤 key、标签和名称不决定执行行为。

Agent Step 必须包含非空 task_instructions。Skill 引用属于绑定 Agent 的能力集合，不能扩大实际 Tool 或 Permission。任务、Skill、Spec 和业务材料保留各自来源。不存在 execution_recipe 或额外隐藏的业务提示词分支。

端口引用由生产 Step、输出名和可选 JSON Pointer 组成；常量显式标注为常量。代码不求值模板、脚本或远程 Schema。输入来源必须处于依赖链内，类型必须与所引用的 Delivery 修订一致。输出类型结构在接纳实际产物时校验。

canonical `agent-task/v4` 同时记录每个输入的绑定、来源输出 ID 和值摘要。输出合同描述端口实际值的 Schema：文本交付是字符串，结构化交付按自己的 Schema 校验；内容检查的 key 和数量来自当前 Spec。只有 `completed` 必须提供全部必需端口，`needs_input` 和 `blocked` 可以没有产物。

## 规则与执行事实

规则仅包含有界的 all、any、产物存在、引用值相等、集合覆盖、执行先后、不同执行身份、可信执行结果和人工决定。规则不能读取任意宿主路径、运行代码或联网。状态机与证据真实性不由配置改写。

执行结果来自具体执行器，保存操作 ID、来源、输入摘要、资源和实际终态。配置规则引用的可信事实来自当前执行输出；Git 等受控工具还核对当前流程中的真实平台回执，不能上传一段 JSON 冒充工具或测试回执。模型判断与人工决定分开保存；人工决定绑定确切输入及产物摘要。

StepExecution 是任务和事实的关联入口，包含运行实例、调用路径、Step、轮次、执行序号、可选 Agent/Session/Turn/ToolCall。取消需停止真实 writer；未知副作用进入核对；技术重试产生新执行身份，业务返工产生新轮次并沿实际消费关系失效后继结果。

Step 预算传入实际原生执行器。人工补充、确认与祖先暂停不消耗活动执行时限。会话或轮次派发失败立即成为步骤失败；子流程重试同时恢复对应的父调用，不重做已经完成的兄弟步骤。

## 配置和边界

Role 是自由定义的业务身份，不能推导写权限、工作类型或输出 Schema。实际权限由 Permission、资源访问声明、Tool 及运行后端共同落实。各层只可收窄授权。模型供应商的协议实现和固定 SDK 映射属于代码，显示和默认选择属于配置。

代码输入授权绑定确切端口中的受管理工作副本、owner、代码修订、路径和分支。同项目内也不能任意跨归属读取；Feature 会话只有在当前冻结任务明确授权时，才可使用其 Task 的工作副本。目录授权允许任意安全的相对路径，不内置测试目录名称。

默认 TDD、独立评审、确认及候选接纳使用同一套配置与执行机制。测试执行器仍核验实际运行结果和代码版本；Git 执行器仍核验候选、预期目标及真实回执。

平台工具由独立 Tool Step 或当前 Codex Agent Turn 调用，共用处理器。Agent 调用必须同时属于冻结 Capability 和 Step 工具授权，绑定原生 worker、Session、Turn、请求及调用 ID；平台请求、执行回执和原生回复交付分别留痕。参数、权限或生命周期校验失败返回真实错误，不创建占位会话或外部接入。需要批准的平台写操作使用显式 Tool Step 和确认门禁；DSH 尚不提供该动态工具桥，配置时明确拒绝。

代码候选回执包含平台从实际 Git 读取的父提交和确切版本 diff，供独立评审使用。评审不需要读取宿主 `.git`，也不能把模型自述当作提交图证据。

Task 完成由显式 `tasks.complete` 工具步骤管理，不由 Git 发布隐式触发。它核对实际 Task 归属、依赖及执行者停止；业务验收条件与调用顺序属于 Workflow，纯材料工作不必创建 Git 交付。

正常配置发布与数据库副本沿用现有资源目录和 API。模板资源只是出厂默认，业务编辑不回写源码。开发数据清理仅针对已定位、已停止执行者的数据集及其托管资源，不删除用户源代码仓库或外部凭据。
