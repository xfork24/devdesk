## P1 存储基础验证

- 每热库初始 4 个读连接、2 个提交连接，进程上限 64；SQL 不持有池内部互斥锁，读连接 query_only，归还时回滚未结束事务，冷池可回收空闲连接。
- 有限提交在事务外准备 SQL/JSON，在短事务中校验全部读集合、CAS 版本、保存变化与事件/幂等回执；重放不发布新通知或推进目录时钟。
- 资源测试验证 100 个同版本写恰好 1 成功/99 冲突、100 个独立目标成功、100 个同 ID 并发重放只提交一次，并覆盖写偏差、批次回滚、注入 SQL 失败、读写隔离、有界 busy 及不可变源/head 提交。上述为存储端口测试，不等同于 C1–C15 或 P6 全部通过。
- 定向旧回归覆盖 workflows、runtime_registry、permission_profiles；P1 的 `cargo test --workspace --locked -- --test-threads=2` 全量通过。后续接口切换仍须按变更范围验证。
- SQL 基线改为 global 20 / project 50，增加 resource_versions、operations 的版本/游标列及事务目录时钟。新程序拒绝旧基线，不对原工作区正在运行的数据自动转换或重建。
- core/adapters 全目标 clippy -D warnings、rustfmt 与差异空白检查已通过；其后改动仍须再次按范围验证。
- 连接预算覆盖到初始化和临时读取，开连接前取得额度；跨项目目录改用读池。配置版本改为 SQL 触发器原子维护的 `catalog_clock`，与目录事实同快照读取，避免跨连接 data_version 误判及旧构建迟到发布。
- 新增目录缓存测试覆盖新连接读到已提交目录、旧视图迟到发布、回滚不推进时钟、运行事件不失效目录，以及全部目录治理类型的时钟覆盖。35 项适配器单元测试、9 项资源提交和 3 项设置用例通过。
