# 资源版本提交与请求作用域合同

状态：实施合同；并发类型、入口清单和有限资源提交端口已加入实施分支，公开 RPC 迁移尚未完成。当前实现进度见 [实施记录](EXECUTION.md)。

## 作用域

Host 将请求正规化为全局配置、指定项目或全局讨论，不读取共享活动项目。项目请求必须携带 `project_id`；全局讨论沿用明确的全局讨论标记，并拒绝混入项目 ID。全局配置类操作使用其明确的资源归属，不能把当前页面的项目选择当作全局资源的所有者。

现有请求字段中，`project_id` 表示本次请求所指项目；另一前端打开项目不使该 ID 过期。配置源 `scope` 表示资源所有者，不等于讨论命名空间。需要区分全局和项目同类资源时，适配层必须正规化到同一内部作用域类型，查询版本、接纳命令、幂等和事件都使用该作用域，不能分别推断。

每次请求只向一个权威库原子提交。跨库采用、配额和复制继续通过独立意图/回执恢复，不将跨库版本向量宣称为全局原子快照。

## 资源与版本

`ResourceKey` 为 `{kind,id}`，在所选库内唯一。`ResourceVersion` 为 `{resource:{kind,id},revision}`；0 只表示不存在，已有对象使用正整数。源内容修订、源 head、运行控制和普通对象各自有资源身份，不合并成一个项目大版本。

`ReadSet` 是上述版本的数组，包含本次业务判断依赖的资源及不存在条件。资源身份或版本范围无效、重复断言和缺少修改对象的前置条件都拒绝；即使通过反序列化构造，也要再次验证。

有限读取返回 `{resource,revision,value}`。多个资源在一个已提交 SQLite 读快照中读取；`value` 是其权威存储形状，配置/运行闭包的展开属于明确用例，不能隐含在通用版本查询内。

公开修改请求在 P2 迁移时携带 `command_id` 和资源前置条件集合。现有 `target`、`expected_revision` 可继续表达对应领域动作的确切版本，但不能代替源 head、多对象依赖或控制代次等额外前置条件。UI 必须保留编辑时取得的基线，不在保存前刷新版本来覆盖冲突。

## 准备与提交

core 生成 `PreparedChangeSet`，包含命令身份、原 Actor/参数指纹、`ReadSet`、有限资源变化、结果及应用环境时间。它不是可由客户端直接提交的数据库补丁，不允许 RPC 调用者指定底层表或自行声明可信 Actor。

adapters 在写事务外校验和编码待写值；短写事务内只校验版本、应用有限 SQL、递增资源版本、保存幂等结果及持久化事件。资源型读取和提交不恢复完整 `EngineeringState`，不持有项目或全局业务锁。

成功结果 `CommitReceipt` 包含 `{result,versions,cursor}`。`operations` 与业务变更和事件共同提交；相同命令/指纹重放原结果和原游标，不增加对象版本、目录版本或通知。不同参数/身份复用 ID 拒绝。

HTTP JSON-RPC 将 `receipt.result` 放在原有 `result` 字段，把 `{namespace,versions,cursor}` 放在顶层 `meta.commit`，避免把提交元数据混入配置源等领域值。`namespace` 由装配的权威库生成，不能由客户端伪造。

初次 CAS 可从已有对象的原生 revision 或明确的存在性恢复起始版本，后续使用 `resource_versions`。该机制不能使旧无版本写入与新 CAS 并行操作同一业务约束；同库旧写路径必须按计划完成一致切换。

设置项 `global_concurrency` 与 `default_harness` 已作为独立资源族先行切换：二者不属于旧 `EngineeringState`，旧全状态保存不写这两行，全部偏好写入都已改走资源提交。它们改变后续调度额度和默认选择，不撤销已有冻结运行。这个独立性证明只适用于这两个键，其余资源不能据此混用新旧写路径。

## 错误和重试

缺少前置条件为 `precondition_required`，过期资源版本为 `revision_conflict`，目录代次冲突为 `catalog_changed`；作用域错误不回退到其他库。SQLite 引擎竞争为 `storage_busy`，与业务版本冲突区分。

技术竞争按原前置条件有界重试；不能把原用户版本替换成新版本，也不能在重试中重发未知效果的外部操作。提交成功但响应丢失时依靠幂等回执核对。

## 入口与防遗漏

静态清单在 `crates/core/src/rpc_contracts.json`：显式区分 RPC 读取、修改、平台工具、已撤销入口和 HTTP 生命周期/回调。`tests/entrypoints/rpc_contract_inventory.py` 核对 Host/core 标识、通用源 create/revise 分派及实际 HTTP 路由，新增入口必须显式审阅作用域与版本策略。

清单登记的是入口合同，不能据此宣称旧处理器已经执行版本校验。P2 必须逐项接入提交端口并补齐缺失/过期前置条件、重放、竞争和副作用恢复测试；所有入口完成后才能移除旧保护。
