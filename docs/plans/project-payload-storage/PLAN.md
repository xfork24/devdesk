# DevDesk 工程库存储改造与百万级容量评估

## 目标

SQLite 保存调度、查询、授权、并发控制和恢复所需的核心元信息。长正文保存到项目文件系统，相同正文只存一份，已有可验证的 Artifact 优先复用。Feature 完成后保留确切输入、交付、审批、失败证据和可重放结果，清理已交接且无后续消费者的运行载荷。

以现有 9 个 Feature 和 535.5 MB 工程库简单外推，100 万个 Feature 约为 59.5 TB 的 SQLite 数据。样本里包含会话、工具和子流程历史，这个数字只说明当前存法的量级。百万级验收采用现有数据实测和容量模型，不生成百万条 Feature 或对应历史。

## 存储与读取改造

| 数据 | SQLite 保留 | 正文处理 |
|---|---|---|
| Feature、Task、流程和步骤 | 归属、层级、状态、时间、版本、计划及审批关联。步骤与历史尝试各有可索引记录 | 冻结计划、输入、历史执行快照和交付正文外置。已核实的 427 份工作流输出直接复用封存文件 |
| 工具、运行观察和经理回复 | 操作身份、阶段、状态、来源、授权与恢复校验字段 | 请求、计划、观察与回复外置。观察和回执各保留记录身份，共用相同正文。多次轮询引用原版本的 Session 和 Turn |
| 命令来源、工作流意图和幂等回执 | 命令 ID、指纹、调用者、目标、状态、回执引用和事件游标 | 原始参数、冻结输入和返回结果只存一份。重放按原引用恢复当时的结果 |
| 会话、经验、文档和快照 | 会话与轮次身份、顺序、类型、时间、来源和有界摘要 | 消息、工具正文和快照按页取用。历史续聊按原 Turn 边界读取。已有文件须通过等价校验才能复用 |
| 事件和待办 | 资源身份、版本、游标、待办状态与调度索引 | 普通事件保留元信息，确需审计和重放的详情通过引用读取。待核对的原始证据完整保留 |

先把现有 SQL 中用于筛选、排序、授权和版本校验的 JSON 字段迁成明确的列或索引。状态页、列表和调度只读元信息。详情、续聊和重放批量读取选中的正文。常用列表提供游标分页，兼容已有分页接口。列表的总数查询也单独检查，避免把全表计数藏在分页路径里。

项目内以 SHA-256 标识正文。先校验并持久化文件，再在短事务内提交引用和业务变更。详情或恢复发现正文缺失或损坏时明确报错。已完成的散文件可离线打成不可变归档包，按偏移和长度读取。运行载荷在对应交接事务中释放引用，离线回收在独占项目锁下校验引用后执行。

## 用现有数据评估百万级

1. 从现有工程库提取每个 Feature 的步骤、Turn、工具调用、命令回执和事件数量。分别量改造前后的 SQLite 表和索引页、外部正文、复用 Artifact、WAL 峰值及临时空间。按普通流程、较重流程和返工较多的流程给出 10 万、100 万、500 万 Feature 的容量区间。区分项目固定开销和每个 Feature 的增量，单列迁移、备份和回收的峰值磁盘。
2. 用现有数据和小型夹具测量同机冷读、热读和短事务写入。记录查询计划、访问行数、正文读取次数和字节数、持久化及 WAL 成本。覆盖列表、状态、待办、工具详情、续聊、重放和终态提交。
3. 按预计索引大小、树高、缓存命中范围和请求触及页数推算读取成本。按正文数、写入字节、索引更新、WAL 和同步成本估算写吞吐。列出不同并发和活跃比例下的范围，标注实测、推算和误差来源。

百万级验收要求查询成本随当前页、待处理批次或单个执行增长。调度、状态、列表、计数或续聊若仍扫描全项目历史，先修读取路径。当前数据上的常用读路径 P95 相对同机基线退化不超过 20%。百万级报告估算区间。

## 迁移与功能验收

新建项目使用新版工程库。已有项目使用 `devdesk-host storage migrate --data <path> --project <id>` 显式迁移。先在副本演练，正式迁移停写并取得项目锁，备份旧库，分批验证正文和新库后原子切换。用现有 9 个 Feature 验证，回收页空间后 SQLite 目标不超过 120 MB，同时报告整个 `./data` 的净变化。百万级容量由模型独立估算。

逐条核对原输入、输出、审批、快照和回执。回归覆盖历史续聊、失败核对、暂停恢复、子流程返工、同一命令重放，以及文件已落盘但事务未提交、文件损坏、并发写入、迁移中断与回滚。
