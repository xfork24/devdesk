# 工程库存储实测与规模估算

2026-11-22，macOS arm64，本地工程库的 9 个已完成 Feature。对迁移前备份与迁移归档后的实际项目做只读查询。磁盘单位使用十进制 MB、GB 和 TB。

## 容量和迁移

| 项目 | 迁移前 | 迁移及归档后 |
|---|---:|---:|
| 工程库 SQLite | 535.54 MB | 119.45 MB |
| SQLite 二级索引 | 34.71 MB | 21.00 MB |
| 新增外部正文 | 0 | 199.85 MB |
| 原 Artifact 实际分配 | 249.45 MB | 249.45 MB |
| `./data` 实际分配 | 3.306 GB | 3.090 GB |

生产迁移耗时 145 秒，归档耗时约 7 秒。10,534 个仍被引用的正文对象归档为 4 个文件。工程库的 WAL 在采样时为 0。逐条校验 40,294 条治理记录、37,209 条命令结果、4,653 条会话消息与 43,280 条事件，恢复值与迁移前一致。原数据库备份 535.54 MB 保存在 `./data` 外。

迁移期间，预留原工程库、候选库及其回滚日志和新增正文的空间。以本项目测得的文件大小保守估算，包含原库的工程数据峰值约 1.9 GB，加上原有 Artifact 和执行目录。这里的峰值是估算，备份和实际迁移用时是实测。

## 查询和写入

同机各采 70 次。热读复用 SQLite 连接，冷读每次重新打开连接，系统页缓存可能仍然有效。时间包含 SQL、所选正文读取和 Python 解码，包括正文 SHA-256 校验。该探针测存储路径，HTTP 接口只是等值验证，未纳入延迟表。

| 查询 | 热读 P95 前后 | SQLite 冷读 P95 前后 | 新版正文读取 |
|---|---:|---:|---:|
| Feature 游标页 | 0.007 / 0.010 ms | 1.599 / 1.382 ms | 0 |
| 工作流状态 | 0.027 / 0.018 ms | 1.573 / 1.464 ms | 0 |
| 平台待办定位 | 0.003 / 0.006 ms | 1.523 / 2.085 ms | 0 |
| 样本中的最大工具详情 | 4.083 / 2.791 ms | 11.360 / 4.332 ms | 2 段，1.078 MB |
| 代表性会话页，20 条 | 0.226 / 0.748 ms | 2.151 / 2.467 ms | 9 段，0.244 MB |
| 样本中的最大回执重放 | 5.695 / 5.478 ms | 6.061 / 9.647 ms | 2 段，1.555 MB |

20% 相对 P95 目标没有在所有探针中达成。热读取会话正文多耗约 0.52 ms，冷重放有约 3.59 ms 的增加。元信息路径使用索引，且探针没有打开正文。旧偏移分页、精确总数和包含搜索仍受命中规模影响。新版 Rust 读取在同一有界请求内可复用归档文件句柄。

4.1 KB 正文探针的文件发布 P95 约 0.25 ms，SQLite 单行加二级索引提交 P95 为 0.108 ms，原版本为 0.129 ms。数据库页从 4 KiB 调整为 8 KiB 后，该探针每次提交的 WAL 从约 8.4 KB 升至 16.4 KB。这个探针包含文件及目录同步，业务事务会受变更行数、索引数量和并发影响。

## 百万级估算

已完成 Feature 的会话量和事件量差异显著。约 0.70 MB 作为项目固定元信息，其余 SQLite 增量和正文按现有 9 个样本均值归一。以会话正文量的中位值、均值、最高值作为三种活动强度，模拟其余执行量随强度变化。

| Feature 规模 | 现行旧库存储的 SQLite 均值外推 | 新 SQLite 中位、平均、重负载 | 外部正文中位、平均、重负载 | 原 Artifact 平均活动 |
|---|---:|---:|---:|---:|
| 10 万 | 5.95 TB | 1.04 / 1.32 / 2.69 TB | 1.75 / 2.22 / 4.52 TB | 2.77 TB |
| 100 万 | 59.50 TB | 10.37 / 13.20 / 26.88 TB | 17.46 / 22.21 / 45.25 TB | 27.72 TB |
| 500 万 | 297.52 TB | 51.86 / 65.97 / 134.42 TB | 87.28 / 111.03 / 226.22 TB | 138.58 TB |

上述估算没有生成大规模数据。会话、工具记录和 Feature 的关系有项目级记录和零散独立会话。活动强度是一组敏感性参数。真实容量还会受留存政策、不同项目的重复率和工作流形状影响。总容量还需计入仓库、执行目录和共享缓存。

在百万级模型里，完全未缓存的索引查找预计需要约 4–6 个索引页，即每次约 32–48 KiB，另计命中行所在的表页。1,000 次同类点查每秒对应约 32–48 MB/s 的索引页请求上界，缓存命中会减少实际磁盘读。工具详情和会话分页的 I/O 按各自读取的正文数及字节数另计。例如每秒 100 次读到上述会话页的请求，对应约 900 个归档范围、24 MB/s 正文读取。

写入按每次事务的脏页数估算。若每次业务事务更新 8–24 页，每秒 100 次提交对应约 6.6–19.7 MB/s WAL 加上正文写入。单 Host 的饱和点取决于 SQLite 写竞争、磁盘随机读和同步延迟、索引缓存命中及检查点。当前工作仍将一个项目的元信息保存在一份 SQLite，**均值场景的 13.2 TB 仍会带来明显的索引缓存、备份和维护成本**。此结果支持估算单项目的资源预算，百万级吞吐没有做实测认证。
