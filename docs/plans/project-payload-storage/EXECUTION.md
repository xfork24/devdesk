# 实施与验收

计划见 [工程库存储改造与百万级容量评估](PLAN.md)。实测和规模估算见 [容量与 I/O 报告](PERFORMANCE.md)。

## 已实施

- project 61 用字段级正文引用保存大输入、输出、运行观察、准备载荷、经理和工具回执、工作流历史及会话正文。用于 SQL 查找与验证的元信息保留在原记录内。工作流状态使用事务维护的步骤摘要，原步骤数组继续保存步骤身份与顺序。
- 正文按项目内内容摘要复用。工作流产物优先引用原 Artifact。离线归档将散文件合并，按摘要定位归档范围。读取验证长度与哈希，批量读取复用归档句柄。
- 资源版本和命令回执使用主键组织表。资源变更事件紧凑保存版本列表，查询与重放恢复原有结构。大型命令结果按原提交保存可验证的引用。
- 显式迁移兼容混合版本数据集。迁移写入候选库并验证后才切换，原库备份随命令输出。正式项目已迁移和归档，启动后仍能访问旧版本的全局讨论库。

## 验证范围

- 正式库大小为 119.45 MB，达到 120 MB 容量目标。正文、回执、会话消息和事件逐条比较，完整性及外键检查通过。27 项迁移前后接口读取结果一致，包含工作流状态、历史和经验快照。再次运行迁移确认无需写入。
- 工作区授权、子流程返工和原任务恢复等配置工作流回归通过。全量 Rust 运行发现三处回归，分别涉及重放观测、外部回执测试读法和新版版本断言。修正后，相关的资源提交、工具集成和工作流套件、混合版本预检及适配器单元测试重跑通过。
- 归档测试覆盖并发写同一正文、读取归档结果、清理未提交对象和文件损坏识别。迁移暂存失败演练验证原数据库保持可用。
- 实测以现有数据和小型 I/O 探针完成。百万级容量和吞吐是推算。20% 相对 P95 目标仍有差距，尤其是会话正文读取和冷回执重放。带过滤的旧偏移查询与精确总数仍有随历史规模增长的成本。
