## 3 执行边界

- 以 main 的实际整合代码为验收对象，保留直接在 main 上完成的 UI、配置加载、诊断及其他并行改动；不以覆盖旧分支文件的方式修复。实施期间如 main 有新变化，单列身份并复核受影响部分，不能混算前后成绩。
- 单 Host、SQLite、项目分库、并发读和资源级乐观提交保持原设计；不以项目/全局业务锁、单写队列、关闭后台工作、降低负载或放宽超时换取通过。显示可最终一致，授权、版本、幂等和业务提交仍以权威事实为准。
- 用户明确排除持续新增的并行 UI 改动：本轮以冻结后台代码及对应 Web 产物验证调度、读取、审批和并发性能；后续独立 UI 修改不触发后台候选反复封存。保留这些改动，逐项注明实跑界面身份；不能据此忽略本轮冻结界面中的性能失败或宣布后续 UI 已验收。
- 使用独立空数据集、测试仓库/分支、私有二进制与端口；不停止、迁移、重建或压测用户现有运行现场。当前 SQL 为 global 24 / project 59，布局为 `single-host-resource-v2`；如确需改变存储结构，明确新基线和拒绝合同，不自动转换用户数据。
- 真实 Feature 启动后，验收操作者仅观察、采集证据及代理已授权的人工审批；不补“继续”、不派发/接纳/重试/返工、不切换驱动或 takeover/resume 救助后宣称完整自主通过。修复平台代码后，从新数据集重新完成自主用例；原失败轨迹保留。故障恢复另作专项。
- 审批须先有经理真实 `workflow.decision.request`，准确绑定原执行、材料和版本；通过项目经理页面签署，不用运行时补出的卡片替经理发起申请。批准只提交决定；结果接纳及后继业务动作由经理或其既有合法授权段完成。
- 保留默认工作流的人工确认、Spec、独立评审、真实测试及完成规则，不批准完成条件豁免。真实业务澄清超出初始需求时交给用户回答，不把审批授权扩展为代答或修改业务目标。
- 真实模型仅用于必要的经理/工程验证；大量统计样本使用测试专用可控端口及真实 Host/SQLite/传输，生产代码不增加模拟模式。测试夹具、真实 Docker/Git、真实供应商/GitHub 分别报告。
- 默认发布可能等待实际 PR 合入。代理审批不自动授予 GitHub merge 权限；真实合入由用户或已存在的仓库流程完成。若该外部事实缺失，保留发布等待并明确全流程尚未完成，不改终态或以模拟合入补足。

### J3 修复顺序

1. **保持经理自主性及审批边界。** 分离 agent 模式的 Human 决定与经理接纳；打通根/子实例的审批事件、经理读取、请求与展示。恢复待决定分页和精确引用，防止子流程越过第一页后丢失事项。给旧卡片、拒绝、返工后重新申请、审批/取消竞争增加回归。人工模式能力单独保留和验证。
2. **消除平台衔接等待。** 测出收包到登记、登记到派发、执行后接纳和原生写回的主要开销；去除重复恢复/编码/评估与同批串行等待。已耐久接纳的结果及时唤醒回复，仍绑定原 worker、Turn、operation、epoch。优化只排空已授权技术转换，不决定下一业务步骤。
3. **收敛待办与外部 I/O 调度。** 统一经理 waiting、Workflow 暂停/人类等待的待办判断，减少 active 即忙轮询；采用耐久待办、提交/worker 完成通知、下一期限和有界补扫。检查 8 个后台 worker 的占用、阶段去重、跨项目公平及配额；把慢 Git/Docker inspect、停止/日志/清理与短接纳、取消和回复隔离。停止证明取得前不释放 writer 或额度。
4. **消除页面与历史成本放大。** 修复普通查询剩余完整恢复；SQL 先过滤分页，摘要与正文/原始上下文分离。经理/步骤共享同键请求和资源失效，事件不刷新整页；隐藏标签页、折叠区域、已完成/稳定等待状态停止无效轮询，保留低频恢复机制。限制卡片、步骤和子流程读取及序列化大小，核对缓存的 Host/项目/资源/版本归属和草稿基线。
5. **缩短物理提交并验证历史增长。** 测量步骤 JSON 解析/改写、索引、读集合大小、事务占用、WAL/checkpoint 和连接等待。若只改逻辑版本仍无法满足延迟/规模门禁，再以同一权威存储合同调整粒度；不新增第二套可独立修改的执行事实或展开配置。保留旧版本拒绝、迟到回执及兄弟步骤交错提交证明。
6. **补齐预算语义缺口。** 核对原性能方案尚未完成的活动时间、平台等待、人工等待、总墙钟、平台 deadline 和无进展 watchdog。确需实现时发布明确配置修订，保留旧冻结预算语义；不提高原超时或无限停表来掩盖性能失败。

实际优化的先后可依据 J2 的主要瓶颈调整，但审批正确性与业务自主边界始终先满足；各根因按独立主题交付。

## 5 功能与自主性验收

### 默认 Feature 修改全流程

选择专用测试仓库中已有且可重复验证的小型功能，提交明确的行为修改需求，同时要求兼容性与真实测试；不只运行“在空目录新增一个文件”。如仓库没有合适对象，先在测试专用种子中建立并冻结既有功能和通过的旧测试，再由经理执行变更需求。初始准备与经理实施的改动分别留痕。

采用 main 当前默认 Feature/Task 的确切不可变修订，节点和人工门禁从冻结图推导。一次初始需求、一次正式 agent 启动，完整经历需求、设计、任务规划、子流程、独立测试、实际增量 Red/Green、实现、文档、评审、候选、发布及规定的外部观察，不删步骤或冻结条件来加速。

验收记录：

- 每项 dispatch、accept、retry/rework、complete 及父子流程推进的实际 Actor、Controller/Segment 授权、原生请求和回执；Human 业务调度动作应为 0，补充调度指导应为 0。
- 经理事件页、处理游标、delivery、检查点和等待；审批后不需要“继续”，根/子流程最终自行完成，经理结束且 writer 实际撤权。
- 默认 PRD、Design、Task Plan 等人工确认均由经理准备说明与材料，在经理页面签署；逐一打开本轮材料、审核、上下文和执行链接。保持现有 main UI 的布局、阅读深链、草稿和移动端行为。
- 精确材料版本、独立审核者、实际命令/退出码、两个真实 TDD 增量、候选 SHA 与发布回执；最终调用工程证据和自主性核验器，并补充针对“Human 审批顺带 accept”“缺失经理申请”“探针补调度”的负向验证。
- 报告总墙钟、各阶段耗时、模型执行/服务等待、平台执行/排队、审批等待和外部发布等待。报告关键路径及非重叠区间，不把并行执行时长简单相加，也不把模型耗时算入平台性能。

### 子流程审批与恢复专项

默认 Task 若不含人类门禁，另建合法、明确带子流程人类确认的测试专用 Workflow；不修改默认工作流。使用同一根经理，覆盖子流程申请、多个子流程同时待批、分页之外的待批、批准、拒绝与重新申请。验证经理先收到事实并主动申请，根项目经理页面能定位具体子流程与材料，审批后由经理自行处理后续动作。

通知丢失/重复/乱序、wait 登记竞态、租约过期、迟到 worker 回执、审批与取消/计划变更竞争、Host SIGTERM/SIGHUP/SIGKILL、Docker 明确拒绝及未知结果单独测试。真实故障只作用于测试 Host；未知效果先核对，不盲目重发，不用故障恢复轨迹冒充不中断自主完成。

## 6 联合性能负载与测量

### 数据、运行与前端矩阵

完整沿用并发合同，不以小历史诊断代替容量：

| 维度 | 必须覆盖 |
|---|---|
| D1 | 单项目至少 100 Feature、2000 Turn、10000 讨论事件、1000 步骤事实及合法关联、源和产物。 |
| D2 | 至少 10 项目，各达到 D1；至少 2 项目同时推进，包含全局讨论。 |
| D3 | 热项目历史至少 D1 的 10 倍；当前活动工作、页大小及冻结闭包不变。 |
| W1 | release 测试入口、真实 Host/core/SQLite/调度，测试专用确定性端口；至少 4 个可推进工作项，平均每秒至少 2 次状态提交。 |
| W2 | 正式 release Host、实际 Git/Docker/Artifact/回执；至少 4 个可推进工作项，平均每 5 秒至少完成 1 次真实执行。 |
| 协议层 | 100 独立上下文、鉴权、读版本、命令 ID 和 SSE 游标；开放到达率 100 次业务读取/s、10 次成功业务修改/s。 |
| 浏览器层 | 100 独立 BrowserContext、真实页面和 RPC；合计 100 次读取动作/s、10 次修改/s、5 次导航/s，记录动作和实际 RPC，包含可见及后台页面专项。 |

L1 同项目热点、L2 多项目独立切换、L3 100 读突发、L4 100 独立写突发、L5 同对象竞争/重放、L6 历史 10 倍、L7 断网/慢订阅者/重连、L8 60 分钟长稳，按原合同规定组合执行；W1/W2 的协议与浏览器结果分别出具。写入覆盖实际资源族及合法状态，不能全部选 no-op 或用预期冲突冒充成功写入。

先做 0 前端至少 10 分钟工作流基线，随后 1/2/10/25/50/100 前端各 2 分钟定位拐点。正式稳态预热 5 分钟、采样至少 20 分钟、各场景 3 轮；突发按合同重复 30 轮，L7 循环 10 次，L8 检查每个 5 分钟窗口。核心导航每类至少 1000 点击样本，冷进程/冷浏览器分别至少 30 次；原生轻量方法按方法/大小/场景至少 1000 样本。真实模型的少量工具调用单列业务证据，不能当作统计 SLA。

正式容量需要独立发生器/浏览器机器。历史报告确认当时没有独立负载机，执行时重新核对：若仍只能同机，则固定分离预算、监测发生器排队/CPU/内存并完成可行的本机联合矩阵，明确标为本机成绩；独立参考容量保持未通过，不停止性能修复或把同机结果升级为正式 P6。

### 必须保留的计时与成本

- 原生 T0 协议可读、T1 请求耐久登记、T2 获得派发、T3/T4 实际外部执行开始/结束、T5 结果接纳提交完成、T6 真正写回原 worker、T7 后继就绪。登记字段不冒充 COMMIT 或模型收到确认；跨进程时钟不能直接相减。
- 按关联身份记录调度等待、每阶段处理、批次队列、池等待、SQL/解码/闭包恢复、编译、序列化、提交占用、外部 I/O、通知及页面渲染；保留嵌套关系，不能相加重复计时。
- 页面从点击到主要状态/操作可用、事件提交到显示、请求个数/字节/重复率、主线程长任务及背景轮询；持续事件页面不以 networkidle 判完成。
- Host/worker/发生器分别统计 CPU、RSS、连接、缓存/队列、DB/WAL/checkpoint；观测开销有界，并用开关对照确认追踪未显著改变结论。
- 全部预定发送、实际发送、完成、失败、超时及未发出样本都入账；每方法/场景单列样本数、P50/P95/P99/最大值及吞吐，不仅统计成功请求或混合平均值。

## 7 核心性能门禁

以下为两份原合同的重点摘录；未列项仍按原合同执行，不因本表缩减验收。

| 指标 | 目标 |
|---|---|
| HTTP 摘要/状态/普通分页 | P95 ≤ 200 ms，P99 ≤ 500 ms；摘要 ≤ 64 KiB、普通页 ≤ 128 KiB。 |
| 普通修改耐久确认 | P95 ≤ 300 ms，P99 ≤ 1 s；标准负载下 storage_busy 和意外冲突为 0。 |
| 原生轻量往返，0 前端 | P95 ≤ 200 ms，P99 ≤ 500 ms。 |
| 原生轻量往返，100 前端 | P95 ≤ 500 ms，P99 ≤ 1 s；无无法解释的分钟级等待。 |
| 外部结束到接纳 / 接纳到写回 | 前者 P95/P99 ≤ 250/500 ms，后者 ≤ 100/250 ms。 |
| 就绪到本机派发 | P95 ≤ 1 s；100 前端后台完成吞吐 ≥ 同预算 0 前端的 80%。 |
| 页面可用 / 正常事件收敛 | 首屏 P95/P99 ≤ 1/2 s；事件 P99 ≤ 1 s，无故超过 3 s 直接失败；重连 P99 ≤ 3 s。 |
| 历史增长 10 倍 | 相同活动负载与页大小，轻量调用/摘要 P95 ≤ 原来的 1.5 倍，仍满足绝对门禁。 |
| 热路径结构 | 普通首屏/状态/分页/待办/空轮询零完整工程恢复、零全状态克隆/序列化比较、零历史闭包重编译；普通读零业务写事务。 |
| 稳定等待 CPU | 仅等人类/暂停等无可执行待办时，60 s 平均 Host CPU ≤ 单核 2%；恢复与维护单列。 |
| SQL | 读连接等待 P95 ≤ 10 ms；写事务占用 P95/P99 ≤ 10/25 ms。 |
| 资源 | Host RSS 峰值 ≤ 2 GiB；后半小时增长 ≤ max(128 MiB, 预热后 RSS 的 10%)；CPU P95 ≤ 固定预算的 70%；连接与队列有界。 |
| WAL | 热库 ≤ 256 MiB，停写后 30 s 内可回收到 ≤ 16 MiB。 |
| 动作完成及突发 | 完成率 ≥ 99.9%；100 读整组 ≤ 1 s，100 独立写及同目标提交/冲突整组 ≤ 2 s。 |
| 正确性 | 丢失更新、串项目、授权绕过、重复副作用、未提交可见、假停止证明均为 0；C1–C15 按原合同执行。 |
