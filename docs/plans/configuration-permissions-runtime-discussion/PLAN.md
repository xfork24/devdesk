# 配置归属、权限简化、本地安装与讨论展示改造计划

日期：2026-11-16。状态：已实施，相关功能定向验证完成。[实施与验收报告](EXECUTION.md) 记录实际结果与未执行项；用户后续要求无需全量测试，以下保留获批计划的原始安排。

本计划整合本次讨论的六项原始需求，以及后续确认的“去除执行授权”“简化增量回复展示”两项调整。目标行为以本文为实施依据；其他已完成计划保留其历史原文。代码核对基线为 `ec0f040`；原计划中的实施前描述用于说明起点，完成情况以实施报告为准。

## 3 改造后的配置归属

| 对象 | 负责内容 | 选择、引用与冻结 |
|---|---|---|
| Agent / Capability | Role、模型、Harness、Skill、完整工具及自身规范 | 继续按确切修订解析完整能力，不承载权限规则。 |
| Harness | Codex/DSH 版本、来源、许可证、安装件、启动入口、驱动/扩展及其安装要求 | 独立不可变修订；本机登录件与容器内程序分别核验平台和内容。 |
| Sandbox | Docker 基础镜像/摘要、平台、系统依赖、容器构建框架、结构隔离与后端资产 | 独立不可变修订；项目执行环境直接选择 Sandbox。 |
| Permission Profile | 文件、网络、工具、审批及平台操作权限 | Harness/Sandbox 各有对应类型；组件绑定默认 Profile，运行入口或步骤可直接选择确切 Profile。 |
| Workflow | 步骤、业务确认条件、调度配置、必要的步骤 Profile 引用 | 不内嵌另一份路径/工具权限正文；调度与步骤选择随工作流修订发布。 |
| Standard | 工作流及其规范依赖的不可变快照 | 自动包含调度正文和工作流显式引用的 Profile，不新增独立“调度 Standard”。 |
| 项目工具接入绑定 | 外部工具来源对应的账户、认证、执行环境、访问限制和工具范围 | 项目选择确切绑定；正式工作保留冻结版本，讨论在静止边界采用变化。 |
| 执行记录 | 实际所用修订、镜像/程序摘要、权限解析结果、调度快照与停止证明 | 保存运行事实；内部解析结果不作为另一份可编辑配置源。 |

## 4 项目工具接入绑定与 Permission 页面

### 4.1 项目工具接入绑定

将“项目接入账户”改为“项目工具接入绑定”。说明所选 Agent 的哪些具体工具需要外部接入，以及各工具来源当前采用哪个绑定；同一来源去重，保留工具关联以便理解用途。

空状态改为“当前所选 Agent 的工具无需配置项目级外部接入绑定”。没有外部依赖时不保留无意义的禁用保存按钮。存在依赖但未选择绑定时，明确列出缺少的来源；沿用自由讨论可先开始、具体调用返回缺少绑定原因的行为，正式工作按其冻结条件校验。

与 Codex ChatGPT OAuth、DSH 模型服务商凭据分别说明用途。管理链接继续进入工具及接入管理，相关绑定中的环境和权限字段改为新模型的 Sandbox/Profile 选择。

### 4.2 Permission 页面

保留 Profile 的创建、修订、导入导出、来源与历史；删除“执行授权（Permission Context）”分区及其所有编辑和选择入口。

将权限类型、权限修订、新建权限草稿置于统一工具行，字段名称在上、控件在下，按钮与选择控件底部对齐。JSON 正文和后续操作单独排列，窄屏自然换行。

详情直接说明 Profile 类型、规则及已采用位置；实际权限预览显示选中的 Harness/Sandbox Profile 与解析来源，不再要求补选 Context 或手工填写另一套执行范围。

## 5 删除执行授权，统一使用 Profile

### 5.1 唯一规则来源与直接选择

删除 `PermissionContextDefinition`、`permission_context` 源、`permission_context_ref`、`step_grants` 及相关默认项、Schema、RPC、查询和编辑器。不能通过改名、隐藏菜单、运行时拼回 Context 或新增等价包装源继续保留原模型。

Harness/Sandbox 的默认 Profile 绑定继续可版本化管理。步骤和必要的会话运行入口允许直接选择对应类型的确切 Profile；显式选择替换同层默认选择，不与被替换的默认 Profile 再次叠加。未显式选择时，在执行装配边界解析目标的默认绑定。

例如“测试目录可写”“实现可写但测试只读”“全仓只读”分别成为可复用 Profile；步骤只保存所选 Profile 的引用。固定工作区挂载下的规范路径（如 `/work/tests`）由 Profile 表达，宿主项目路径由可信挂载解析器映射，不将项目 ID、步骤 key 或角色名写成权限后门。

Profile 必须表达现有有效规则，包括只读例外、拒绝路径及精确工具范围。若现有 Profile 字段不能无损表达某条原步骤规则，先补足其合同和后端编译支持，不能在删除 Context 时退化为全仓可写或全工具允许。旧步骤工具修订约束需要有类型引用及引用图校验，不能丢失成不受校验的字符串。

### 5.2 双层边界与完整能力

一次执行明确采用一个 Harness Profile 和一个 Sandbox Profile；文件和网络访问同时满足两层约束。工具与审批、平台操作权限归 Harness Profile，Sandbox Profile 管理其可执行的文件和网络边界。

继续验证 Profile 对具体 Harness/Sandbox 修订及实际后端的适用性。已有目标默认绑定在显式覆盖时不再形成第三层限制，但后端支持范围、容器结构隔离和真实可访问挂载仍由执行器核验。

Agent 具备的工具仍由 Capability 定义。权限在调用时校验，不删除完整工具清单，不通过步骤要求给 Agent 增加工具。能力存在、账户绑定可用、Profile 允许和后端能够落实分别给出准确结果。

内存执行计划、Docker 挂载与原生权限配置只能由所选 Profile 和实际挂载映射派生。清除读取独立 `ExecutionScope`/StepAccess 授权正文的写入口，避免删除 Context 后继续存在隐藏权限源。

### 5.3 原 Context 职责的去向

| 原职责 | 目标位置 |
|---|---|
| `sandbox_ref` | 项目或无项目会话的执行环境选择；正式工作冻结确切 Sandbox。 |
| `harness` / `sandbox` 权限选择 | 组件默认 Profile 绑定，以及运行入口/步骤的直接 Profile 引用。 |
| `step_grants` 文件与工具规则 | 可复用 Profile 正文；步骤直接引用。 |
| `allowed_operations`、`human_operations` | Harness Profile 的平台操作权限；继续由可信调用链执行。 |
| `waivable_requirements`、`allow_task_revision` | Harness Profile 的平台操作权限，仍受工作流及内核的业务门禁约束。 |
| `max_turns_per_wakeup`、`max_tool_calls_per_turn`、`timeout_seconds` | Workflow 调度配置中的 Agent 编排预算。 |
| 人类确认、独立评审、测试与交付条件 | Workflow 原有业务规则；Profile 不能伪造人类决定或成功证据。 |

无工作流的自由讨论/经理会话使用运行入口声明的通用技术预算；工作流实例使用其冻结调度预算。技术预算只有一处有效来源，不因删除 Context 把原唤醒循环变成无限执行。

### 5.4 冻结、改绑与 Standard

新执行记录实际 Profile 修订、默认绑定来源（如有）、内容摘要和编译合同。显式 Profile 引用直接冻结；默认绑定一经解析即冻结，恢复/重试不再次追随当前活动默认。

权限发生变化时沿用静止检查、停止并核对写撤销、快照与后继会话机制；旧执行和未知回执保留。普通轮次复用原生 Session 不要求保留旧容器。

工作流显式选择的 Profile 作为配置图依赖进入 Standard 快照。组件默认绑定在实例装配时解析，并写入该执行的冻结依据；查看历史 Standard 或执行时不使用当前默认替换原版本。预览区分工作流显式选择与运行时采用的组件默认来源。

## 6 Harness / Sandbox 拆分与执行资产组合

### 6.1 字段和资产归属

| 现有运行资源内容 | 目标归属 |
|---|---|
| `provider`、发行 `version`、Harness 许可证及上游来源 | Harness；版本只维护一份。 |
| `native_releases` 的平台、URL、摘要、解包成员 | Harness 的本机发行件声明。 |
| 安装 Codex/DSH 的精确包版本、驱动启动入口、SDK 扩展与版本兼容声明 | Harness 安装输入；所需扩展内容纳入同一不可变修订和摘要。 |
| Docker 基础镜像 digest、支持平台、系统包、容器工作目录与用户等通用构建内容 | Sandbox。 |
| Docker enforcement、隔离支持与执行器后端资产 | Sandbox；Profile 规则仍由权限编译器应用。 |
| 混合 Dockerfile 和构建上下文 | 根据选定 Harness/Sandbox 组合生成内部构建输入。 |
| 预构建镜像 | Sandbox 可声明具有不可变摘要和实际 Harness 内容身份的配套镜像；校验与所选 Harness 匹配。 |

DSH 的 SDK 工具边界扩展、启动配置与其特定协议要求归 Harness；bubblewrap 等容器依赖和隔离资产归 Sandbox。实际组合须校验所需后端资产齐全且摘要一致，不能仅按文件所在旧目录搬运。

### 6.2 组合和身份

选定 Harness 与 Sandbox 后，由准备服务生成可重建的配方或解析匹配的不可变镜像，内容身份覆盖实际安装输入、基础镜像、平台及后端资产。缓存键不依赖可变标签或显示名称，不从系统 PATH 随机采用其他版本。

保留实际驱动、协议能力、平台和权限后端验证；发行版本相同不自动等于内容或能力相同。编译器、探针和权限绑定改为消费新组合内容身份，不再通过 `runtime_resource` 源或其摘要查找另一份配置。

删除独立源类型、出厂目录、manifest/defaults 项、引用边、查询字段、编辑器和“运行资源精确修订”选择器。内部仍可保存构建准备意图、安装登记、配方摘要和镜像事实，这些是执行资产记录，不提供第三种可编辑资源对象。

Harness 详情显示程序版本、安装声明、驱动能力、本机安装与依赖要求；Sandbox 详情显示容器平台、基础环境、配套镜像和组合准备结果。各自显示对应 Profile 绑定、适用性预检和来源。

## 7 本地安装复用与登录反馈

### 7.1 本机资产与执行镜像

建立同一宿主用户可复用的受管安装缓存，允许多个数据集登记同一已校验程序；数据集保留独立安装引用和使用记录。缓存只存程序、包和构建资产，OAuth、模型服务商凭据、Session 状态和工作目录继续按原边界隔离。

本机发行件以其发布摘要、平台和解包成员建立身份，解包后记录并校验实际文件摘要。URL、显示名称、无关 Docker 配方或数据集变化不使相同程序失去复用资格。

查找顺序为：已登记且可核验的资产、共享缓存中的完整资产、发行包附带的匹配资产，最后才下载。对当前数据集原有 `runtimes/` 中已校验资产保留发现与复用路径；登记丢失但资产完整时可恢复登记。摘要或平台不匹配时给出修复结果，不静默采用其他版本。

下载/解包使用按内容身份协调的锁、临时目录、完整性检查和原子发布；中断留下的半成品不视为可用安装，多个登录请求或数据集不会重复发布同一资产。

Docker 镜像按 Harness/Sandbox 组合身份及平台复用；先核对本地镜像和保留标签，再决定拉取或构建。数据集缺少登记时可根据可信内容证明重新登记，不能仅靠镜像标签认定匹配。已验证且内容完整的本地镜像不因再次打开登录而重建。

提供明确的安装检查/准备入口，展示本地版本、平台、来源、完整性和准备结果。缓存齐备时程序准备不依赖下载网络；官方登录授权和模型推理仍需相应服务可达。首次完全离线运行需要提前准备匹配程序及镜像，不将其描述成已有缓存即可自动满足。

### 7.2 登录状态与取消恢复

将本地准备与官方登录阶段分别报告：检查安装、等待共享准备、下载、校验/解包、启动认证进程、初始化协议、请求授权地址、等待用户完成授权、成功/失败/取消。页面显示当前阶段和已用时间；可获得下载字节时显示真实进度，否则不生成虚假的百分比。

阶段状态可通过请求身份恢复读取；刷新页面或重复点击复用仍有效的登录请求。准备、初始化、官方请求分别使用有界超时和准确错误原因，UI 请求不再以统一 25 分钟等待替代所有状态。

准备阶段就提供取消入口；取消仅作用于当前任务拥有的下载/认证工作，不影响其他数据集共享使用的资产、用户桌面 Codex 或工程 worker。共享准备的取消和等待需按实际使用者协调，无法确认停止时显示待核对，不能直接重新派发。

收到并校验官方授权 URL 后立即导航预先打开的普通标签页，工作区刷新在之后进行。保留可点击的官方链接以及窗口受限时的反馈。检查登录状态在已有本地凭据可判定时不隐式开启长下载；需要进一步协议核验时明确显示该阶段。

设置页说明当前登录程序及用途，并将“共享运行时安装”整理为“本地安装与执行镜像”一类的资产状态展示；此展示不重新引入运行资源配置类型。

## 8 Workflow 内嵌调度配置

### 8.1 内容与编辑

每个 Workflow 详情增加“调度配置”，随草稿编辑、校验、发布、导入导出和差异预览共同处理：

| 配置 | 来源与用途 |
|---|---|
| 最大并发 | 原 `max_concurrency`，约束相应实例可派发的执行数量。 |
| 每轮最大动作数 | 原 `max_actions_per_tick`，用于 Rust 驱动单轮推进。 |
| 租约时间 | 原 `lease_seconds`，用于 Rust 驱动租约管理。 |
| 技术重试次数及错误码 | 原 `max_retries` / `retry_error_codes`，只对明确可重试的技术失败生效。 |
| Agent 编排预算 | 从 Context 移入的每次唤醒轮次、每轮工具调用数和超时。 |

保留当前有效数值边界；出厂值来自工作流/模板配置，不在 core 按业务名称硬编码。可选配置的缺省值在发布时物化，实例恢复不读取后来修改的默认值。界面注明 Rust、Agent 或通用参数的适用范围，未支持的组合明确报错。

### 8.2 版本与执行

调度正文参与 Workflow 内容摘要和版本差异，自然进入 Standard 闭包。修改后发布新 Workflow 修订；既有 Standard 和运行实例继续使用其原调度快照。

根驱动读取根 Workflow 冻结配置，子流程的实例约束来自其自身冻结 Workflow；定义根树预算与子流程局部约束的执行范围，同一 worker 不重复计数。Host 全局并发仍表示机器总容量，不复制为独立可选调度策略源。

manual/rust/agent 执行方式选择继续表达运行方式；并发和实际派发边界共同受冻结约束，tick/lease 由相应驱动消费。技术重试明确与步骤重试预算的关系，避免重复重试；业务返工与业务确认沿用 Workflow 原规则。

删除项目配置、根实例页面的独立策略选择及 `policy_ref` 依赖。运行页面可只读查看冻结调度配置；运行方式切换沿用现有静止、epoch 和控制规则，不借入口调整绕过执行围栏。

## 9 讨论消息与“原始事件”新标签页

### 9.1 正常对话

每条 Agent 消息对应稳定消息身份。相同 Turn 和 `provider_item` 的 delta 更新该消息，full 用最终完整文本替换；不会把最终全文再次追加到已有片段。不能按相同文本跨轮合并，也不能把同一轮不同消息合成一条。

删除“合并展示 · N 条原始事件”、分片编号和逐增量链接。只有完整事件的首轮回复与有增量的后续回复具有相同消息外观和入口。底层流式日志可继续保留用于排查，但产品界面及诊断正文不逐条展示增量分片。

正常完成、正常停止回执从聊天消息流移除。执行中、等待审批/澄清、取消、失败和待核对保留简洁且可操作的状态提示，后端状态和人工交互判断仍基于权威回执。

### 9.2 原始事件入口和内容

每轮 Agent 回复区域提供一致的“原始事件”只读入口，关联稳定的 Session/Turn，并可定位当前消息。入口不显示底层事件数量；一轮包含多条消息时可跳至各自最终内容，运行回执按本轮统一关联。

新页提供运行信息与 JSON：Session/Turn 标识、执行操作、实际状态、停止回执字段（包括 `operation_id`、`writer_revoked`、停止 `mode` 和 `requires_successor`）、最终消息内容及其源记录 JSON。停止方式的 `mode` 与消息传输的 `delta/full` 模式分别说明，避免混淆。

内部终态与停止证明保留真实值，展示解释不改写 JSON。页面说明 JSON 对应已持久化的会话/执行记录；直接复用现有记录与协议产物来源，不能把拼接后的显示文本冒充原始协议帧。用户复制或查看 JSON 时不输出凭据字段。

普通点击通过带 `target="_blank"`、`rel="noopener noreferrer"` 的链接请求打开新标签页，移除 `popup` 和窗口尺寸参数；不使用模态框。浏览器最终打开位置服从其标签页偏好。新页支持刷新、深链接、错误重试和复制 JSON；读取时验证项目、Session、Turn、消息及执行的实际关联，兼顾无项目讨论。

继续验证第二轮复用同一原生 Session 的行为；完成一轮后的容器停止、下一轮恢复该原生 Session 都不产生重复消息或错误“需要后继”提示。

## 10 配置合同、数据与文档

本次涉及三类源删除和职责拆分，需整体更新源引用白名单、配置图、摘要、使用方检查、编译/预演、装配、Session 后继、Standard 闭包、RPC 和 Web 类型。`source_definitions` 继续为唯一配置存储，不增加一套展开权限或组合配方的权威配置表。

出厂配置把原步骤限制转换成明确 Profile 引用，保留测试与实现隔离、评审只读、实际工具限制和人工门禁。新的平台操作权限默认保守，不能在字段缺失时回退为允许全部。Harness/Sandbox 及 Workflow 新修订引用在 manifest/defaults 中一次性保持闭合，避免混用新旧模型。

如源、SQL 或冻结数据合同不兼容，显式调整数据集兼容标识及必要初始化基线，使用专用空数据集验收；不自动迁移、转换、删库或清理用户现有 `data2`。旧库保留，旧执行只能由兼容其冻结合同的版本读取/恢复，不承诺新版本直接运行不兼容历史数据。受管程序和 Docker 内容资产的核验复用不等同于转换业务数据。

删除旧活跃合同与入口，不用兼容别名继续接收新 `permission_context` / `runtime_resource` / `orchestration_policy` 写入。历史 Markdown 保留原文；旧链接可提供明确的新入口或不兼容说明，不偷偷选择新的默认配置。

实施完成时同步更新 `AGENT.md`、`README.md`、`docs/design/source-configuration.md`、`docs/design/permissions.md`、`docs/design/workflow-orchestration.md`、`docs/design/conversations.md`、`docs/design/tool-skill-integrations.md`、`docs/design/web-workbench.md`、`docs/design/protocol.md`、`permissions/README.md` 及受影响安装/发行说明。特别修正现行指南中 Context 授权、Workflow 不含权限选择、运行资源来源等旧约束；用户已确认的新归属优先。
