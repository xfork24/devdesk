# 工作流读取隔离

真实验收现场的 Feature 页面中，Add 的 query.work_configuration 已在约 12 秒返回两条历史，但目录和项目配置在 30 秒超时，规范历史因 Promise.all 共用结果而继续显示零条。同期项目管理面板每 2.5 秒发起新查询，未等待旧查询结束，网络记录保留多条重叠并超时的请求。

在独立 worktree 修正：项目管理轮询在本次读取结算后再安排下一次；卸载与上下文切换取消后继轮询并隔离迟到数据/错误。规范历史按自身读取结果展示，目录与授权读取错误不抹掉已返回的历史，规范切换表单仍等待完整授权来源后初始化。

补浏览器回归：较慢的项目管理读取不重叠且首个结果可见；目录或项目默认配置失败时已返回的规范历史仍可见。受控响应只用于 UI 回归，不作为真实模型、测试或 Git 回执。完成后合入 main，定向验证；避免中断正在执行的原生工作步骤。
