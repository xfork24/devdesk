# 保留历史的实现返工检查点

真实验收 `devdesk-project-1` 在独立评审拒绝历史环境证据后，从 implementation 返工。原输入仍引用 Red 快照，但工作树已被 implementation_snapshot 封存并推进，因此新 writer 无法启动。不能回退工作树、修改旧输入、放宽 Git 校验或伪造历史证据。

返工属于新的执行轮次。对有代码写权限的返工起点，内核可使用同一实例、同一工作区、当前已登记代码头对应的真实平台快照作为本轮检查点。只有已经存在并具有平台来源的完整 Workspace Snapshot 可用；未知 HEAD、跨范围、普通 Agent 产物不能成为检查点。检查点显式持久化到替代执行，记录原工作区输入、真实产物 ID 与新值；原执行及输入不变。

返工同时显式传递原因和本步骤既有产物引用；新执行只可读取同一实例同一步骤的历史产物，不能读取其他步骤或项目的材料。

新 writer 的工作区输入及后继 workspace.snapshot 的 workspace 参数使用该检查点；比较基线 diff_base、测试/设计/规范及其他输入保持原合同。实际 Agent 输入提供原绑定及检查点来源。Git 层继续要求 HEAD 等于冻结版本且无未封存修改，不自动 reset 或忽略漂移。新轮次不补造历史 Red/Green，真实环境证据仍交由独立评审。

回归覆盖实际 Git 快照后的写入返工、后继封存、历史不变、源引用可追溯和未知来源拒绝。定向检查通过后合入 main、重建签名 Host，并通过公开 stop/reconcile/rework 恢复原验收数据集，保留恢复前数据库和执行目录。
