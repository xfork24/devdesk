# Agent 完整能力与自由讨论及经验访问实施计划

日期：2026-11-15。状态：实施与本轮验收完成；见 [实施验收](EXECUTION.md)。范围：Agent 能力定义与装配、自由讨论、平台工具调用、Agent 经验读取、运行绑定、Web、配置源、协议及验收。

同一个 Agent 在自由讨论、工作流步骤、经理工作台和编排场景中保有其身份所定义的完整能力。Workflow 负责调度这些 Agent，不拥有、补发或裁剪 Agent 的技能、工具与能力。用户无需先选择项目、启动工作流或准备材料，就能与 Agent 对话，并让 Agent 读取现有 UI 中的“Agent 经验”。

当前 `devdesk-project-2` 的需求分析师讨论在发送首条消息时出现 `permission_conflict · 仅允许相同 Agent 与运行时的讨论切换`。本计划同时修复该问题及其背后的能力装配和上下文依赖，建立覆盖不同会话入口的一致合同。

## 1 已确认的需求

1. **能力属于 Agent 身份。** Agent 的 Role、Model、Harness、Skills、Tools 及自身声明的规范引用按确切修订组成完整配置。使用场景不能改变该组合。
2. **Workflow 负责调度。** Workflow 和 Step 描述任务、参与者要求、输入输出、依赖、验收和推进条件；所需技能是选择 Agent 的匹配条件，不成为另一份技能集合或能力授予来源。
3. **自由讨论无需业务对象。** 没有当前 Project、WorkflowInstance、Feature、Task 或材料时，用户仍能选择 Agent 并开始对话。缺少某项操作的必要目标，只影响该次操作。
4. **历史上下文就是 Agent 经验。** 复用现有经验记录、快照、文档和原始证据，不另建平行的记忆系统。Agent 在当前对话中可以检索、阅读并引用这些历史材料。
5. **当前会话归属与历史来源分开。** 无项目讨论也可以读取该 Agent 在既有项目、工作流和 Feature 中积累的经验；读取不要求切换当前项目、启动来源工作流或恢复成另一个会话。
6. **实例身份连续且可追溯。** 经验按 Agent 实例归属，不按角色名、模型名或相同配置合并。项目、工作流和 Feature 是经验来源与筛选维度。
7. **能力与调用授权分别表达。** 完整保留能力清单；具体调用检查 Permission、目标范围、必要上下文及实际驱动支持，并返回明确结果。

## 3 能力定义与运行上下文

### 3.1 Agent 的完整能力

沿用 `Agent → Role + Capability` 的单一配置来源。Capability 持有 Model、Harness、Skills 和 Tools 的确切引用；增加可选 `spec_refs`，表达 Agent 自身采用的规范。新增字段进入引用白名单、类型与可见性校验、组合摘要、使用关系和只读展示；缺省表示该历史修订未声明自身规范，不从当前默认配置推断。

Agent 自身 Spec 和当前任务的 Step、Delivery Spec 分别记录来源。前者随 Agent 装配，后者随当前工作上下文提供；相同引用可以去重读取，但保留两种引用关系。Spec 正文仍只保存在不可变源中，不复制到 Workflow 或 Agent 的另一份可编辑正文。

形成统一的完整能力解析结果，包含 Agent 实例、Agent 修订、Role、Capability、Skills、Tools、Agent Spec、内容摘要和运行资源要求。讨论、业务步骤、经理和编排入口只补充上下文与授权，不对该结果执行场景过滤。

现有 Workflow 中的 `required_skill_refs` 仅校验所选 Agent 是否具备要求。既有平台动作步骤仍表达调度过程中的确定性操作，其工具引用不向参与 Agent 增加能力。所有 Agent 工具调用始终从该 Agent 的完整配置解析。

### 3.2 分开记录三个范围

| 范围 | 含义 | 无当前项目时的处理 |
|---|---|---|
| 实例及配置来源 | Agent 实例和依赖定义的归属、可见性及确切修订。 | 保留原身份与来源，通过限定实例引用解析。 |
| 当前对话上下文 | 本次讨论是否绑定项目、Feature、Task 或工作流实例。 | 允许为空，Session 保存在全局讨论命名空间。 |
| 经验来源 | 被读取历史的 Project、WorkflowInstance、Feature、Task、Session 和快照。 | 按经验读取范围解析，不依赖当前选中项目。 |

全局讨论命名空间是存储位置，不要求将所选实例改成 Global Scope。选择已有项目实例进行无项目对话时，解析器可以从其来源项目读取该实例及配置闭包，保留项目可见边界；不能复制成一个丢失历史的新实例，也不能因此让它获得其他项目的私有资料。

创建全新实例继续明确选择归属，并遵循配置依赖的可见范围。没有历史记录的实例也能正常对话。

### 3.3 缺少上下文时继续对话

会话启动只要求 Agent 配置和基础推理运行条件有效。项目、工作流、材料、工作副本和某个外部接入账户，不作为所有讨论的统一前置条件。

工具描述和能力清单完整保留。调用时才解析它需要的业务目标、接入账户与资源：能从当前上下文或用户指定引用解析则执行；必要对象缺失则返回 `context_required` 及具体字段。相关资源暂不可用时返回明确的不可用原因，该次工具结果回传给 Agent，讨论继续进行。

外部接入未绑定时保留工具及依赖声明，延迟解析实际可执行绑定，返回现有或更明确的 `integration_binding_required`。不通过选用其他账户、其他模型或删除工具来完成装配。需要写入代码或调度工作的操作，仍检查其目标及实际授权。

## 4 统一平台工具调用

建立与工作流身份解耦的 Agent 调用者上下文，至少含 Agent 实例与修订、Session、Turn、worker operation、call ID、工具引用，以及可选的 Project、WorkflowInstance、Feature、Task 和 Controller 关联。调用身份由可信执行链生成，工具参数不能冒充调用实例或控制器。

统一执行顺序：

1. 确认调用属于当前有效 Session、Turn 和 worker，处理重复 call ID。
2. 从完整 Agent 能力解析工具，校验确切修订、参数结构及实际驱动支持。
3. 解析该操作需要的上下文和目标，分别处理当前上下文与显式历史来源。
4. 检查 Permission、目标范围及所需控制授权。工作流的步骤授权只约束本次操作，不删减工具定义。
5. 保存调用意图，执行并接纳结果，向 Agent 回传成功或失败回执；需要外部副作用的调用沿用现有恢复与核对机制。

`spec.lint` 在自由讨论中可以检查 Agent 自身或明确选择的规范与草稿；业务步骤仍按其冻结输入输出合同验收。`workflow.outputs.read` 可以在讨论中读取明确指定且可读的历史实例与材料，保留来源项目和计划，不要求当前讨论自身成为该实例的一个执行步骤。

工作流控制、项目经理策略、人工决定及 Git 写入等仍使用对应操作授权。用户在讨论中授予了实际操作权限时可以执行；缺少授权时回传具体拒绝。经理和编排的策略成为该调用链的一部分，不能继续通过过滤完整 Agent 的工具集合代替校验。

Codex 与 DSH 分别按真实驱动协议实现能力传递和结果回传。已声明工具不得因驱动缺失而静默消失。DSH 当前缺少动态平台工具桥，实施需补足本计划所需的上下文调用通道并单独验收；未完成的供应商不能被计为完整功能通过。

## 5 Agent 经验的统一读取

### 5.1 复用现有事实源

以现有 `experience` 记录、Snapshot、Document、Artifact 和会话执行关联为权威来源。共享库中的经验目录继续服务定位，内容由来源库只读读取。UI 和 Agent 使用同一个核心读取用例，通过端口接入跨项目存储，core 不直接打开 SQLite 或切换活动项目。

经验读取是所有 Agent 的通用上下文能力，以带版本的运行协议提供，调用形式采用模型可调用的只读工具。该协议与 Agent 的业务 Tools 一同展示并冻结，但不由 Workflow、Step 或 Controller 授予。其版本随实际运行绑定固定，避免仅为读取经验重建 Agent 实例或丢失其原有经验。

首版提供两个接口，名称在协议、UI 和适配器中保持一致：

| 接口 | 输入 | 返回 |
|---|---|---|
| `agent.experience.list` | 可选项目、工作流、Feature、Task、时间、关键字和分页条件。 | 当前实例可读经验的索引、摘要、来源、可用性及后续分页标记。 |
| `agent.experience.read` | 列表返回的来源引用，以及可选内容分块位置。 | 快照内容、文档与证据索引、完整性结果、内容摘要及后续读取位置。 |

Agent 调用时，实例身份从调用者上下文取得，不能通过参数换成另一个实例。用户 UI 查询继续显式指定所查看的实例。双方共享过滤、可见性、分页和完整性规则。

关键字首版用于来源名称和已生成摘要的确定性匹配；正文按具体引用分块读取，不引入另一套记忆生成或向量存储。列表先给索引和摘要，按需展开快照、文档和原始证据，返回总量及明确的继续读取位置，避免把全部历史塞入每次请求。

### 5.2 来源与版本

经验来源至少包含 `agent_instance_id`、`agent_revision_id`、`project_id`、`workflow_instance_id`、`plan_revision_id`、`step_execution_id`、`feature_id`、`task_id`、`session_id`、`snapshot_id`、时间及可核验的内容摘要。没有对应对象的自由讨论记录相应字段为空，不能虚构来源。

已有经验缺少工作流字段时，按原 Session 的执行关联和冻结计划重建只读来源视图；无法唯一确定则明确标记未知。新经验写入完整来源。不可变历史记录保持原样，不用当前工作流默认值回填过去。

Agent 在原对话中读取经验时，记录所读来源引用与摘要，后续会话快照能够追溯这些上下文。普通读取不触发 `experience.restore`，也不恢复历史执行状态。已有“基于快照开启新讨论”继续作为用户可选操作。

### 5.3 可见范围与异常

全局实例按原参与记录读取跨项目经验；项目实例读取其来源项目中的自身经验。无项目对话不会抹去或扩大这些边界。同配置的不同实例不自动共享经验；显式继承继续保存来源实例与当前引用者的区别。

列表与正文访问均核对经验归属及来源权限。来源项目未激活、工作流已结束、Feature 已完成都不妨碍历史读取。来源库不可用、材料缺失或摘要校验失败时返回具体状态，其他可读结果及当前对话继续可用。

## 6 运行绑定与当前报错修复

完整能力、执行授权、实际接入绑定和业务上下文分别冻结并计算摘要。相同输入在创建、发送、恢复及重启后必须得到一致结果，不能因装配路径不同而出现伪变化。

修复发送前检查和后继校验：

1. 相同 Agent、配置、接入和权限直接发送，不产生后继会话。
2. 真实权限或接入变化在静止边界按现有持久化意图创建后继，保留同一 Agent 身份、上下文和消息幂等性；明确列出允许变化的字段。
3. Agent 修订、Model、Harness、运行安装或适配器内容身份变化单独核对，不能伪装成权限变更通过。
4. 新代码遇到此前已经裁剪能力的旧 Session，识别具体差异，保存旧锁并通过可追溯的后继采用完整绑定。活动或未知执行先静止核对，不原地扩大其授权，也不丢失尚未消费的输入。
5. 错误信息分别说明缺少上下文、接入未配置、实际权限拒绝、运行环境变化或待核对，并保留结构化错误类别。当前笼统提示不能继续用于工具集合装配差异。

新增 Agent Spec 或修改业务能力仍通过新的 Capability 与 Agent 源修订发布；已有实例固定的业务修订保持原样。通用经验访问协议属于运行协议演进，旧 Session 经明确后继采用，不借此更换该实例的业务能力身份。

## 7 Web 交互

角色讨论以选择 Agent 实例为入口，当前上下文可选。没有当前项目时可直接发送消息；选取某个项目实例时显示其来源项目，不能隐式创建同名实例替代。

Agent 详情显示完整 Skills、Tools、Agent Spec 和通用经验访问接口。权限拒绝、缺少对象、接入未绑定或驱动暂不支持作为相应能力的状态显示，清单保持完整。工作流步骤显示同一能力来源，任务需要的技能和规范另外标明。

现有“Agent 经验”面板与 Agent 查询共享数据源，增加来源工作流与精确对象过滤，支持在当前讨论中引用经验。用户可查看 Agent 在本轮读取了哪条经验、其来源和版本；经验读取不改变当前选中的工作对象。

讨论引用历史工作只提供上下文。用户明确指定要操作某个工作时，再将该目标用于具体调用；不能仅因阅读某条经验就自动启动或续跑它。

## 8 实施顺序与交付物

| 阶段 | 工作 | 主要入口 | 完成条件 |
|---|---|---|---|
| W1 合同与领域 | 固定完整能力、可选上下文、经验读取及错误合同；增加 Capability 的 Agent Spec 引用与统一调用者结构。 | `crates/domain`、`schemas`、`crates/core/src/ports.rs`。 | 合法引用、摘要、可见性和参数校验有对应回归；模型中没有工作流私有的 Agent 能力副本。 |
| W2 一致能力装配 | 提取统一解析器，移除讨论、步骤、经理和编排的场景裁剪；分离工具声明与延迟接入绑定。 | `session_assembly.rs`、`configured_runtime.rs`、`controllers.rs`、`integrations.rs`。 | 同一 Agent 修订的业务能力清单跨入口相同；未绑定项目或接入账户仍能讨论。 |
| W3 通用工具执行 | 平台调用者与 Workflow Step 解耦；按工具解析上下文并执行授权，错误作为工具回执返回。 | `platform_tools.rs`、`spec_lint.rs`、控制器及经理用例、Host 装配。 | 自由讨论可实际检查草稿和读取指定历史产物；控制与写入授权回归保持成立。 |
| W4 经验上下文服务 | 抽取只读端口，复用索引与快照，补足工作流来源、分页分块及引用记录，注册通用上下文接口。 | `adapters/src/experience.rs`、`core/src/governance.rs`、`catalog_sync.rs`、Host 经验分发。 | 同一请求通过 UI 和 Agent 得到一致可见结果；无项目对话可读取自身历史。 |
| W5 绑定与恢复 | 修复创建和发送比较及后继校验，覆盖旧 Session 采用完整能力、重启、幂等与停止回执。 | `permission_resources.rs`、`permission_switch.rs`、`source_views.rs`、会话生命周期。 | 原始报错复现用例通过；旧锁、原消息和来源均可追溯，重放不重复提交输入。 |
| W6 驱动与界面 | Codex 和 DSH 接入统一上下文协议，补齐必要驱动通道；更新 Agent 配置、讨论和经验 UI，发布需要的新默认源修订。 | `adapters/src/harness.rs`、DSH 驱动与权限资产、`AgentCatalog.tsx`、`RoleConversation.tsx`、`AgentExperience.tsx`、`configurations`。 | 用户可从无项目入口完成对话、检索和读取经验；实际调用与页面状态一致。 |
| W7 回归与验收 | 执行下列验收矩阵、HTTP 与浏览器回归、真实运行验证，更新现行文档并保存报告。 | `crates/adapters/tests`、`tests/entrypoints`、`tests/browser`、`docs`。 | 自动化及供应商实机结果分别记录，全部范围通过后才标记计划完成。 |

W1 先固定共同合同，W2 是 W3 与 W5 的基础；W4 接入 W3 的统一调用链；W6 在相关端口稳定后完成；W7 验收全部路径。实施范围包含完整行为，不以“发送不再报错”作为全部完成条件。

## 9 验收矩阵

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 新数据集无 Project、Workflow、Feature 和材料，选择有效 Agent。 | 可以正常对话；历史为空不阻塞。 |
| A02 | 同一 Agent 修订进入讨论、工作流步骤、经理和编排会话。 | Skills、业务 Tools 和 Agent Spec 的确切引用与内容摘要一致。 |
| A03 | 实例已有项目经历，当前不选择项目。 | 保持原 Agent 实例身份，可以检索并读取其可见经验。 |
| A04 | 在项目 A 的讨论中读取该实例在项目 B 的可见经验。 | 返回 B 的确切来源；当前活动项目、工作流和代码均不因读取改变。 |
| A05 | 同角色同模型的两个不同实例。 | 默认各自读取自身经验，不能靠请求参数冒用另一实例。 |
| A06 | 自由讨论调用 `spec.lint`、读取已知工作流产物。 | 在有目标和授权时实际返回结果，不要求当前讨论成为工作流 Step。 |
| A07 | 调用需要目标对象的工具，但当前上下文为空。 | 返回具体缺失字段给 Agent，保留工具，并可继续交谈。 |
| A08 | 外部接入尚未绑定，或某次调用无实际操作权限。 | 对话可用；工具保留，调用返回准确原因，后端确实阻止未授权副作用。 |
| A09 | 经验属于已结束工作流或已完成 Feature。 | 仍可读取快照、文档与证据，保留历史版本，不自动续跑。 |
| A10 | 来源项目离线、材料缺失、摘要校验失败或历史不完整。 | 结果有具体状态，其他经验与当前对话继续可用；未知来源不被猜填。 |
| A11 | 经验超过单页或单次正文上限。 | 按稳定分页和分块完整读取，能核对摘要与继续读取位置。 |
| A12 | UI 与 Agent 对相同实例及条件查询同一条经验。 | 可见范围、来源、内容和完整性结果一致；当前对话可记录引用。 |
| A13 | 重现 `devdesk-project-2` 需求分析师首条消息报错。 | 消息只接收一次，创建与发送工具清单一致，无伪权限切换。 |
| A14 | 旧 Session 曾裁剪工具，且存在活动或待核对工作。 | 先处理静止与核对，完整能力通过后继采用；旧绑定及未消费输入可追溯。 |
| A15 | 真正修改权限、接入或运行环境，并重试、重启。 | 各类变化正确区分；后继和工具结果幂等，不重复派发或误换 Agent。 |
| A16 | Workflow 的技能要求、步骤授权和验收规则。 | 按完整 Agent 匹配；授权只作用于调用，正式输出仍通过原合同接纳。 |
| A17 | Codex 和 DSH 分别运行完整对话与经验读取。 | 分别保存真实调用证据；协议夹具通过不能代替真实供应商验证。 |

## 10 验证与交付约束

新增有业务意义的 Rust 回归，覆盖统一能力装配、无项目实例解析、经验读取范围、来源重建、工具失败回传及后继恢复。补充 HTTP 协议和浏览器用例，覆盖首条消息、空历史、当前对话引用经验、跨项目读取与错误反馈。

实施阶段按变更执行 `cargo test --workspace --locked`、`npm --prefix web run build`，并通过 `scripts/check/check.sh` 中相应架构、配置、Schema、风格、HTTP 和 debug/release 浏览器检查。工具声明保留不能代替真实工具调用成功，页面能展开经验不能代替 Agent 能读取经验。

真实模型和容器验收使用独立数据目录与已明确指定的运行资源，记录二进制、配置修订、实际工具调用、经验来源、回执和失败项。原始日志、JSON 和截图放临时证据目录；本目录只保存 Markdown 计划及执行、验收报告。

沿用 `source_definitions` 的单一配置存储和既有治理记录，不为展开能力或历史正文增加第二份权威存储。优先使用可兼容的新增引用和记录字段；若实施确需变更 SQLite 基线，显式更新合同并拒绝不兼容数据，不自动迁移、删库或重建。用户当前运行数据和已有未提交改动保持可追溯。

完成后更新 `docs/design/domain.md`、`docs/design/source-configuration.md`、`docs/design/conversations.md`、`docs/design/tool-skill-integrations.md`、`docs/design/permissions.md`、`docs/design/protocol.md` 及相关 Web 说明，使当前文档准确描述实际能力、调用与经验访问路径。
