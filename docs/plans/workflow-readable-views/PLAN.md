# 工作流程、材料、上下文与角色讨论的可读性改造

日期：2026-11-15。状态：待实施，本轮只制定计划。代码核对基线：本地 `main`，`bf5cc53`。

## 1. 目标与范围

让用户先看懂流程进展，再按需要查看材料、Agent 上下文和执行依据。默认页面不再用整块 JSON 代替正文，也不在步骤卡片中重复展开交付物和任务指令。

本计划采用四个执行详情 tab：**工作流程、材料、上下文、执行记录**。角色讨论继续作为独立入口，复用相同的内容展示规则。原始 JSON 通过用户点击在独立窗口查看。

仅涉及 Web 展示、导航及必要的 Rust 只读查询。不改变工作流调度、任务分配、验收规则、授权、源配置或数据结构；不增加模型调用、账号系统或其他核心功能以外的建设。不重跑完整工程验收。

## 3. 页面职责与交互

### 3.0 先确定目的和主对象，再安排内容

每个 tab 只有一个主要阅读目的和组织主对象。当前 Project/Feature/Task 是共同的范围边界，不意味着各页都复制一份按步骤排列的内容列表。

| 页面 | 首先回答的问题 | 组织主对象与默认视图 | 不作为本页正文的内容 |
|---|---|---|---|
| 工作流程 | 进行到哪里、由谁负责、卡在哪里、下一步能做什么？ | 流程实例 → 阶段/步骤；默认看当前进展、异常和待处理操作 | 材料正文、完整任务上下文、会话全文、原始执行数据 |
| 材料 | 已产出哪些成果、某份成果具体写了什么？ | 交付物目录 → 具体材料 → 正文；交付类型用于分类，步骤/执行用于来源和筛选 | 调度控制、整轮会话、上下文全集、操作回执全集 |
| 上下文 | 某个 Agent 执行当前工作时，实际依据了什么？ | Agent 实例 → 任务/轮次选择 → 冻结上下文；默认看选中 Agent 的当前任务 | 所有 Agent 的任务全文、所有交付物正文、完整聊天记录 |
| 执行记录 | 某一次执行实际发生了什么、为什么得到这个结果？ | 流程实例 → 某次步骤执行 → 当次决定与回执；默认看所选执行的事实链 | 无归属的技术杂项、成果全文、Agent 上下文全集、全项目日志 |
| 角色讨论（独立入口） | 这次会话提出了什么请求、收到什么响应、还有什么待回答？ | 会话 → 轮次 → 消息/调用；默认看当前会话 | 所有参与者的上下文合集、流程和材料的重复阅读页 |

统一遵循以下规则：

1. **一个主对象、一处主要正文**。跨页关联显示必要摘要和精确链接，进入目标页继续阅读；材料正文属于材料，冻结任务属于 Agent 上下文，对话属于角色讨论，执行决定和回执属于当次执行记录。
2. **先目录/选择，再正文**。材料、Agent 上下文和执行记录都以选中对象的详情为阅读主体，不默认展开所有对象。分类、筛选和历史轮次用于找对象，不堆成多层全文列表。
3. **摘要随页面目的变化**。例如同一份测试结果，在流程页表示步骤是否阻塞，在材料页阅读报告，在执行记录页核对实际回执。不能复用一个“全部字段详情块”铺满各页。
4. **细节有明确归属**。新增内容前先确定它属于哪个主对象；不把“执行记录”当作其余内容的收纳箱，也不为了安置单个字段继续新增 tab。原始 JSON 是各对象的独立查看入口。
5. **局部操作保留必要依据**。流程管理中的人工决定和讨论中的审批仍显示足以理解操作的摘要及对象引用，详细内容按主归属跳转，不增加强制阅读或审批条件。

### 3.1 工作流程：只承担流程管理

以流程实例、阶段和步骤组织内容，采用两级管理展示，第二级仍是简要管理信息，不作为正文阅读器。

- **第一级，步骤摘要**：阶段/步骤名称、状态、实际执行者或执行方式、当前轮次、正在等待或阻塞的原因。已完成步骤紧凑展示；异常和待人工处理事项有明确标识。
- **第二级，展开管理**：必要的前置条件说明、当前可用操作及简短处理结果；提供“查看材料”“查看上下文”“查看执行记录”“打开 Agent 讨论”等有目标的入口。
- 启动、暂停、停止、重试、核对、接纳、确认、人工决定和计划调整等原有管理能力保留。涉及人工决定时，操作对象、关键影响和理由必须可见，不能只剩无上下文的批准按钮。
- 不在两级视图内嵌 PRD、Design Doc、评审全文、测试日志、完整任务指令、Role/Skill/Spec 正文、输入输出 JSON 或原始执行快照。
- 材料入口只显示名称/数量等索引。一个步骤有多个输出时，进入材料页并筛选该次执行的交付物目录，再选择具体材料；单一输出可以直接定位正文。此来源筛选不改变材料页围绕交付物组织的方式。
- 子流程保留阶段与步骤的层次关系。历史执行入口只显示必要摘要，详情进入“执行记录”；流程级计划变更继续归于计划管理，原始计划/变更对象通过独立只读入口查看。

执行者来自实际绑定和记录；计划中的 Role、分配的 Agent、实际执行者有区别时分别标注，缺失则显示未记录，不能用当前配置推断历史实施者。前端现有状态汇总只承担导航提示，不改变后端终态和门禁判断。

### 3.2 材料：集中阅读交付正文

- 以交付物为主对象，提供目录和选中材料的正文阅读区。交付类型分类使用实际冻结定义的可读名称，不硬编码 PRD/Design 等固定栏目；同类型的多份材料仍各有身份，不因名称相同而合并成同一份文档的修订。
- 保留当前范围的搜索、分页和手工材料修订入口。所属工作、步骤/执行、轮次及接纳状态作为来源元数据和筛选条件，不把材料页做成第二份步骤执行列表。
- 默认只展开用户选中的材料正文。手工材料与工作流交付物在目录中明确区分来源，编辑操作归于选中手工材料，不与所有正文混排。
- Markdown 字符串直接渲染标题、列表、表格、引用和代码块。
- 结构化交付中的正文、结论、说明、证据等文本使用 Markdown；标量属性用名称和值，检查项及任务集合用表格/列表。测试结果区分执行状态、断言/环境失败及预期失败；评审结论和逐项证据分别展示。Diff 仍使用代码块。
- 以冻结的 `format`、已有协议字段和实际值结构决定展示；不得按 `builtin-*` ID、业务名称、版本号或特定验收项目选择渲染器。数组只有在实际合同/结构明确为任务集合时才标为 Task。
- 不认识的对象仍按字段分节展示，保留字段名；不认识的数组使用通用条目。缺失、空值和无法解析均明确提示，不生成虚构摘要，也不把 JSON 代码围栏当作可读正文。
- 冻结引用、来源 ID、校验详情等放入次级“来源与规范”区域；正文优先。完整原始交付通过“查看原始 JSON”打开独立窗口。
- 每项正文有稳定定位标识。从步骤进入时自动显示目标、展开正文、滚动定位并高亮，不要求用户重新搜索。

### 3.3 上下文：按 Agent 组织当前工作流程

主组织对象是 **Agent 实例**。当前工作范围限定目录，步骤/任务、会话和轮次是选中 Agent 的上下文选择条件，不默认展开成五层全文树。

1. 范围来自当前生效工作根及其关联流程。Feature 包括其当前 Task 工作根和嵌套流程；已有 Project/Task 入口使用各自范围。沿实际绑定收集参与者，不能混入同项目中无关讨论或已替换的旧工作根。
2. 优先以 `agent_instance_id` 分组，显示可读名称、Role 和参与工作。不能按显示名称或 Role 合并不同实例。旧记录缺少实例身份时单独标为“实例身份未记录”，保留会话/冻结 Agent 引用，不猜测合并。
3. 如当前编排控制器绑定经理 Agent，将其作为编排参与者单独展示，注明与步骤执行者的区别；不把 Rust/平台或人工步骤伪装成 Agent。
4. 使用 Agent 目录与选中 Agent 的详情区。先显示该 Agent 当前工作摘要和上下文可用状态，再选择所参与的任务/步骤及轮次；默认读取选中 Agent 的当前任务。任务多于一项时保留明确选择，不把全部任务全文同时展开。选中项按“任务请求、输入材料、工作背景、输出要求”分节展示；已有响应显示摘要及角色讨论链接，完整消息仍在会话中阅读。
5. 输入材料使用可读标题和材料定位链接，不反复嵌入同一份长正文。输出要求显示必要要求，Role/Skill/Spec 正文及实际发送的完整输入作为次级章节按需读取。
6. 实际冻结任务、平台记录的请求/响应与手工补充上下文分开标识。手工 Feature/Task 上下文作为该任务的共享背景引用，保留编辑入口；不得将当前手工内容宣称为某轮实际发送内容。
7. 默认展示当前轮次。当前工作流内的前轮/继承会话可显式展开；归档任务标为历史。完整请求响应继续可跳转角色讨论，不在上下文页重新建设另一套聊天或操作系统。
8. 没有 Agent、尚未派发或没有冻结任务时提供明确空态。平台/人工执行的详细依据进入“执行记录”；不为凑齐 Agent 分组制造记录。

### 3.4 执行记录：围绕一次执行核对事实与决定

新增此 tab，主对象为有确切 ID 的一次步骤执行。先选择所属流程实例及执行轮次，再查看该次执行的事实链；默认只展示选中项。使用现有执行、相关计划引用、控制器决定和回执事实，只提供阅读与关联导航。

- 选中执行按“执行身份与结果、关键操作/决定、真实回执”组织章节。执行状态、失败/核对说明和决定理由是阅读重点；长 ID、摘要值、输入输出引用等技术字段位于来源区域。
- 材料、冻结任务和会话在此只显示关联摘要与链接，分别回到材料、上下文和角色讨论阅读，不重复其正文。完整测试报告属于材料；本页展示证明某次实际测试执行及其结果的回执事实。
- 只列与选中执行有实际关联的决定、回执及历史依据。无法关联到某次执行的流程级计划变更保留在工作流程的计划管理入口，不能伪造归属塞进此页；其原始计划/变更对象可使用独立只读窗口查看。
- 模型声明、真实工具/平台回执、人类决定分别标识。没有记录的信息显示未记录，不能用模型的成功描述补成通过结论。
- 原流程页中的历史任务指令、输入输出引用和原始执行详情从这里进入相应材料/上下文或独立 JSON 窗口。
- 工作流程页保留待处理决定及管理操作；此处承接详细依据和已发生的记录，不新增审批流程，也不扩大为全局审计、日志检索或监控系统。

### 3.5 角色讨论：显示必要的请求与响应

- 以会话和轮次组织消息，围绕请求、响应及待回答事项阅读，不复刻上下文目录。普通用户/Agent 消息继续使用 Markdown，标明身份和轮次。当前任务提供必要摘要、局部预览及到确切 Agent/轮次上下文的链接，不直接倾倒任务对象或整套 Role/Skill/Spec 正文。
- 工具调用按已记录的事件类型和供应商消息结构，展示工具/操作名称、核心请求参数、响应正文/结果及错误；长输出可展开或转往对应材料。
- 状态、审批和澄清问题使用清晰的状态文字和字段布局，保留实际问题、选择和必要操作，不能作为“技术细节”隐藏。
- 没有可靠 call ID 或协议关联时不强行配对请求与响应；原有流式 delta/full 合并、事件顺序和终态语义保持。
- 未识别的结构使用通用字段阅读视图；JSON 解析失败保留原文和提示，不让整页失效。正文仍可一键查看该来源的原始记录。

## 4. 共用展示与只读查询

### 4.1 小型共用组件

复用现有 `MarkdownPreview`，整理少量文本/字段/列表/代码块展示函数，供任务、消息和交付内容共用。共用的是格式化能力，各页仍按自己的主对象和问题组织内容，不能用通用对象遍历器替代页面信息设计。未识别字段只在选中对象的补充详情中使用通用展示，不默认铺满页面。不要新增渲染器 DSL、配置投影表、业务类型注册系统或 Markdown 转存步骤；原始记录始终是唯一事实源。

沿用现有 Markdown 安全策略，不开启任意 HTML。默认摘要可缩短长文本，但应有“展开正文”入口，失败原因和人工决定的关键影响不能被截断到不可识别。

### 4.2 查询落点

- 材料复用 `query.workflow_materials` 的列表和 `output_id` 详情；冻结任务复用 `query.execution_task`；讨论复用 `query.session`/`query.sessions`；流程和历史复用 `query.workflow_instance` 及现有控制器查询。
- 增加窄的只读 `query.workflow_contexts`：输入项目和工作 owner，可按实际实例限定；返回当前范围的 Agent 分组与步骤/会话/轮次索引。每项包含实际可用的实例身份、冻结 Agent/Role 引用、工作/执行 ID、session/turn ID、当前或归档标记及详情可用状态。列表不返回所有冻结任务正文。
- 当前工作根选择使用现有权威规则，参与者归属使用 configured session、运行时绑定和控制器绑定。范围解析与材料查询保持一致，不能用“最后一条配置”、名称相等或 UI 列表顺序代替关联。
- 详情按选中项读取。单条事件的独立读取若现有分页无法直接定位，给现有讨论查询增加有范围校验的单条读取方式；不让窗口从第一页开始扫描整个会话。
- 执行记录以现有查询事实组成，按确切执行关联相关记录，不做全项目事实混合列表。若需要单条历史/决定详情，仅补充相应只读选择参数，不建立新的审计事实模型。
- 所有新入口核对 project/owner/instance/execution/session/turn 的实际关联。历史任务继续按原修订读取；不存在或不属于当前范围时明确报错，不回退为同名新内容。

Rust 修改限于 core 查询、必要路由装配及协议文档；不修改业务命令、数据库基线、源资源或调度器。通用字段展示是 UI 能力，不是配置合法性门槛。

### 4.3 原始 JSON 独立窗口

- 用户点击“查看原始 JSON”后打开独立阅读窗口，提供格式化 JSON、来源类型/ID和复制入口。浏览器限制弹窗时提供可打开的新窗口/标签链接，不能只用现有页内 Reader 代替。
- 使用同源只读路由，URL 只带来源定位 ID 和必要范围参数，不携带 JSON 正文、凭据或大段输入；窗口刷新后可重新读取同一来源。使用独立阅读壳，避免加载整个工作台及其后台轮询。
- 原始来源明确区分任务合同、交付记录、会话事件和执行/决定记录。JSON 字符串内的原文不能被摘要替换。流式合并视图不能冒充单条原始事件，需标明合并结果并保留对应事件来源入口。
- 不写回、不重算状态、不运行工具。读取失败、来源过期、无权限和未完整加载有明确提示；大内容按需读取，不能把截断内容标为完整原始数据。

### 4.4 精确跳转与历史

- 扩展现有详情路由，使用 `instance_id`、`execution_id`、`output_id`、`agent_instance_id`、`session_id`、`turn_id` 等实际所需 ID。显示名称只作标签，不能作定位主键。
- 跳转带齐项目及工作范围，切换到正确 tab，并选中该页的主对象。材料目标即使不在当前分页或搜索结果，也能在正文阅读区直接读取和定位，保留返回原目录的入口。从步骤进入多个输出时仅限定来源，不把目标页的主组织改成按步骤罗列。
- 上下文跳转自动展开目标 Agent、步骤及轮次。执行记录跳转定位确切执行/决定；刷新及浏览器前进后退保持一致。
- 当前材料查询只收集当前执行输出，不能直接用于旧轮次假定位。历史引用若有详情入口，应以原执行及冻结计划校验的单项读取展示，并明确标为历史；确实不可读时显示原因。此次不建设全量历史材料目录，绝不跳到当前同名产物充数。
- 无输出、尚未生成上下文或不可访问时显示具体空态；请求切换后隔离迟到结果和错误，避免上一个 Agent/项目的内容落入当前页面。

## 5. 实施顺序与交付边界

| 阶段 | 工作 | 完成判据 |
|---|---|---|
| P1：信息组织、阅读基础和定位 | 先落实各页主对象、默认选择、正文归属及跳转；整理共用字段/Markdown 展示；增加原始 JSON 独立路由；补必要的单条只读读取 | 页面结构符合 3.0 的职责表；同一份原始对象可在独立窗口刷新读取；正文与原文对应；无业务写入 |
| P2：材料与讨论 | 改造交付物目录、选中正文和定位；改造讨论消息及任务请求/响应摘要 | 材料以交付物组织，讨论以会话/轮次组织；Markdown、报告和未知对象可读；材料定位不受分页影响 |
| P3：按 Agent 的上下文 | 实现当前范围只读索引、Agent 目录和选中任务/轮次详情；接入冻结任务及共享手工背景 | 同名实例不混淆，无关会话不混入；默认只读选中 Agent 的上下文；材料、讨论可精确定位 |

## 6. 定向验证与验收

只做与显示和读取直接相关的验证。实施时使用两个现有验收现场的**检查副本或其再次复制的数据**，原始 Rust/Agent 验收现场保持不变；不运行模型、Docker 工程流程、真实 GitHub 操作或完整 C4/全仓验收。

| 检查点 | 验收要求 |
|---|---|
| 页面目的与主对象 | 无需展开其他对象即可回答各页在 3.0 中的核心问题；目录/选择/正文层次清楚，不出现把全部字段和正文换个 tab 继续堆叠的情况 |
| 工作流程 | 首屏和展开层无完整产物、任务注入或 JSON 墙；管理状态、阻塞原因、人工操作及子流程关系清楚 |
| 材料 | 以交付物目录及选中正文组织，步骤只作来源/筛选；PRD/Design、任务集合、评审、测试及其他对象可读；真实结论保留；任意数组不会误标为 Task |
| Agent 上下文 | 按实例目录及选中任务组织，默认不展开所有任务；当前流程归属正确，同名不同实例分开，无关会话隔离；当前、历史、手工补充来源明确 |
| 执行记录 | 选定一次执行即可追溯其参与者、决定、回执和结果原因；不混入无关执行或无归属杂项，不复制材料/上下文/聊天全文 |
| 请求响应 | 工具调用、结果、错误、审批/澄清有可读格式；长文本、流式消息和解析失败可正常查看 |
| 细节归位 | 材料链接到材料；任务上下文链接到 Agent 及轮次；决定、回执和历史链接到执行记录，无重复大段内嵌 |
| 原始窗口 | 真正独立打开；刷新仍读同一原始对象；窗口之间不串范围；不存在或无权限有提示；内容与源记录一致 |
| 定位 | 跨页/搜索外材料、多端口、子流程、历史、无输出情形有确定行为；前进后退、刷新及切换 Agent 不错位 |
| 加载 | 列表不逐条预取全文；展开按需读；失败可重试；切换时迟到响应不覆盖新内容；长表格/代码不挤坏页面 |

运行 `npm --prefix web run build`，并用浏览器逐项检查页面效果和跳转，保存关键截图。若有 Rust 查询修改，运行相应编译和少量有意义的范围/关联读取测试；必要时补定向浏览器回归，重点覆盖跨页定位、Agent 身份隔离和窗口原文一致性，不为静态排版堆叠测试。

浏览器检查应包含同一份工作的连续阅读路径：从工作流程发现阻塞或完成步骤 → 进入相关材料阅读成果 → 选择实际 Agent 查看当轮依据 → 进入某次执行核对决定/回执 → 返回流程继续管理。逐项核对每次跳转是否选中正确主对象，以及正文是否只在其主要阅读位置完整展开。

实施证据放仓库外，包括代码身份、实际检查项、截图、只读结果及已知限制；不得把受控 UI 数据称为真实工程执行结果。实施后在本目录留下 Markdown 执行说明，本轮不生成虚构通过报告。

## 7. 工程约束

遵守 [仓库约束](../../../AGENT.md) 和 [工程能力对齐计划的工程约束](../engineering-capability-alignment/PLAN.md#2-不可退让的工程约束)。旧计划中的阶段完成描述不作为当前代码事实。

- 依赖和职责保持 `host → adapters → core → domain`，只读聚合位于 core，Web 只展示和调用用例。
- 精确修订及冻结记录是依据，不读取最新默认来重建旧任务；不引入渲染器版本门禁。
- 不新增配置存储、SQL 迁移、数据清理或业务状态投影；原始材料、人工决定及失败事实保持不变。
- 人类决定、平台事实、Agent 输出分开标识；展示重组不等于业务接纳，不新增审批步骤或模拟成功。
- 当前任务到此只交付计划；后续实施按 P1 → P2 → P3 → P4 进行，使用独立工作区并遵守原始现场保护要求。
