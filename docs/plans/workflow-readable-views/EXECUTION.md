# 可读页面改造执行记录

实施位置：独立 worktree `codex/workflow-readable-views`，基线 `bf5cc53`。仅 UI 及只读查询；原始工程验收数据不用于写入或重新执行。

## P1：阅读基础与定位

- 增加按需读取、结构化文本阅读、精确导航和独立原始 JSON 阅读壳。
- 原始窗口通过来源 ID 重读，使用现有同源请求，不携带正文，也不启动工作台轮询。
- 会话支持读取属于指定 Session 的单条原始事件；冻结任务查询补项目范围核对。
- 验证：Web 构建与 `cargo check -p devdesk-core --locked`。页面交互的实际验证随 P4 在检查副本完成。

## P2：材料与讨论

- 材料采用交付物分类目录和单份正文；精确 output 定位与来源 execution 筛选独立于目录分页/搜索，手工材料进入同一选择模式。
- Markdown、Diff、测试报告、评审及任务规划分别采用适合的正文布局；未知对象使用可读字段，任意数组不再被标为 Task。
- 讨论保留原流式合并，展示工具请求/响应/错误；合并结果保留各原始事件入口。冻结任务改为必要摘要和上下文跳转。
- 验证：Web 构建通过，core 编译检查通过。真实检查副本的交互与截图在 P4 汇总。

## P3：按实际 Agent 的上下文

- 材料和上下文共享权威的当前工作根/嵌套实例范围解析，不以配置排序选择工作根。
- 新增只读 Agent 索引，按实际实例区分，任务/轮次按需选读；旧会话身份缺失时独立呈现，不按 Role 或名称合并。
- 经理编排参与者与步骤执行者分别标识；手工共享背景与冻结任务明确区分；继承快照仅允许读取属于当前范围会话的快照。
- 冻结输入使用材料链接，输出要求及职责/方法/规范按需展开；会话入口支持刷新后的精确定位。
- 验证：Web 构建和 core 编译检查通过。没有发起任务、模型或工程验收。
