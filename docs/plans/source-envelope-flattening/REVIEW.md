# 最近三次改动评估

评审日期：2026-11-13。范围：`48603ff5b8acde5b6e2bc827fdb1290309141c92` 之后的 `5bec145`、`58bb4d2`，以及基于 `58bb4d2` 的源配置信封扁平化工作区。按未上线项目处理，只验证全新数据集，不实施旧数据迁移或兼容层。

## 结论

三次改动的方向合理，建议保留。配置精简解决出厂目录冗余；服务商与模型目录进入配置体系、执行按内容摘要绑定，符合不可变组合原则；信封扁平化使引用与载荷职责更清楚。问题主要出在跨层接线和验证覆盖：离线端口替身没覆盖真实运行时注册后的摘要检查，批量字段替换也不能代替 API、浏览器和实际工程流程验证。

## 分项评估

| 改动 | 合理性 | 边界与结论 |

## 已修复的问题

1. **P1：真实 Codex 启动被摘要门禁阻断（`58bb4d2`）。** 注册运行时写入 16 位配方摘要，权限检查与完整 64 位比较。真实 Feature 首次启动即复现。统一注册、物化、绑定核验和目录匹配为完整摘要相等，16 位只用于镜像标签和错误展示。专项回归覆盖完整摘要、截断值、尾部篡改。
2. **P1：ModelProvider / ModelCatalog Host 写入入口缺失（`58bb4d2`）。** core 支持创建/修订，但 Host 未将方法识别为配置命令，无项目时误报 project_required。补齐路由，并验证服务商真实修订命令。
3. **P2：服务商目录重复返回历史修订（`58bb4d2`）。** 查询可能按源插入顺序选中旧事实。目录只提供当前、未停用的最新修订；已有 Harness 按原引用解析。回归同时证明新目录与旧不可变绑定的不同职责。
4. **P1：Web 与探针仍使用旧信封（当前改动）。** 补齐记录类型、Scope、Capability/Agent/Delivery/Harness/PermissionContext/Standard 引用的读取和保存，以及脚本、浏览器夹具、离线证据核验的 SQL 列名。历史视图的手工 JSON 投影同步改为 type，接入操作重放按 type 识别。项目使用位置查询的递归引用闭包补齐 refs，回归覆盖 Project → Agent → Capability → Model/Harness/Tool，避免项目中的间接采用被漏报。
5. **P2：新字符串 Scope 与 flatten 引用校验不足（当前改动）。** 拒绝不完整或畸形 Scope；引用区分单值与列表、验证规范修订和去重；Agent/Capability data 要求空对象，防止把根级引用重复塞回正文。写命令统一执行源校验。
6. **P2：Schema 和默认检查漂移（前两次及当前改动）。** ModelDefinition provider 不再以出厂供应商枚举限制可配置实例；源和 RPC Schema 描述各类型允许的引用、必需引用及正确形状。权限检查脚本、权限源 Schema、bundle 元数据、数据库索引和文档与新形状一致。

7. **P2：规范比较被晚到的配置读取清空（完整回归发现）。** 规范比较完成后，初始化的默认配置读取仍可能较晚返回，原回调会清空已经显示的比较结果。改为在实际工作/计划/比较对象切换时失效，并拒绝过期比较响应。新增可控延迟的浏览器回归，与真实双 Task Standard 切换用例一并通过。

8. **P2：证据脚本对实际存储与任务渲染的假设过窄（真实流程发现）。** 冻结计划在当前存储中是不可变源引用，不是内联 document；较大评审输入按合同为分块读取引用。修正核验器为按精确修订读取原始 Workflow，并将确切评审 Turn 的成功读取回执与原生工具响应匹配，重组全部字节后核对摘要与封存输入。增加 9 项回归，包括缺块、缺原生响应、错误 Turn/输出、篡改和源丢失；不增加旧格式兼容路径。

9. **P2：真实探针的退出和日志保留不完整。** 原入口在业务实例完成后立即停止 Host，可能中断 PM 正在结束的控制 Turn；每次恢复还会覆盖 Host 启动日志。后续入口增加等待控制器自然关闭以及启动前保留日志。本次业务已完成，未为验证该等待分支重复业务执行；原 PM 停机待核对状态与已有失败日志照实封存。
