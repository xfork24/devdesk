# 领域包与客户端扩展

DevDesk v0.5 独立交付 Rust Host、Web Core 和领域 ZIP。Host 带有 Model、Harness、Docker Sandbox、Git 和领域无关的工具、权限预设及领域模型。业务部署可从空领域开始，在运行时安装所需的 ZIP。

## ZIP 内容

| 内容 | 职责 |
|---|---|
| `manifest.json` | 包 ID、版本、标记、文件 SHA-256、配置与可选运行时或呈现目标 |
| `configurations/` | 不可变源定义和默认选择，以及实体 Schema、工作流绑定和引用索引 |
| `runtime/` | 可选 JavaScript 处理器、输入输出合同关联和运行辅助文件 |
| `ui/` | 可选客户端贡献声明与目标专属资产 |

格式由[领域包 Schema](../../schemas/domain-package.schema.json)、[对象定义](../../schemas/domain-entity-types.schema.json)和[客户端贡献](../../schemas/domain-contributions.schema.json)共同描述。核心与领域目录在源码中独立管理。软件开发包的 Feature、Task 使用冻结证据授权，仓库识别、分支命名、PR 文案、测试报告和页面入口也随包发布。

## 安装、激活和版本

安装核对清单、逐文件摘要、引用和包定义。用户可在 Host 运行时显式激活已安装的包。活动目录记录包 ID、摘要和活动代次，整个工作台共享一个活动领域。切换更新代次，客户端重新发现贡献。停用保留已安装的版本，卸载撤掉对应版本的运行入口。处于活动执行的包受到切换屏障保护。

核心工作台读取核心配置与未绑定领域的项目。领域工作台携带活动 `domain_epoch`，按包摘要合成核心定义、包内源修订和该包的项目目录。选定项目之前即可读取包内修订。项目建立时采用包内源定义，执行使用冻结的修订。仅供领域对象工作流使用的源定义由对象入口调用，日常配置目录只列出可选配置。软件开发的 Repository Preflight 属于仓库对象入口。项目及执行保存包摘要。切回所需版本后可读到它原有的项目和执行。更新 ZIP 使用新版本；同 ID、同版本的不同内容会被拒绝。现有早期包的离线回切检验使用真实历史 ZIP 夹具。

包内 Role 和用户在领域工作台创建的 Role 新修订都按领域显示。旧 Host 发布到全局库的包内 Role 副本仍可由所属领域工作台读取。

领域数据目录位于对应领域工作台设置页的「数据与运行」区块末尾。通过 Web SDK 的 `DomainLayout` 挂载的工作台在 `main.settings-page` 内用 `data-domain-storage-outlet` 标记此区块。目录设置按领域包 ID 保存在 Host 的领域登记库，空值表示使用 Host 数据目录。配置独立目录时选择空目录或已登记给当前 Host 和领域的目录。新项目在绑定领域包时固定存储位置，工程库、仓库、执行记录和产物位于该目录的 `projects/<project-id>`。修改设置时，已有项目保留原路径，设置页会显示这些路径。Host 数据目录保存领域 ZIP、项目索引、共享设置和凭据。架构重构前的数据集可先归档，再用腾出的目录承接新领域项目。

## 运行端与前端

「打开 GitHub 项目」按仓库和主分支匹配已登记项目。如果没有可复用的登记，会在当前领域数据目录的 `projects/<project-id>` 中查找可兼容的旧项目数据库。将完整项目目录拷回原路径后可保留原项目 ID、仓库和历史。遇到多个匹配目录或仓库路径不符时，Host 提示核对目录。

领域 JavaScript 处理器由 Host 调度到受限的 Docker worker 进程，使用 JSON-RPC 处理调用。Host 验证输入、范围、返回值和运行证据。核心 Git、持久化模型、调度与发起外部操作的权限仍由平台管理。

Web Core 使用 `web.react` API 2 将活动包的 ES 模块装进同一 React 树。组件获取当前项目、导航、RPC 和订阅上下文。领域页共用布局和主题，以包提供的样式表扩展。执行脚本与核心前端共用浏览器上下文，前端资源请求需要匹配当前包摘要和代次。

非浏览器客户端通过 `query.domain.active` 和 `/domain-events` 读取相同代次及贡献目录。它可以用通用动作、字段和数据查询自行呈现，也可以实现包声明的专属呈现目标。项目操作与事件订阅使用相同的作用域规则。原生客户端无需加载 Web 资产。

协议示例见[RPC 参考](reference/rpc.md)，安装与兼容矩阵见[运行指南](run-binary.md)，跨端制品验收见[测试索引](../../tests/README.md)。
