## 实现及保留的边界

[有界委托](../../../crates/core/src/workflow_segments.rs) 的 Tool revision 4 增加两个默认关闭的显式选项：

- `prepare_human_requests:true`：完成条件和证据检查通过后，使用原审批材料投影准备普通 `workflow.step.confirm` 请求。必须同时明确 `include_human:true`。
- `complete_instance:true`：必须授权当前实例全部节点；全部接纳、交付、子流程及完成合同满足后，调用原受保护的 `workflow.complete` 登记真正完成。父实例授权不覆盖新 Task。

两项分别核对当前经理的请求/完成权限，并消耗原有 64 操作预算；授权时预估所需操作，不能发放无预算完成的自动收尾委托。[自动动作](../../../crates/core/src/workflow_segment_actions.rs) 复用原控制入口、确切输入/产物、事务读集及审批依据。同一个确切结果具有稳定请求标识，重复授权和重启共享请求。拒绝不重提，不能生成 Human 签名、批准失败评审或豁免完成规则。旧工具和省略选项的调用保持原来的派发/接纳语义。

普通审批请求、真实签署和完成通知仍进入 SSE 与审计；只在同经理、同 epoch 的明确授权内合并模型投递。拒绝、失败、输入、计划、驱动和授权变化仍是注意边界。根真正完成且经理 worker 静止后，由协调器关闭经理。

[成功停止通知](../../../crates/adapters/src/workflow_stop_events.rs) 另有确切证明：匹配原 session、turn、operation、输入和计划的不可变 native terminal 必须成功且静止，原 worker 停止证明必须已经接纳，并排除显式停止。正常输出接纳可能晚于停止事件 400ms，不能只靠短时间配对判断。此提示减少通知，后续输出、内容、失败及未知副作用校验继续执行。

[普通 Feature 创建](../../../crates/core/src/workspace_commands.rs) 还补齐了与 `workflow.start`、子流程创建相同的返工额度初始化。只在新建事务中确立已知零次历史；旧实例未知历史仍需核对，已有共享额度和上限不重置。

### 为什么 workflow 一栏增加

| workflow 侧归属 | 旧净秒 | 新净秒 |
|---|---:|---:|
| 原生 turn 准备/回收生命周期 | 51.578 | 64.628 |
| 经理控制接口 | 8.664 | 1.159 |
| 原生平台工具请求/回传 | 7.285 | 8.623 |
| 其余内部衔接，尚未独立细分 | 19.954 | 48.925 |
| 合计 | **87.481** | **123.335** |

这是墙钟归属，不能直接解读成“调度器变慢 41%”。分配优先级为外部排除、工具、Agent 服务、turn 生命周期、剩余内部时间。旧轮有更多经理活动与其他工作/外部等待重叠；减少经理轮次也改变了这些时间最终分配到哪一栏。

原始累计生命周期的准备实际从 **77.523 降至 60.380 秒**，terminal 后收尾从 **30.109 降至 12.972 秒**，合计 107.632 → **73.352 秒**。把累计转成净互斥账本时，旧轮因并发、外部排除或更高优先级归属扣去 56.054 秒，新轮扣去 8.724 秒，因此净生命周期栏反而增加 13.050 秒。`open_intent → open_observed` 原始累计也从 71.868 降至 **59.102 秒**；它可能与其他生命周期跨度重叠，不另行加入合计。

剩余内部衔接从 19.954 增到 48.925 秒，目前没有足够子 span 将其全部分到 Docker、空间/权限 preflight、打开会话、协议导出或 scheduler。完整时间线显示每段归属，数据不足时不声称全是调度 CPU，也不把整栏增量都解释成某一个实现退化。

本轮净收益的账面关系是 **Agent 减少 132.427 − 业务工具增加 11.587 − workflow 分配增加 35.854 = 84.986 秒**。这支持“确定性控制接力已减少”，不支持按回合数比例推算总体提速。
