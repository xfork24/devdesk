# Web 工作台与 Host

工作台负责组织用户操作和解释结果。Host 负责保存状态、执行规则和推进后台任务。浏览器刷新、切换项目或断开连接，不改变已有任务的业务状态。

## 页面如何取得数据

应用先读取初始化和项目目录信息，确认当前标签页所选项目。配置页按需读取目录、正文、引用关系和诊断；执行页分别读取工作区、流程摘要、步骤详情和产物。长历史和大内容分页或分块读取。

这样做让用户可以先看概况，再打开细节，也避免每次刷新都恢复整个项目历史。代码入口见[前后端衔接](../crates/web-integration.md)。

## Feature 工作队列

工作总览以项目主分支为根。展开 Feature 可查看对应的 Candidate 和 Feature 分支，再展开 Feature 分支查看 Task。分支名来自仓库登记与已记录的发布回执，交付状态依据已提交的工作状态和合入回执。尚无记录的分支显示占位。Task 按页读取，选中 Feature 后可从队列顶部进入对应项目的执行工作台。

## 配置加载期间的用户操作

配置编辑器按确切修订读取详情，目录列表可以只显示每个配置的最新修订。恢复历史选择时，即使目录稍后才加载完成，当前详情和未保存的草稿也会保留。

用户点击配置列表中的操作按钮后，列表停止自动选择首项。切换到 Skill 导入时，编辑器同时取消尚未完成的条目详情请求，保留导入界面和草稿。

工作规范与授权表单在默认值读取完成后才可编辑。切换 Standard 时，表单从其根级 Workflow 引用中读取第一个入口流程。

## 命令与显示状态

用户保存或执行时，客户端提交明确的项目 ID、命令身份和原对象版本。Host 返回业务结果及提交元数据，页面据此更新相关查询。

如果收到版本冲突，草稿仍保留原内容和版本。自动刷新只更新展示，不能偷偷用新版本重发旧草稿，否则会掩盖用户没有看到的并发修改。

页面应区分“已提交请求”“后台运行中”“等待输入”“等待确认”和“已完成”。Host 接受启动请求不表示模型已产生结果。

## 事件怎样刷新页面

浏览器订阅作用域固定的 SSE 尾流。Host 共享读取器和有界缓存向订阅者发送变化提示。前端使相关查询失效，再读取当前状态，不把事件流当作可独立重建全部业务状态的数据库。

`stream.ready` 触发初次刷新，`stream.reset` 表示缓存或游标不足以补齐间隔，客户端重新查询。配置版本提示和工程事件游标有不同用途，不能用目录新鲜度令牌替代业务修改前置条件。

## 项目、经理与批准

每个标签页维护自己的项目选择，RPC、SSE 和产物请求显式携带作用域。一个标签页切换项目，不会让另一个标签页的请求转向新项目。

经理页面展示工作流状态、消息和待处理决定。人工批准由 Host 记录用户来源；UI 不直接写步骤终态。子流程的待处理事项可以在经理上下文中显示，但决定仍须绑定具体对象和原版本。

## 连接其他 Host

“连接内核”先探测目标的产品和协议，再打开目标 Host 的同源工作台。此后数据、凭据、Docker 和 Git 操作都发生在目标机器。它不把当前机器的运行资源透明迁移过去。

协议详见 [RPC 与 SSE](reference/rpc.md)，界面修改约定见 [Web 开发规范](../crates/standards/web.md)。
