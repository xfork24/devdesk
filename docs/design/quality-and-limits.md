# 质量、诊断与当前限制

DevDesk 的正确性既包括规则计算，也包括真实进程和远端系统的行为。不同测试层证明不同的事情，不能把其中一层的通过扩大解释为完整工程交付已验证。

## 测试层次

| 层次 | 验证内容 | 不能单独证明 |
|---|---|---|
| domain/core 单元与集成测试 | 规则、状态、配置、版本冲突、恢复决策 | 真实供应商协议或 Docker 环境可用 |
| adapters 存储和协议测试 | SQL 提交、进程消息、权限转换、异常处理 | 所有真实账号和平台都可用 |
| HTTP/浏览器回归 | 请求合同、项目隔离、显示和交互 | 模型产出质量或远端合入成功 |
| Docker 原生协议验收 | 固定安装与容器的实际协议和隔离行为 | 付费模型推理和真实 GitHub 交付 |
| 真实工程验收 | 指定模型、仓库、认证和机器上的交付过程 | 其他配置、其他平台或全部容量要求 |

执行入口与修改后的检查选择见[测试与扩展指南](../crates/testing-and-extension.md)。

## 主要架构取舍

| 选择 | 获得什么 | 要承担什么 |
|---|---|---|
| 单 Host + SQLite | 部署简单，项目数据本地可控 | 单机资源限制、短事务竞争、跨库协调 |
| 固定配置修订 | 运行可追溯，恢复不追随最新配置 | 更新后需要明确采用，新旧引用并存 |
| 外部操作与业务提交分阶段 | 可以核对中断前是否已执行 | 需要操作身份、结果记录与恢复逻辑 |
| Harness/Sandbox 分离 | 模型程序和执行环境分别配置 | 配方、驱动、权限和安装兼容性需要检查 |
| 有界查询与 SSE 失效提示 | 避免每客户端扫描完整历史 | 显示允许短暂延迟，重连可能需要重新查询 |

## 支持范围与容量

当前一个数据集只支持一个管理 Host。Codex 与 DSH 的普通运行及工具桥有不同能力声明，根经理编排目前要求 Codex。仅有模型目录、凭据检查或安装探针成功，不能说明完整会话可用。

工作流运行时支持至少 100 个活跃前端是容量要求；连接建立或局部性能改善不足以完成该验收。正式判据见[并发验收合同](../plans/single-host-concurrency/ACCEPTANCE.md)。历史报告说明各自当时执行的范围，当前文档不把未完成目标写成已实现的性能保证。

旧数据迁移不属于当前自动启动行为。程序拒绝不兼容数据集，详细要求见[运行指南](run-binary.md)。

## 诊断顺序

先确定项目、工作流实例、执行和会话身份，再读取对应状态与原始失败原因。然后按边界检查：配置是否可解析、资源是否准备、权限是否落实、Harness 是否收到输入、工具是否有实际结果、输出是否通过检查。

`DEVDESK_PERF_LOG=1` 启用 Host 性能日志，RPC 也提供请求关联信息。嵌套阶段的耗时存在包含关系，不能把所有字段直接相加。诊断日志不应包含凭据、完整请求正文或用户产物。

技术故障应保留原操作记录。重新生成输入、换模型、换密钥或清空数据库，都会改变问题条件，不能作为不留痕迹的“恢复”。
