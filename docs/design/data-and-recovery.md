# 数据、并发与恢复

DevDesk 将可查询的状态放在 SQLite，将较大的交付内容保存为产物文件。Docker 和 GitHub 在数据库之外，因此一个 SQL 事务不能保证这些系统同时成功。恢复机制必须分别记录“准备做什么”“实际观察到什么”和“最终如何处理”。

## 数据怎样划分

| 存储范围 | 主要内容 | 边界 |
|---|---|---|
| 全局配置库 | 配置源、默认选择、项目目录及全局设置 | 为项目提供可采用的定义 |
| 项目工程库 | Feature/Task、会话、工作流、执行、事件和工程记录 | 请求必须明确选择项目 |
| 全局讨论库 | 不属于项目的会话与讨论材料 | 不回退到某个项目数据库 |
| 产物目录 | 文档、结构化输出及其他内容 | 数据库保存身份、归属和摘要，读取时核验 |
| 运行资源 | 容器、状态目录、Git 工作树及私有认证材料 | 生命周期与业务记录关联，但不是同一事务 |

配置源以 `source_definitions` 为主存储。UI 列表、运行摘要和缓存是读取视图，不能独立替代配置或执行事实。SQL 布局见[迁移与基线索引](../../sql/README.md)。

数据集内，全局配置数据库是 `global.sqlite3`，项目数据库是 `projects/<project-id>/engineering.sqlite3`，全局讨论数据库是 `conversations/global/engineering.sqlite3`。这些是诊断时的定位信息，外部调用者仍应通过带作用域的接口访问，不能直接写表改变执行状态。

## 一次可靠的外部操作

以启动分析师为例：

1. core 在数据库中保存执行身份、输入版本和准备启动的操作。这个持久记录称为 intent。
2. Host 取得该操作的执行资格，在事务外调用适配器启动容器。
3. 适配器返回容器及协议观察结果。core 核对它是否属于原操作，保存结果，再推进业务状态。
4. 如果进程中断，重启后先查原操作和实际资源。已有结果可以接纳；未知结果需要进一步核对。

启动、产物写入、Git 发布等操作采用各自的身份和核对方法。这提供可追踪的恢复路径，并不意味着跨 SQLite、文件和远端服务存在一个统一的 exactly-once 事务。

## 并发修改怎样避免覆盖

命令携带自己的 `command_id`，以及它读取的对象版本。core 准备一个有限的读取集合和修改集合，存储适配器在短事务内检查这些版本并提交修改。

例如两个人都从 Feature 的第 5 版开始编辑，第一个提交产生第 6 版，第二个不能把旧草稿直接覆盖上去。系统返回 `revision_conflict`，页面保留草稿和原版本，让用户查看差异后重新决定。

同一命令 ID 和相同参数重放时，返回原结果；同一 ID 换参数会被拒绝。SQLite 锁竞争可以有限重试同一个提交，但不能借此重新准备业务命令或再次启动外部操作。

普通查询从已提交快照或有版本的视图读取，不持有长时间的业务写锁。显示缓存允许稍后刷新；授权、版本比较和最终业务提交必须以存储检查为准。

## 几种继续执行的方式

| 操作 | 适用情况 | 保留什么 |
|---|---|---|
| reconcile，核对 | 不知道外部操作是否完成 | 原操作身份、输入和已有观察结果 |
| retry，重试 | 已明确可以再尝试同一任务 | 原配置与输入条件，原失败记录 |
| rework，返工 | 结果被评审拒绝，需要业务修改 | 原拒绝、返工原因、前后执行关系及额度 |
| 计划变更 | 后续步骤或依赖需要调整 | 预览依据、停止相关执行的结果、旧计划和历史 |
| resume，恢复推进 | 流程已暂停且具备继续条件 | 当前已保存状态，不重新创建全部历史 |

计划变更分为 preview、quiesce、apply：先计算影响，再使受影响执行停止或失去写权限，最后校验原版本并应用。迟到结果仍应留有记录，不能覆盖已被替换的执行。

父步骤把已确认取消的子流程记录为结果已知的失败。返工可在现有授权和额度内创建新的执行，原执行及其取消结果留在历史中。子流程仍有未核对的外部副作用时，必须先核对原执行。

## 停止与重启

暂停调度不等于正在运行的进程已停止。取消或清理需要适配器提供停止、写权限撤销或资源移除的检查结果。只修改状态字符串无法阻止原容器继续写入。

Host 关闭时停止接收新的调度工作，等待当前阶段并核对自己管理的 worker。重开保留历史，结果未知的外部操作先核对。共享镜像不因某个会话结束而删除。

恢复当前格式的数据与迁移旧数据库是两件事。当前程序只打开兼容数据集或初始化空目录，不自动转换旧布局，也不以删库解决恢复问题。操作要求见[运行指南](run-binary.md)。
