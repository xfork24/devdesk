# Web 工作台指南

Web 是构建后嵌入 Host 的 React 单页应用：默认打开 `http://127.0.0.1:4317`，与内核同源（会话 Cookie 鉴权），全部操作经 `/rpc` JSON-RPC 与 `/events` SSE 完成。本文按导航区说明操作入口；运行语义见 [工作流与编排](workflow-orchestration.md)，部署与远程连接见 [运行包说明](run-binary.md)。

## 初始化与连接内核

首次打开时先探测 `/capabilities`：需要初始化则显示设置页选择数据集目录；受密钥保护的远程内核显示密钥登录。设置页的"连接内核"可切换到其他 `http(s)://ip:port` 内核：先无凭据探测 `/connection` 确认产品与协议，再整页跳转目标 origin；连接密钥不进入 URL 或浏览器持久存储。

## 九大导航区

| 导航 | 内容与操作 |
|---|---|
| 工作总览 | 指标卡（Features/Tasks/运行中/待确认/阻塞）、Feature 工作队列、当前流程阶段、新建 Feature（只保存需求、流程输入与执行配置，不启动） |
| 执行与交付 | 对尚未启动的 Feature 显式点击“启动 Feature”；工作流实例按阶段逐步操作：派发/接纳/批准/补充输入/重试/返工/核对；项目经理协作；调整运行计划；材料与上下文 |
| 角色讨论 | 与 Agent 会话、工具审批与澄清、结构化提案、经验与快照（见 [讨论与经验](conversations.md)） |
| 项目管理 | 项目列表与 GitHub 接入；基础 Standard、项目规范覆盖、来源差异预览和项目专属快照；Role→Agent、Sandbox 与可选 Profile、项目经理编排 Agent 与默认驱动；项目工具接入绑定。只保存配置，不启动经理会话或流程 |
| 流程与规范 | Workflow 编辑器、Delivery、Spec 与结构 lint、Standard 快照/比较/采用；配置依赖与精确修订选择 |
| 角色与代理 | Role 职责编辑；Capability（Model+Harness+Tools+Skills）；Agent（仅 Role+Capability 精确组合） |
| 基础组件 | Model、Harness、Sandbox、Permission、MCP、Skills、HTTP 工具、Harness 原生工具；Harness/Sandbox 按确切修订绑定权限，Permission 管理 Profile 与预设来源（见 [运行时权限](permissions.md)） |
| 历史记录 | 当前项目或 Global 的事件与工具调用统一时间线；审批/取消/核对入口；文件结果下载 |
| 设置 | 内核连接、数据路径、仓库接入状态、模板重置、运行时与凭据、全局并发、退出内核 |

页面路由写入 URL（tab/project/feature/子页/所选对象），重开时按当前可访问对象恢复。使用草稿持久化组件的编辑器将草稿保存在本机；这些草稿不等于已发布源修订，旧目录代次或失效引用仍需重新核对。连接密钥不进入 URL 或草稿存储。

各页面的单选下拉框和多选列表按最长选项确定宽度，并为文字、箭头和留白预留空间；宽度随当前选项列表更新，不随选中值缩短。相邻选择项横向排列，空间不足时自然换行，各字段名称在上、列表在下；窄屏下控件最大宽度受所在容器限制。

普通单行输入框按当前文字确定宽度，至少保留约 32 字符的空间，空间不足时受容器宽度限制；多行正文编辑保留完整编辑区域。Model 的模型标识、刷新目录和推理参数排列在同一行并自动换行。Delivery 将名称、范围和格式放在首行，内容规范、结构与来源分别分组展示。

## 刷新模型

配置类别和项目管理页面从 `query.ui_bootstrap` 挂载，Role 的项目选项读取 `query.project_directory`。目录查询复用服务端配置快照，切换类别不再等待完整 workspace 和工程历史恢复；具体执行、历史和已有 Feature 上下文仍使用完整查询。

事件流启用配置版本通知。配置页只在目录版本、项目或仓库状态变化时刷新轻量启动信息，普通会话/轮次事件不触发完整 workspace 刷新；会话自身继续按游标读取。SSE 按项目固定并使用持久化事件游标重连，切换类别不重复建立连接。后台刷新保留编辑草稿。

SSE `/events` 通知变化后全量刷新工作区快照；会话详情（1 秒）、编排面板（2.5 秒）、仓库接入与运行准备（1.5 秒）另有定向轮询。编排状态与配置选项分别读取；目录加载缓慢或失败时仍展示真实经理和调度状态，首次状态查询完成前显示读取提示，不推断为人工调度。写操作统一封装命令信封（command_id、目标、expected_revision 乐观锁），模板类定义写入另带目录代次校验。

## 典型旅程

1. **接入**：工作总览或项目管理页"打开 GitHub 项目"，填仓库与主分支；后台验证、克隆并准备 worktree，接入完成前阻止工程操作（项目管理页显示接入状态与核对入口）。
2. **配置**：项目管理页采用默认配置或选择基础 Standard，其声明决定默认启动入口。无覆盖时直接使用所选 Standard，有覆盖时预览实际引用变化后保存项目专属快照；移除全部覆盖恢复引用基础版本。覆盖编辑按规范类型（Workflow / Spec / Delivery）、具体规范项、替换版本三列排列，后两列按类型过滤，未选类型时没有内容选项。系统记录项目快照的基础来源、覆盖项和差异，已有 Feature 冻结版本保持不变。调度模式、Profile、编排角色和编排 Agent 横向排列，Role→Agent 绑定也横向排列并随宽度自动换行，各字段名称在上、下拉框在下。管理与编排仅允许项目经理角色；其他角色仍按 Workflow 步骤执行专业工作。保存配置不会启动会话或流程。
3. **执行**：工作总览的“新 Feature”只创建草稿并保存需求、流程输入与执行配置。在执行与交付页选择该 Feature，点击“启动 Feature”，才按保存的配置启动 Workflow：人工逐步派发/接纳，或由已选择的 Rust/Agent 驱动推进。经理协作面显示当前根驱动、真实会话和等待事项，可通过 CAS 切换当前根驱动；项目默认修改只影响未来工作。默认 Feature 的 PRD、Design、Tasks 在 Spec 验收后分别签署确切版本，再自动继续；其他 automatic 步骤无需逐项确认。澄清问题可在步骤或步骤会话中由用户回答。
4. **调整**：运行计划变化时在"调整当前运行计划"编辑变更（改任务/增删/绕过/豁免），先预演受影响范围再应用；Agent 提出的受保护流程变更须等人类批准确切请求，静止等待后原子切换。
5. **发布**：integration 阶段的候选、候选测试与接纳在页面逐步确认；发布报告与 PR 链接显示在产物与历史中。

## 基础组件中的权限配置

项目管理页的新配置默认选择 Agent 调度及“Harness 容器内全权限”Profile；点击“采用默认配置”也恢复这两项选择。已保存的显式调度模式和 Profile 在重新打开页面时保留。

Standard 页面将比较功能单独成行，标题、目标选择和比较按钮横向对齐，窄屏自动换行。“使用位置”标明当前查看的 Standard 名称与修订，查询对应这份规范。

基础组件按 Model → Harness → Sandbox → Permission → MCP → Skills → Tools → Harness 原生工具排列。Harness 与 Sandbox 的详情页为所选确切修订管理权限绑定、兼容性预检、构建/平台/安装信息、双层实际执行范围预览及绑定和权限来源历史。新修订不会继承其他目标修订的活动绑定；可通过修订选择器返回旧版本查看历史。

Permission 页面管理 Harness/Sandbox Profile 创建、修订、导入导出、预设来源和历史。权限类型、修订及新建按钮在同一工具行底部对齐；窄屏换行。目标默认绑定的预检与双层实际范围预览从 Profile 自动推导，不要求手填范围。保存或重载不会自动改绑已有目标。

## 设置页导览

- **仓库接入**：GitHub 仓库状态、未完成操作核对、worktree 列表。
- **模板**：目录指纹与重置预览/确认（自建定义退出当前目录，绑定与运行保留，见 [存储与数据布局](storage.md)）。
- **运行时与凭据**：默认 Harness 切换、Codex OAuth 登录、DSH 各服务商 key（写入系统凭据库）、共享安装列表（见 [模型接入](model-providers.md) 与 [系统凭据](system-credentials.md)）。
- **并发与退出**：全局并发额度（1–32）、项目编辑、退出内核（优雅停机）。

经理状态与资源目录分开加载，目录错误不会把活动 Agent 或 Rust 调度误显示为人工模式。大产物通过摘要和分块读取展示；任务预览只做配置解析，实际执行任务另含冻结输入及 core 提供的运行事实，预览不能证明已经执行。

## 无项目讨论与 Agent 经验

角色讨论允许当前上下文为空，并可选择原有项目实例；实例来源项目与当前活动项目分别显示。Agent 详情展示完整 Skills、Tools、Agent Spec 与通用经验入口。经验面板支持来源工作流过滤及“引用到当前讨论”，不要求先恢复成另一会话；讨论中可查看 Agent 实际读取的历史来源。


## 安装准备与讨论诊断

Harness 编辑版本、来源、许可证、入口、本机登录件和驱动扩展；Sandbox 编辑 Docker 基础镜像、系统依赖和后端文件。Workflow 编辑器内的调度配置随本次 Workflow 修订发布，不存在独立调度选择页。

设置中的 Codex 网页登录展示检查缓存、等待同版本锁、下载、校验解包、启动组件及请求授权地址等实际阶段和耗时；准备阶段可取消。取得官方地址立即打开授权页，工作区刷新随后进行。固定版本程序在用户级安装缓存复用，Docker 镜像独立校验复用，账户凭据不进入共享程序缓存。

角色讨论的一条回复持续更新；完整文本替换增量文本，不展示分片条数。正常完成和停止技术回执收起，需处理的错误、取消、未知结果、审批及澄清仍保留。回复上的“原始事件”在普通新浏览器标签页展示该 Turn 的最终消息、执行身份、停止证明与 JSON，刷新可重建，不逐条罗列增量分片。

工具调用与响应在讨论记录中仅展示工具类型（如 `webSearch`）及“原始事件”链接，不展开请求参数、输出、状态或错误正文。链接在新浏览器标签页读取对应的持久化事件，刷新可恢复；同一工具项合并更新后链接指向最新事件。
