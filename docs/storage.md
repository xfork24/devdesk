# 存储与数据布局

本文描述数据集结构、三库分工、幂等与恢复模型及升级策略。表结构清单见 [SQL 说明](../sql/README.md)，配置存储语义见 [源配置与执行解析](source-configuration.md)。

当前实施分支继续使用 SQLite、独立读快照及资源级乐观提交。业务准备和外部 I/O 不持有全局/项目写锁，显示和跨库目录允许最终一致。分支修改与验收状态见 [实施记录](plans/single-host-concurrency/EXECUTION.md)，容量目标见 [100 前端验收合同](plans/single-host-concurrency/ACCEPTANCE.md)。

## 数据集总览

`resource_versions` 保存有限资源和集合谓词的单调版本；`operations` 同一短事务保存命令指纹、结果、新版本集合及事件游标。所有业务写入口使用明确原读集合，不通过恢复、比较和保存整个项目提交。全状态保存只供 test-fixtures 离线夹具使用。数据库连接的短暂物理写竞争采用有界技术重试，不重新准备业务命令或重发副作用。

会话、Turn、原生 worker、交互、工具及 Controller 观察先保存原不可变报告，再核对原授权与版本。打开、派发、发送、停止、清理、Git 操作和回复分别持久化单次执行资格；重放只读原结果。未知副作用和停止结果保留待核对，不盲重发；显式恢复有独立来源，不能把旧回调改用新版本。完成快照与经验是独立派生阶段。

配置的唯一存储为不可变 `source_definitions`；配置校验可以读取完整配置目录，不恢复运行历史。集合谓词及步骤/流程头授权令牌由事实写入的 SQL 触发器原子维护，防止并发插入与身份复用绕过原判断。运行材料、任务、模型/平台观察及人类决定保持独立。

Workflow 步骤使用独立原生版本，定点 SQL 替换 steps 数组中的原执行，保留并发兄弟步骤；流程头更新不覆盖 steps。权威事实仍为 workflow_instance，步骤版本触发器将新旧数组各物化一次，再按执行身份连接，避免每次更新对数组作平方级扫描；同一实例的批量精确步骤读取也只扫描一次数组，保留请求顺序、重复键、缺失及删除后的版本。物理大 JSON 的写放大仍需容量验收。`workflow_display_headers` 与 `workflow_display_steps` 只保存小型状态/引用元数据，减少状态轮询对输入及产物正文的读取；条件提示附原资源见证，失效时显示待汇总，控制命令重新检查权威事实。

仓库连接、工作副本准备与主干刷新使用持久意图、原 Git 物理身份、不可变观察和原业务版本接纳。原结果未知时不重做 clone/worktree/CAS。平台只发布候选并创建 PR，后续只读核对，不执行远端合并。Git 不使用全局业务锁。

项目库在创建前由全局目录预留身份，原子创建 Project/Context/来源。冷启动以每个服务实例的 OnceLock 去重，不串行业务写入。项目目录后台按权威修订单调投影，普通读取不发布目录或同步配置。后台项目和阶段轮转，有界并行长阶段；结构锁不覆盖 SQL 或外部操作。

本分支初始化基线 global 24 / project 60 另要求 `dataset_layout` 合同 `single-host-resource-v2`。旧布局在 WAL/初始化写入前拒绝；不自动迁移、删除或重建。当前代码与基线的验收结论见实施记录，不能据初始化成功宣称 100 前端容量通过。

一个数据集目录（`--data`）以 `.devdesk-dataset` 标记（内容 `devdesk-profile-runtime-v2`）并施加独占写锁（`.devdesk.lock`）；同一数据集同时只能有一个可写进程。

```text
<data>/
├── global.sqlite3                      # 全局配置库（并发、共享定义、项目目录、运行时安装、权限预设）
├── conversations/global/engineering.sqlite3   # 全局讨论独立库（固定命名空间，不创建项目）
├── projects/<project-id>/
│   ├── engineering.sqlite3             # 该项目的工程数据、事件与幂等记录
│   ├── artifacts/                      # 该项目的封存产物（SHA-256、fsync、拒 symlink）
│   ├── execution/                      # 会话、测试、工具、Git 意图及 worktrees/ 工作副本
│   └── repository/                     # 受管理的 GitHub 仓库克隆
├── runtimes/                           # 共享运行组件与构建工作目录
├── packaged-permission-presets/        # 内嵌权限预设的内容寻址缓存
└── credentials/                        # Codex OAuth 本机凭据文件（数据集作用域）
```

## 三库分工

- **全局配置库**：共享源配置、项目索引、全局并发额度、运行时安装、准备/验证记录和权限预设来源；不保存项目工程执行数据。经验目录从各库只读汇总，不保存第二份工程事实。
- **每项目工程库**：该项目的全部工程事实。显式 `project_id` 把每个请求钉到一个 Engine/一个数据库；Host 不保存活动项目，也不按其他前端的选择回退。历史记录与工具调用按"当前项目 / Global"两个范围读取，互不泄漏。
- **全局讨论库**：scope=global 的会话单独存储，不创建占位项目。

## 配置的唯一存储

配置只存于 `source_definitions` 表（两库同构）：主键 `(identity, revision)`，`reference` 为 `identity:revision` 虚拟唯一列，触发器禁止 UPDATE/DELETE。没有 definitions/harnesses/sandboxes 等投影表：执行视图（任务、运行时、权限、工具）在加载时由同一解析器按需重建；持久化编码把内嵌配置对象压缩为 `$source` 引用，读取时从原源闭包还原，缺失或内容冲突直接报错。SQLite 基线为 global 24 / project 60。

经验的权威快照和完整历史保存在原项目或全局讨论库。后台轮转每次最多读取 16 条经验版本头，仅在来源版本推进时读取白名单元数据并乐观发布全局 `experience_directory`；来源命名空间、身份、版本和摘要共同绑定投影，旧观察不能覆盖新版本。每条派生元数据最多 64 KiB，历史节选最多 20 条并保存精确总数；不复制快照正文、路径、凭据或展开权限。来源可读时查询原权威记录，来源不可用时界面明确显示缓存历史摘要。投影不参与执行授权，也不使用全局业务写锁。预算在记录之间检查，单条既有 JSON 历史的 SQL 解析仍随其原始大小增长。

配置目录另有可丢弃的进程内快照，不新增展开配置投影。`catalog_clock` 只保存目录快照时钟，由源、目录治理、Project 和 mainline 工作副本的 SQL 触发器在同一事务中推进；它只用于读取新鲜度，不是项目写入乐观锁。读取在同一 SQLite 快照内取得时钟与目录事实，热读返回该版本的不可变 Arc，不跨连接比较 `PRAGMA data_version`。慢读取不能以新版本标记旧数据或覆盖更高版本的缓存。

共享目录与项目目录的只读组合最多保留 8 个视图；底层缓存按估算字节计账，单项 32 MiB、进程合计 128 MiB，预算随旧 Arc 的最后一个读者释放，过大或预算不足时读取但不保留。跨项目只读目录最多复用 8 个读池，各有最多 4 个读连接；初始化、临时只读连接和各池共享进程 64 个连接的预算，先取得额度再打开 SQLite，SQL 不持有池的互斥锁。
同一快照还保存模板成员、head、来源和停用索引，以及最多 16 项纯查询结果；查询结果按序列化大小的两倍计账，单快照 4 MiB、进程合计 32 MiB，超额逐出或不保留。成功结果才缓存，编译期间不持有 memo 锁。运行记录的冻结计划恢复复用同一目录快照和确切源选择描述符下的纯计划投影，共用上述条目和字节预算；执行状态、输入产物、回执及后端权限落实不缓存。键包含方法、完整参数和快照全部配置输入；权限矩阵额外包含运行程序登记及后端资产摘要。重启与源提交重建视图，命令与执行不使用展示结果替代权威校验。

完整 control/inspect 投影在一次同步建议性查询内复用有限资源行，当前页步骤批量读取，避免逐项重新扫描同一 steps JSON。作用域按连接池身份及线程隔离，最多 256 项、估算 1 MiB，进程合计 16 MiB，最多八层嵌套；查询结束或异常立即释放，不持有连接/事务。专门的 authority 资源不在复用白名单中，查询中的治理行只用于建议性投影；命令不进入此作用域，提交前清除本线程同池残留，再按原读集合执行权威 OCC。它不构成跨请求的运行状态缓存或一致快照承诺。

浏览器配置查询只在内存保留，最多 64 项、估算 8 MiB；模型目录单独限制 16 项、估算 1 MiB。缓存按连接/数据路径、Host、全局及项目提交序列、项目来源摘要与参数隔离。相同进行中请求合并，普通读取在最后一个消费者离开后取消传输；HTTP 服务可跳过已取消的排队读取，已开始的同步工作仍可能完成。模型发现归有界后台服务管理，页面离开后仍可完成，切回继续复用；更换身份或主动失效会清空它。没有新增持久化目录、配置格式或迁移。

SSE 按事件主键和游标读取 `events`，提交后通知唤醒读取，低频补查处理丢失通知；不为事件轮询重建完整状态。全局讨论的 Agent 目录读取配置快照，经验列表按 Agent 查询既有经验记录和快照文本摘要，具体快照详情继续核对封存清单与摘要。

## 事实表族（速览）

| 表族 | 内容 |
|---|---|
| source_definitions | 不可变配置源修订及根级引用；执行视图按原引用恢复 |
| events / governance_records | 项目事件日志；Controller、驱动、计划采用、变更、决定、工具意图与回执、模板目录状态 |
| operations | 幂等操作记录：相同 command_id + 参数指纹重放首次结果 |
| sessions / turns / conversation_events / interactions / proposals | 会话域：绑定、轮次（单活跃约束）、append-only 事件、人工交互、讨论提案 |
| executions | 真实执行事实（容器、镜像摘要、writer 撤销、冻结权限） |
| features / tasks / documents / contexts / snapshots / artifacts | 工程对象与材料 |
| repository_operations / repository_worktrees | Git 动作-回执与工作副本登记 |
| orchestration_wakeups / orchestration_leases | 编排唤醒队列与单写者租约 |

完整表清单见 [SQL 说明](../sql/README.md)。

源描述的文件/SQL 编解码在 adapters；冻结计划与任务选择的纯重建在 core/frozen_views。两者共享精确源引用，不以当前目录最新版重选执行依赖。`command_context` 保留由可信入口构造的 Actor/项目归属与原请求指纹，不接受客户端提供的解析后身份。

工作台、经理与驱动的显示摘要通过项目只读连接直接查询原生元数据，并使用 controller 归属、根实例、调用归属、活动根与待决定项索引；不新增展开配置表。消息、调用、待决定项和等待条件都有限额，完整决定请求另按需读取。`query.workspace` 不再附加全局/项目全量模板快照；其项目配置状态表示已保存且在发布时校验的确切选择，当前目录的完整诊断通过显式配置读取提供。workflow_pending_decision / workflow_human_decision 的 request 原样保存为输入事实，不将其中用户提供的 `$source` 或保留文本解释为配置引用；全量恢复与精确详情读取遵守同一事实边界。该输入事实编解码与当前项目基线一致，不转换旧记录。

项目库的 governance_records.owner_project 是从 Scope 计算的虚拟列，统一提取 project/feature 的所属项目，供运行摘要与子流程分页索引使用；global 归属为空，不进入项目运行摘要。它不保存第二份可编辑配置。事实表通用读写明确列出物理列，避免虚拟列改变 SELECT * 的列序后误解码；虚拟归属列不参与事实写入。当前使用 project 60，project 59 及更旧基线拒绝打开。经验目录的分页使用 owner_project/id/revision 索引，游标读取不会扫描或排序整个历史。全局库启动先只读核对已登记项目及全局讨论数据库的基线，再执行初始化与恢复；不兼容数据在全局业务写入前拒绝。

## 幂等与恢复模型

所有外部调用遵循三段式：**持久化意图 → 事务外执行 → 核对回执并接纳**。命令以 command_id + 参数指纹幂等；相同 ID 不同参数被拒绝；重放先于版本冲突检查。

崩溃恢复（bootstrap）把未知终态打回 NeedsReconciliation：已派发的工具调用、仓库操作、活动轮次均进入待核对；**未知结果绝不盲目重发**，重试必须先核对远端事实（`tool.call.reconcile` / `repository.reconcile` / `workflow.step.reconcile`）。取消必须取得真实执行者的停止与写撤销证明；日志导出失败时仍保留停止证明和容器，通过持久清理任务只读恢复协议日志，导出完成前不清理容器或把日志失败误当作未知模型执行；Git 操作另有落盘意图文件，丢失数据库回执后仍可按操作 ID 核对。

外部工具调用的派发、停止意图、回执、原生回复及人类控制使用调用资源的原版本提交。仅首次提交的不可变 `tool_dispatch` 授予一次执行资格；停止及原生回复各有独立持久意图。外部结果先保存 `tool_observation`，再按原调用版本接纳；与取消或人工核对冲突时保留原观察，不覆盖较新状态。未知原生回复不自动重发。工作流外部工具创建原子保护原意图、不可变派发/决定、原步骤及祖先的原生版本和精确源；实际 Actor 来自原决定。准备句柄不能跨命名空间或替换原请求，暂停保留待执行意图，完成重放不恢复完整工程历史。原生会话调用、Controller、Driver 与 Segment 使用各自原资源读集合提交。普通派发扫描按活动调用索引每页最多 16 条，在调用之间检查 25 ms 预算，不恢复整库历史；实际外部 I/O 的耗时不能被此预算抢占。原 worker 撤销后不能恢复该执行身份，执行行不可删除复用，避免活动条件发生 ABA。

人工测试调用的创建也使用有限资源提交：调用与来源不存在条件、确切不可变源和完整配置校验所依赖的只读 catalog_clock 一起保护；该时钟只读，不因创建调用而推进，不把独立调用串成共同写资源。运行记录及原回执采用同一源编码，权限和绑定不得用展开副本持久化。

工作流意图回调采用原意图版本、不可变观察与原命令回执的有限提交。回调结果摘要只保存原结果身份，完整结果仍由原操作回执持有。控制器接管以原 Controller/驱动代次及实际 worker 事实准备撤销意图；与回调竞争时按原读集合返回冲突。业务入口不再使用原全局或项目写锁。

待执行工作流意图使用 id 的 prepared 条件索引，每页最多 16 条候选，游标经过暂停或失效项后继续轮转。创建时保存有限的原步骤/祖先身份和 owner，扫描及运行前按原生已提交事实校验；不恢复完整工程状态。冻结任务解码显式接收原实例、计划、所需历史执行及匹配 Turn 的正文/封存；源编译时不占 SQL 连接。完整配置目录只用于源重建，不给旧业务规则构造缺少其他事实的工程状态。工作流评估与执行准备读取实际资源事实并按步骤提交，不构造缺少业务事实的 EngineeringState。

工具发现目录按绑定读取索引中的最新不可变目录版本；外部调用前捕获原版本和原目录身份。回调先持久化原始观察，再同事务校验原头并创建新目录、更新原意图；冲突不覆盖已接纳目录，也不丢弃供应商原结果。差异计算只读取原目录，不恢复工程历史；相同回调不新增目录或事件。工具源发布另按原目录、源 head、引用谓词及命令身份原子提交。

原生工具派发同时校验原 Session/Turn/worker；工作流工具保存原步骤、计划、输入/合同摘要和祖先执行链，派发前按同一读快照重新核对这些确切身份与各工作流原生版本。暂停保留调用等待，执行替换或撤销后在外部 I/O 前停止；该本地停止有独立依据，不伪造供应商回执。原生会话调用创建、工具源发布、配置及运行族使用资源提交；不再以旧业务 writer 或全状态事务兜底。

资源提交将连接池排队与 SQLite 锁等待分开计时：提交 checkout 共用 2 秒期限，物理锁每次最多等待 25 ms，至多 16 次技术尝试、约 500 ms 技术预算，且每次尝试使用原读集合。锁等待采用有界细粒度轮询，避免连续短 WAL 事务下默认毫秒退避反复错过空隙；不降低同步持久性、不增加业务写锁或单写队列。resource.submit_pool_wait 与 resource.sql_transaction 分别记录排队和事务时间。

启用性能 Trace 时另保留逐次事务尝试：连接取得、BEGIN 返回、COMMIT 调用/返回或明确回滚，按数据库路径、命令和资源键的 SHA-256、资源版本及事件游标关联。每个 Trace 最多 64 项、每项最多 16 个资源身份，超额计入 transactions_omitted；错误、重放、BEGIN/COMMIT 失败分别记录。重放没有新的 COMMIT 完成点，回滚失败不记为成功。计时使用本进程单调区间，UTC 仅作关联；不记录正文、参数或原路径。既有 Event.time/提交 prepared.time 仍是 COMMIT 前字段，尚无精确 SSE/页面渲染关联。

## 模板目录与默认配置

默认配置以 `resources/configuration/manifest.json` 发布（bundle 版本），空库初始化生成数据库副本；UI 编辑写入数据库修订或草稿，应用升级不改写已有目录。模板目录使用**代次（generation）**机制：重置只把当前目录选择切到默认代次，从不改变源身份；自建定义与草稿退出当前目录（归档可查），旧项目绑定、冻结运行与凭据保留。相关命令见 [本地协议](protocol.md) 的模板目录一节。

## 升级策略

系统只支持当前协议与当前 SQLite 基线（见 [SQL 说明](../sql/README.md)）：旧结构明确拒绝，不自动删除、不转换、不保留双版本执行器。升级前备份整个数据集目录；验证新版本使用独立空目录，不用既有数据目录试验。凭据引用绑定数据集与服务商，换机器后需重新配置本机凭据。

## 配置发布恢复

`configuration_transfer` 保存跨库候选及 prepared/applying/completed/failed/cancelled 状态；暂存正文不是 source_definitions 中的可用源。项目原子提交源副本、选择和 configuration_transfer_receipt；共享库随后发布相同源并标记完成。重启从 applying 与项目幂等回执继续，不重复创建选择。相同源引用的内容必须一致。

## 证据归档

`tests/live/export_evidence.py` 使用 SQLite backup 生成一致快照，关闭快照后计算摘要，按项目登记核验 Artifact 的路径与实际内容，再生成逐文件 SHA-256 清单。记录投影遮蔽已知凭据字段；全局认证文件、进程环境和私有 worker 状态不导出。归档保留实际失败、未运行项、执行安装及原始来源，不用模型摘要替代证据。

实现依据：[全局 SQL](../sql/global/schema.sql)、[项目 SQL](../sql/project/schema.sql)、[数据集与项目库](../crates/adapters/src/lib.rs)、[Git 目录](../crates/adapters/src/git.rs)、[证据导出](../tests/live/export_evidence.py)。

调度器的待办、运行模式和活跃对话数通过单个已提交读快照直接查询，运行数按非 queued/终态 Turn 且存在未撤销 writer 计算；同一会话有多个执行记录时仍只计该 Turn 一次。项目库增加活跃 Turn、未撤销 writer、工作根归属和调用成员索引，不增加展开配置副本。查询结果为调度提示，派发仍须通过原领域授权和执行围栏。

Host 按项目和就绪阶段轮转，后台最多 8 个阶段工作线程，以短结构锁去重任务；外部调用不阻塞 HTTP 读写。各阶段在记录之间检查 25 ms 预算，并至少访问首个候选；回调分页只前移一个候选，避免预算截断后永久跳过同页后续资源。Rust 驱动先用原流程头过滤已结束和依赖未就绪的步骤，再读取权威就绪事实及执行原版本提交。目录同步独立轮转，并按开始时捕获的共享/项目时钟复用完成结果；普通材料编辑不重新同步整个目录。所有项目的活跃 writer 和已预留启动额度共同参与全局预算。

材料、提案、输入前快照的封存路径使用资源提交：持久意图保存有限变化及原读集合，文件身份、归属、长度和 SHA-256 在 I/O 前固定。文件发布使用不覆盖既有身份的原子链接；恢复只核对原文件，不替换内容。文件观察与业务接纳分离，最终仍验证原版本；业务冲突后的文件和原始观察保留。手工背景的修订事件与 Context 变化在同一提交中追加。本分支的验证结果及未完成的正式容量验收见实施记录。
