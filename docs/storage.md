# 存储与数据布局

本文描述数据集结构、三库分工、幂等与恢复模型及升级策略。表结构清单见 [SQL 说明](../sql/README.md)，配置存储语义见 [源配置与执行解析](source-configuration.md)。

已确认的并发重构继续使用 SQLite：独立读快照、资源级版本比较与短事务提交、无应用层全局/项目串行写锁，视图允许最终一致。实施分支已接入读连接池与有限资源提交，共享项目选择已移除，旧业务写锁尚未替换；本文以下描述现行业务路径，目标结构见 [底层重构方案](plans/single-host-concurrency/PLAN.md)，容量门禁见 [100 前端验收合同](plans/single-host-concurrency/ACCEPTANCE.md)。

## 数据集总览

`resource_versions` 为有限资源提交保存 `(kind, resource_id, revision)`；`operations` 同事务保存结果、新版本集合和事件游标。旧业务写路径仍在迁移，不能将新端口测试视作所有入口已具备并发保护。

项目库为集合谓词维护只读的 `collection` 版本：`repository:<project>` 随仓库操作、工作副本、代码头及项目 Git 调用变化推进，`features:<project>` 只随 Feature 成员归属变化推进。SQL 触发器与事实变更同事务更新；上下文在同一读快照中读取事实和版本，提交校验可拒绝并发插入、删除及删除后重建造成的旧判断。它们不取得业务锁，也不把无关 Feature 标题编辑变成项目级冲突。仓库登记/同步的类型化准备上下文已使用这些版本，公共分派与回调尚未共同切换。

Harness 物化回执按固定源修订、配方及平台身份创建，使用不存在前置条件与稳定内部提交身份原子保存不可变记录；同身份不同安装拒绝覆盖。执行启动读取配置快照和确切回执，不为这条记录恢复工程历史或取得旧业务 writer。外部安装准备及其公开 RPC 的意图/控制版本仍在迁移。

内部提交端口另返回本次是否实际提交，公共幂等回执内容保持原值。仓库派发协议以此区分新准入与重放，准备不可变 `repository_dispatch`；外部观察独立保存为 `repository_observation`，迟到结果不直接改写当前操作。观察恢复重新核对原意图和调用来源，不授予新的执行资格。这套仓库协议目前只用于准备端口和隔离测试，尚未替换生产调度的权威投影与恢复路径。

仓库登记的有限接纳端口已实现单库原子更新操作、Project 工作区、主干头、工作副本及不可变接纳记录。意图和派发保存各自仓库活动版本，外部调用期间发生的活动不能因当前已结束而被忽略；Project 名称和额度等独立字段按当前快照保留，工作区摘要必须匹配原意图。未知外部结果只标记原操作待核对，不发布工作副本。此端口同样尚未接入生产调度，共同约束的其他写入仍待迁移。

已预留项目库中的 project.create 元数据提交已接入资源端口，原子创建 Project、初始 Context 和不可变调用来源，三个目标都验证不存在。重放不再恢复工程状态；目录身份预留与数据库初始化仍由 Host 协调，相关旧锁和未指定项目库的旧兼容路径尚未撤销。

项目目录发布按权威 Project 修订单调推进，相同版本且内容相同只读返回，不更新数据库或重复通知；相同版本不同内容拒绝。旧 query.workspace 已不再发布目录，也不为补充当前项目元数据再次恢复完整状态。后台独立轮转修复空闲项目目录，每轮最多 8 项、项目间检查 25 ms 预算，工作阶段后也尝试发布原生项目元数据。跨库摘要仍允许最终一致，调度和全部旧查询的重构尚未完成。

安装登记使用确定的 runtime_installation 资源身份及独立的内容封存设置；内容封存绑定版本/平台/配方与可执行文件摘要或不可变镜像身份，不绑定安装路径。安装行缺失不重置资源版本；内部恢复用原封存和当前不存在谓词保护，公共登记仍只接受版本 0。安装表对 recipe_digest 的 NULL 情况也执行唯一约束，防止同一程序/平台被重复登记。当前使用 global 22，global 21 及更旧基线拒绝打开，不自动转换。

事件写入只追加：旧业务路径也由 SQLite 在提交时分配持久化 ID，不再 upsert 内存中暂定的事件 ID。这样设置/安装的独立资源提交与旧路径交错时不会覆盖事件。内存事件提示不构成已提交游标，有限提交的权威定位来自回执；尚未迁移的业务对象仍保留旧保护。

一个数据集目录（`--data`）以 `.devdesk-dataset` 标记（内容 `devdesk-profile-runtime-v2`）并施加独占写锁（`.devdesk.lock`）；同一数据集同时只能有一个可写进程。

```text
<data>/
├── global.sqlite3                      # 全局配置库（并发、共享定义、项目目录、运行时安装、权限预设）
├── conversations/global/engineering.sqlite3   # 全局讨论独立库（固定命名空间，不创建项目）
├── projects/<project-id>/
│   ├── engineering.sqlite3             # 该项目的工程数据、事件与幂等记录
│   ├── artifacts/                      # 该项目的封存产物（SHA-256、fsync、拒 symlink）
│   ├── execution/                      # 会话、测试、工具、Git 意图及 worktrees/ 工作副本
│   └── repository/                     # 受管理的 GitHub 仓库克隆
├── runtimes/                           # 共享运行组件与构建工作目录
├── packaged-permission-presets/        # 内嵌权限预设的内容寻址缓存
└── credentials/                        # Codex OAuth 本机凭据文件（数据集作用域）
```

## 三库分工

- **全局配置库**：共享源配置、项目索引、全局并发额度、运行时安装、准备/验证记录和权限预设来源；不保存项目工程执行数据。经验目录从各库只读汇总，不保存第二份工程事实。
- **每项目工程库**：该项目的全部工程事实。显式 `project_id` 把每个请求钉到一个 Engine/一个数据库；Host 不保存活动项目，也不按其他前端的选择回退。历史记录与工具调用按"当前项目 / Global"两个范围读取，互不泄漏。
- **全局讨论库**：scope=global 的会话单独存储，不创建占位项目。

## 配置的唯一存储

配置只存于 `source_definitions` 表（两库同构）：主键 `(identity, revision)`，`reference` 为 `identity:revision` 虚拟唯一列，触发器禁止 UPDATE/DELETE。没有 definitions/harnesses/sandboxes 等投影表：执行视图（任务、运行时、权限、工具）在加载时由同一解析器按需重建；持久化编码把内嵌配置对象压缩为 `$source` 引用，读取时从原源闭包还原，缺失或内容冲突直接报错。SQLite 基线为 global 22 / project 56。

经验的权威快照和完整历史保存在原项目或全局讨论库。后台轮转每次最多读取 16 条经验版本头，仅在来源版本推进时读取白名单元数据并乐观发布全局 `experience_directory`；来源命名空间、身份、版本和摘要共同绑定投影，旧观察不能覆盖新版本。每条派生元数据最多 64 KiB，历史节选最多 20 条并保存精确总数；不复制快照正文、路径、凭据或展开权限。来源可读时查询原权威记录，来源不可用时界面明确显示缓存历史摘要。投影不参与执行授权，也不使用全局业务写锁。预算在记录之间检查，单条既有 JSON 历史的 SQL 解析仍随其原始大小增长。

配置目录另有可丢弃的进程内快照，不新增展开配置投影。`catalog_clock` 只保存目录快照时钟，由源、目录治理、Project 和 mainline 工作副本的 SQL 触发器在同一事务中推进；它只用于读取新鲜度，不是项目写入乐观锁。读取在同一 SQLite 快照内取得时钟与目录事实，热读返回该版本的不可变 Arc，不跨连接比较 `PRAGMA data_version`。慢读取不能以新版本标记旧数据或覆盖更高版本的缓存。

共享目录与项目目录的只读组合最多保留 8 个视图；底层缓存按估算字节计账，单项 32 MiB、进程合计 128 MiB，预算随旧 Arc 的最后一个读者释放，过大或预算不足时读取但不保留。跨项目只读目录最多复用 8 个读池，各有最多 4 个读连接；初始化、临时只读连接和各池共享进程 64 个连接的预算，先取得额度再打开 SQLite，SQL 不持有池的互斥锁。
同一快照还保存模板成员、head、来源和停用索引，以及最多 16 项纯查询结果；查询结果按序列化大小的两倍计账，单快照 4 MiB、进程合计 32 MiB，超额逐出或不保留。成功结果才缓存，编译期间不持有 memo 锁。键包含方法、完整参数和快照全部配置输入；权限矩阵额外包含运行程序登记及后端资产摘要。重启与源提交重建视图，命令与执行不使用展示结果替代权威校验。

浏览器配置查询只在内存保留，最多 64 项、估算 8 MiB；模型目录单独限制 16 项、估算 1 MiB。缓存按连接/数据路径、Host、全局及项目提交序列、项目来源摘要与参数隔离。相同进行中请求合并，普通读取在最后一个消费者离开后取消传输；HTTP 服务可跳过已取消的排队读取，已开始的同步工作仍可能完成。模型发现归有界后台服务管理，页面离开后仍可完成，切回继续复用；更换身份或主动失效会清空它。没有新增持久化目录、配置格式或迁移。

SSE 按事件主键和游标读取 `events`，提交后通知唤醒读取，低频补查处理丢失通知；不为事件轮询重建完整状态。全局讨论的 Agent 目录读取配置快照，经验列表按 Agent 查询既有经验记录和快照文本摘要，具体快照详情继续核对封存清单与摘要。

## 事实表族（速览）

| 表族 | 内容 |
|---|---|
| source_definitions | 不可变配置源修订及根级引用；执行视图按原引用恢复 |
| events / governance_records | 项目事件日志；Controller、驱动、计划采用、变更、决定、工具意图与回执、模板目录状态 |
| operations | 幂等操作记录：相同 command_id + 参数指纹重放首次结果 |
| sessions / turns / conversation_events / interactions / proposals | 会话域：绑定、轮次（单活跃约束）、append-only 事件、人工交互、讨论提案 |
| executions | 真实执行事实（容器、镜像摘要、writer 撤销、冻结权限） |
| features / tasks / documents / contexts / snapshots / artifacts | 工程对象与材料 |
| repository_operations / repository_worktrees | Git 动作-回执与工作副本登记 |
| orchestration_wakeups / orchestration_leases | 编排唤醒队列与单写者租约 |

完整表清单见 [SQL 说明](../sql/README.md)。

源描述的文件/SQL 编解码在 adapters；冻结计划与任务选择的纯重建在 core/frozen_views。两者共享精确源引用，不以当前目录最新版重选执行依赖。`command_context` 保留由可信入口构造的 Actor/项目归属与原请求指纹，不接受客户端提供的解析后身份。

经理与驱动的显示摘要通过项目只读连接直接查询原生元数据，并使用 controller 归属、根实例、调用归属、活动根与待决定项索引；不新增展开配置表。消息、调用、待决定项和等待条件都有限额，完整决定请求另按需读取。workflow_pending_decision / workflow_human_decision 的 request 原样保存为输入事实，不将其中用户提供的 `$source` 或保留文本解释为配置引用；全量恢复与精确详情读取遵守同一事实边界。该输入事实编解码与当前项目基线一致，不转换旧记录。

项目库的 governance_records.owner_project 是从 Scope 计算的虚拟列，统一提取 project/feature 的所属项目，供运行摘要与子流程分页索引使用；global 归属为空，不进入项目运行摘要。它不保存第二份可编辑配置。事实表通用读写明确列出物理列，避免虚拟列改变 SELECT * 的列序后误解码；虚拟归属列不参与事实写入。当前使用 project 56，project 55 及更旧基线拒绝打开。经验目录的分页使用 owner_project/id/revision 索引，游标读取不会扫描或排序整个历史。全局库启动先只读核对已登记项目及全局讨论数据库的基线，再执行初始化与恢复；不兼容数据在全局业务写入前拒绝。

## 幂等与恢复模型

所有外部调用遵循三段式：**持久化意图 → 事务外执行 → 核对回执并接纳**。命令以 command_id + 参数指纹幂等；相同 ID 不同参数被拒绝；重放先于版本冲突检查。

崩溃恢复（bootstrap）把未知终态打回 NeedsReconciliation：已派发的工具调用、仓库操作、活动轮次均进入待核对；**未知结果绝不盲目重发**，重试必须先核对远端事实（`tool.call.reconcile` / `repository.reconcile` / `workflow.step.reconcile`）。取消必须取得真实执行者的停止与写撤销证明；Git 操作另有落盘意图文件，丢失数据库回执后仍可按操作 ID 核对。

外部工具调用的派发、停止意图、回执、原生回复及人类控制使用调用资源的原版本提交。仅首次提交的不可变 `tool_dispatch` 授予一次执行资格；停止及原生回复各有独立持久意图。外部结果先保存 `tool_observation`，再按原调用版本接纳；与取消或人工核对冲突时保留原观察，不覆盖较新状态。未知原生回复不自动重发。工作流外部工具创建原子保护原意图、不可变派发/决定、原步骤及祖先的原生版本和精确源；实际 Actor 来自原决定。准备句柄不能跨命名空间或替换原请求，暂停保留待执行意图，完成重放不恢复完整工程历史。原生会话调用创建和通用工作流回调尚未全部迁移。普通派发扫描按活动调用索引每页最多 16 条，在调用之间检查 25 ms 预算，不恢复整库历史；实际外部 I/O 的耗时不能被此预算抢占。原 worker 撤销后不能恢复该执行身份，执行行不可删除复用，避免活动条件发生 ABA。

人工测试调用的创建也使用有限资源提交：调用与来源不存在条件、确切不可变源和完整配置校验所依赖的只读 catalog_clock 一起保护；该时钟只读，不因创建调用而推进，不把独立调用串成共同写资源。运行记录及原回执采用同一源编码，权限和绑定不得用展开副本持久化。

工具发现目录按绑定读取索引中的最新不可变目录版本；外部调用前捕获原版本和原目录身份。回调先持久化原始观察，再同事务校验原头并创建新目录、更新原意图；冲突不覆盖已接纳目录，也不丢弃供应商原结果。差异计算只读取原目录，不恢复工程历史；相同回调不新增目录或事件。该路径不使用旧业务 writer，源定义发布仍待迁移。

原生工具派发同时校验原 Session/Turn/worker；工作流工具保存原步骤、计划、输入/合同摘要和祖先执行链，派发前按同一读快照重新核对这些确切身份与各工作流原生版本。暂停保留调用等待，执行替换或撤销后在外部 I/O 前停止；该本地停止有独立依据，不伪造供应商回执。原生会话创建调用、工具源发布、配置与其他运行族仍有待迁移的旧写路径，不能把此处视为全部业务锁已移除。

资源提交将连接池排队与 SQLite 锁等待分开计时：提交 checkout 共用 2 秒期限，物理锁每次最多等待 25 ms，至多 3 次技术尝试、约 100 ms 技术预算，且每次尝试使用原读集合。锁等待采用有界细粒度轮询，避免连续短 WAL 事务下默认毫秒退避反复错过空隙；不降低同步持久性、不增加业务写锁或单写队列。resource.submit_pool_wait 与 resource.sql_transaction 分别记录排队和事务时间。

## 模板目录与默认配置

默认配置以 `resources/configuration/manifest.json` 发布（bundle 版本），空库初始化生成数据库副本；UI 编辑写入数据库修订或草稿，应用升级不改写已有目录。模板目录使用**代次（generation）**机制：重置只把当前目录选择切到默认代次，从不改变源身份；自建定义与草稿退出当前目录（归档可查），旧项目绑定、冻结运行与凭据保留。相关命令见 [本地协议](protocol.md) 的模板目录一节。

## 升级策略

系统只支持当前协议与当前 SQLite 基线（见 [SQL 说明](../sql/README.md)）：旧结构明确拒绝，不自动删除、不转换、不保留双版本执行器。升级前备份整个数据集目录；验证新版本使用独立空目录，不用既有数据目录试验。凭据引用绑定数据集与服务商，换机器后需重新配置本机凭据。

## 配置发布恢复

`configuration_transfer` 保存跨库候选及 prepared/applying/completed/failed/cancelled 状态；暂存正文不是 source_definitions 中的可用源。项目原子提交源副本、选择和 configuration_transfer_receipt；共享库随后发布相同源并标记完成。重启从 applying 与项目幂等回执继续，不重复创建选择。相同源引用的内容必须一致。

## 证据归档

`tests/live/export_evidence.py` 使用 SQLite backup 生成一致快照，关闭快照后计算摘要，按项目登记核验 Artifact 的路径与实际内容，再生成逐文件 SHA-256 清单。记录投影遮蔽已知凭据字段；全局认证文件、进程环境和私有 worker 状态不导出。归档保留实际失败、未运行项、执行安装及原始来源，不用模型摘要替代证据。

实现依据：[全局 SQL](../sql/global/schema.sql)、[项目 SQL](../sql/project/schema.sql)、[数据集与项目库](../crates/adapters/src/lib.rs)、[Git 目录](../crates/adapters/src/git.rs)、[证据导出](../tests/live/export_evidence.py)。

调度器的待办、运行模式和活跃对话数通过单个已提交读快照直接查询，运行数按非 queued/终态 Turn 且存在未撤销 writer 计算；同一会话有多个执行记录时仍只计该 Turn 一次。项目库增加活跃 Turn、未撤销 writer、工作根归属和调用成员索引，不增加展开配置副本。查询结果为调度提示，派发仍须通过原领域授权和执行围栏。

Host 以轮转顺序访问待办项目，一轮最多 8 个项目，在项目阶段间检查 250 ms 预算；已开始的项目阶段完成后再让出，不能抢占某个外部端口调用。未选中项目的活跃 writer 仍计入全局额度。后续业务提交和回调迁移仍是移除旧写锁及缩短单个阶段的必要工作。
