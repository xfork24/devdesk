# DevDesk 领域与工程接入基础补强计划

日期：2026-11-08。状态：H1–H4 已完成并验收。执行基线：[架构设计 v0.2](devdesk-v0.2.md) 的领域语义及 [原型实施计划](devdesk-prototype.md) 第14节的范围决策。

## 目标与边界

保留单机 Rust domain/core/adapters/host + 完整 Web 架构，将原型补强为可继续实施真实工程适配器的基础。工程库和 Artifact 真实持久化；本轮不连接用户 GitHub、不启动 Docker、不调用真实模型，不开放未经真实用例验收的 live 模式。Archive/迁移执行仍延期，但应明确领域契约。不可用空接口数量或测试通过数代替领域完整性。

## H1 已复现缺陷与回归

1. 所有文档修订先解析权威 Feature 目标，强制目标及 expected_revision；拒绝 payload 借道。
2. Run 保存独立不可变 ExecutionBindingLock；技术重试继承原 Run 的全部绑定，评审不得换回作者。
3. Requirement、plan、implementation、closure、merge_candidate 各自校验必需文档、来源、证据与引用；不接受供应商空成功。
4. Task 局部文档/Test 修订只失效该 Task 与 Feature 收尾/主干候选，不失效兄弟 Task 和已接受的需求规划。需求/设计变化仍要求重新规划。

验收：四项独立负向回归，加原有闭环、重启、取消和幂等测试。

## H2 领域模型与追踪

保留现有对象稳定 ID 与修订链，补充可校验的值对象和关系：Requirement 验收条目、Design 引用、Task 实现范围与测试、Test 映射、Run 执行绑定、Session/Snapshot 捕获来源。Workspace、Harness、Sandbox、Reviewer、Archive 明确区分定义、实例与契约，不为值对象添加管理服务。领域模型不得依靠 Markdown 关键词判定追踪完整。

迁移必须支持已有 v1 SQLite 数据集，不删库；历史未知信息标记为缺失/legacy，不伪造已执行事实。新增字段有明确默认与校验；新建交付采用增强约束。

验收：引用同属范围、修订不可变、测试对应验收项、局部影响传播、旧锁不被配置更新改变、旧库重开。

## H3 执行与副作用边界

将 Harness 轮询、测试执行、文件封存和 Sandbox 清理移出持有数据库写事务的执行阶段。先读取已登记意图，外部调用携带稳定 Run/operation ID，随后事务内核对状态和绑定，接收结果；取消/输入变化期间不得将延迟结果当成成功。产物导出成功后才允许释放资源。异常保留可重试/待核对记录。模拟 Git 与目标推进仍原子提交；真实 Git 推进必须通过显式幂等/核对契约实现，不可把外部副作用冒充 SQLite 原子事务。

为真实 Harness/GitHub/Docker 接入规定请求/结果、外部身份、版本与能力、取消确认、幂等、重复/延迟事件、清理和恢复契约。契约及实例必须被当前用例或契约测试使用，不仅写类型。

## H4 流程、文档与验收

维护需求 Review → Design/Task/Test 计划 Review → 初始 Snapshot → Task 独立执行/交付/Review/Merge → Feature 完整测试与文档收尾 → 主干候选验证/Review/接纳流程。冻结输入与新产生的阶段输出应明确区分；Web 保持全部操作入口，显示结构化追踪和执行绑定。

验证：Rust 全工作区；Web 类型检查/构建；HTTP 鉴权/生命周期；真实 Rust 后端 Web E2E；迁移、缺字段供应商、取消竞态和副作用顺序专项测试。运行平台仅据实记录，不将本机测试冒称双平台验收。

交付：更新领域/协议/架构与接入文档、验收记录和未完成项。完成结论必须逐项对照上述条件；若仍有缺口，明确记录，不宣称已具备真实生产执行能力。

## 完成判定与接入边界

本轮停止线仍是领域与架构基础，不连接真实账号/模型/容器。公共操作账本和恢复框架属于 H3，已经实现；真实供应商 SDK、版本/凭据配置、事件映射和供应商端去重/查询实现，以及对应真实用例，是下一轮接入工作。Archive/迁移执行、环境重建和 live 开放仍遵守本计划的原始边界。本轮不声称 Linux 复验或独立评审。
