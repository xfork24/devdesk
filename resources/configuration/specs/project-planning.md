# Task Plan 拆分规范

## 阶段意图

形成边界明确、依赖无环、验收覆盖完整的固定 TaskGroup。

## 输入与前置条件

已采纳 PRD、Design Doc、AC-* 编号、资源和执行约束。

## 必需交付内容

稳定任务标识；每项任务目标、范围和非目标；依赖 DAG；允许变更范围；逐项 AC 映射；测试分工与 TestRecipe 要求；并行与汇合条件；风险和阻塞。

## 内容与一致性检查

检查 DAG 无环、任务可交付、每项验收有责任任务，跨任务验收安排了 Feature 验证。任务不能只用模糊活动名称描述，必须给出可检查成果。

## 完成与拒绝标准

由项目规划职责提交 task_plan 提案并由人工采纳。执行中的范围变化应显式修订，不能静默替换冻结任务；尚未发生的实现结果不属于计划阶段完成条件。

## 工具与证据

当前 Step 引用本 Spec 的精确修订，并提供给执行 Agent 和独立评审。保留材料修订、代码或候选 SHA、命令、环境与真实结果，明确未运行和结果未知的事项。traceability、failure_paths、sections 只承担各自已经实现的有限自动检查，正文要求仍需基于内容和证据评审。
