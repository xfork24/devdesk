# Feature 完整验收规范

## 阶段意图

在 Task 汇合后验证 Feature 全部承诺和跨任务行为，形成完整收尾交付。

## 输入与前置条件

已接受的 Task 交付与汇合事实、Feature 当前代码 SHA、冻结需求、设计、TaskGroup 和测试计划。

## 必需交付内容

完整 AC 覆盖矩阵；跨 Task 集成、端到端与失败恢复验证；回归结果；文档与配置一致性；剩余风险；未完成项；后续候选验证安排。

## 内容与一致性检查

核对所有验收在当前 Feature 代码上有有效证据，Task 的局部通过不能自动证明跨任务行为；检查环境、版本和输出是否可追踪。

## 完成与拒绝标准

Feature 收尾交付经独立评审后进入候选流程。缺失完整验收、关键回归失败或材料与代码不一致应请求修改，不以任务数量完成代替产品行为完成。

## 工具与证据

当前 Step 引用本 Spec 的精确修订，并提供给执行 Agent 和独立评审。保留材料修订、代码或候选 SHA、命令、环境与真实结果，明确未运行和结果未知的事项。traceability、failure_paths、sections 只承担各自已经实现的有限自动检查，正文要求仍需基于内容和证据评审。
