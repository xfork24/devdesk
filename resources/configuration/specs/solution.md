# 方案交付规范

## 阶段意图

验证需求、设计、任务与测试计划构成一致且可执行的方案。

## 输入与前置条件

已经采纳的 PRD、Design Doc、固定 TaskGroup、TestPlan 及相应精确修订。

## 必需交付内容

需求到设计、Task 和 TestRecipe 的追踪关系；接口与边界；依赖与执行顺序；失败路径；环境和权限约束；关键风险、未决问题和验证方法。

## 内容与一致性检查

逐项检查验收覆盖、DAG 可执行性和测试配方，识别跨材料冲突。引用实际材料修订，说明方案验证执行内容及结果。

## 完成与拒绝标准

方案交付须经独立 Review。拒绝理由应针对当前方案缺陷；未来实现、Task Green 或 Feature 收尾尚未产生，不能当作本阶段必需证据。

## 工具与证据

当前 Step 引用本 Spec 的精确修订，并提供给执行 Agent 和独立评审。保留材料修订、代码或候选 SHA、命令、环境与真实结果，明确未运行和结果未知的事项。traceability、failure_paths、sections 只承担各自已经实现的有限自动检查，正文要求仍需基于内容和证据评审。
