# PRD 与需求阶段 Spec

## 阶段意图

明确用户问题和可验收需求，产出可采纳 PRD。

## 所需能力

需求分析与 PRD。Agent 必须引用相应 Skill；执行职责与写范围仍受内核规则约束。

## 必需交付内容

- 目标、用户、场景、范围及非目标。
- 约束、假设、依赖和未决问题。
- 稳定验收编号及可观察结果。
- 错误、失败、边界和恢复行为。

## 完成与拒绝标准

PRD 正文与验收字段一致，人工采纳后再进入正式需求验证与独立评审；未实现的未来代码不属于本阶段完成条件。

## 检查方式

由当前 Step 绑定本 Spec 精确修订，并提供给执行 Agent 与独立评审。Markdown 要求按内容和真实证据评审；现有 traceability、failure_paths、sections 只承担各自已实现的有限自动检查，不代表全文要求已自动验证。
