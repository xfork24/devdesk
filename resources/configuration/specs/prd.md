# PRD 与需求阶段规范

## 阶段意图

明确用户问题和可验收需求，产出可采纳的 PRD。

## 输入与前置条件

用户描述、项目约束、已有材料和原始问题；标记来源、假设与待确认项。

## 必需交付内容

目标与成功指标；用户与场景；范围和非目标；主流程；约束与依赖；稳定 AC-* 编号；失败、边界与恢复行为；未决问题。

## 内容与一致性检查

逐项核对正文与结构化验收是否一致，验收能否通过可观察结果判定，冲突和假设是否有处理方式。

## 完成与拒绝标准

PRD 经人工采纳后进入正式需求验证及独立评审。缺少未来代码实现不是本阶段拒绝理由；验收空洞、范围冲突或错误行为缺失应请求修改。

## 工具与证据

当前 Step 引用本 Spec 的精确修订，并提供给执行 Agent 和独立评审。保留材料修订、代码或候选 SHA、命令、环境与真实结果，明确未运行和结果未知的事项。traceability、failure_paths、sections 只承担各自已经实现的有限自动检查，正文要求仍需基于内容和证据评审。
