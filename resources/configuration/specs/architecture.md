# Design Doc 设计规范

## 阶段意图

把已采纳需求转为可实现、可验证的系统设计。

## 输入与前置条件

冻结 PRD、验收编号、现有架构、接口及部署约束。

## 必需交付内容

系统边界与职责；组件和数据流；接口与数据模型；权限与信任边界；兼容、迁移和回退；失败与恢复；替代方案及取舍；验证与可观测性。

## 内容与一致性检查

每个关键决策应可追踪到需求或约束；核对接口两端、状态变化和异常路径，说明未验证假设及验证计划。

## 完成与拒绝标准

设计讨论产出 design 提案并由人工采纳。方案不能以未知实现细节掩盖缺口，也不能把未运行的实验描述成已验证结论。

## 工具与证据

当前 Step 引用本 Spec 的精确修订，并提供给执行 Agent 和独立评审。保留材料修订、代码或候选 SHA、命令、环境与真实结果，明确未运行和结果未知的事项。traceability、failure_paths、sections 只承担各自已经实现的有限自动检查，正文要求仍需基于内容和证据评审。
