# Test Plan 测试设计规范

## 目标与适用边界

从用户验收和设计接口建立独立、可执行的验证方案。说明什么输入会触发什么可观察结果、测试在哪里运行，以及如何区分产品缺陷、测试错误和环境故障。

## 输入与前置条件

- 冻结需求、设计、TaskPlan、稳定 AC-* 及接口和状态不变量。
- 当前 Task 或 Feature 的测试范围、允许写入的测试目录、执行镜像/命令和依赖限制。
- 已知缺陷、已有独立测试和评审发现；标明可复用证据的版本与范围。

## 必需交付内容

### 用例与覆盖

每个用例包含前置状态、输入、操作、预期结果与验收编号；覆盖正常、非法输入、边界、权限、重复操作、中断恢复和失败反馈。

### 层次与归属

区分 Task 行为测试、跨 Task 集成测试和 Feature 完整流程，说明各层证明什么、不能证明什么。

### TestRecipe

提供实际测试文件、入口命令、环境、导入路径、输出和超时要求；路径与模块导出应能由设计及项目约束定位。

### 独立性

测试由测试职责独立编写，实现职责不可改写只读断言；外部服务用明确夹具隔离，夹具结果不能冒充真实服务验收。

### 失败分类

语法、依赖和环境错误与预期断言 Red 分开；说明产品实现缺失时如何以受控断言报告，而不吞掉其他导入错误。

### 证据与维护

规定运行后记录代码 SHA、测试修订、命令、环境、退出码和关键输出；补测与修订应保持稳定验收语义。

### 执行顺序

1. 先从每个 AC-* 和重要状态不变量推导可观察断言，再补充边界和故障场景。
2. 明确 Task 与 Feature 测试分工，给出独立、可复现的数据准备和清理策略。
3. 检查文件、导入路径、工具和环境约束，确保测试不会访问未授权目录或依赖未安装组件。
4. 提交当前输出端口所声明的 TestRecipe 或测试设计材料；计划未实际执行时，只给出设计证据与待执行项。

## 内容与一致性检查

- 预期结果能区分正确与错误实现，断言不只是调用成功或对象存在。
- 每个关键验收有对应测试，错误与恢复行为覆盖完整，范围与当前阶段一致。
- 环境准备错误不会被计为产品 Red；已通过的局部测试不会被扩大解释为完整 Feature 验证。
- 测试、设计和配方中的文件、命令、导出与依赖一致，不依靠隐藏安装或修改产品代码来运行。

## 完成与拒绝标准

用例、预期、覆盖和配方可供独立执行时，测试计划才可提交采纳。缺少断言、使用空壳测试、无法复现环境或混淆失败分类时应要求修订。

## 工具与证据

计划阶段保留 AC 与用例/配方映射；执行阶段提供真实执行回执、测试 Artifact、代码 SHA 和失败分类。未运行、受夹具限制和结果未知的范围必须明确。 自动规则只能核对当前配置声明的有限事实，不能替代上述内容评审。
