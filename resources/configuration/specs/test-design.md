# Test Plan 测试设计规范

## 阶段意图

建立独立于实现的验证策略，使每项验收具有可复现的测试配方。

## 输入与前置条件

冻结 PRD、Design Doc、TaskPlan、验收映射、运行环境与测试写权限。

## 必需交付内容

覆盖矩阵；单元、集成和端到端分层；正常、边界、错误和恢复场景；数据与环境；逐项 TestRecipe；命令、断言、超时、产物与清理；Task 和 Feature 验证边界。

## 内容与一致性检查

检查每个用例有明确预期结果、失败含义和执行前置条件；区分产品断言失败与环境不可用，说明无法自动验证的部分及替代证据。

## 完成与拒绝标准

测试职责提交 test_plan 并人工采纳。后续 Task 独立测试须取得真实断言 Red；仅有测试计划或命令文本不等同于测试已执行。

## 工具与证据

当前 Step 引用本 Spec 的精确修订，并提供给执行 Agent 和独立评审。保留材料修订、代码或候选 SHA、命令、环境与真实结果，明确未运行和结果未知的事项。traceability、failure_paths、sections 只承担各自已经实现的有限自动检查，正文要求仍需基于内容和证据评审。
