# 合入阶段综合规范

## 目标与适用边界

对精确源交付、目标基线和候选代码建立可核验的合入结论。候选准备、验证、独立评审、人类确认和推进分别记录，目标变化或结果未知时保持事实可恢复。

## 输入与前置条件

- 已接受源交付；Task 汇合使用当前 TaskScope，Feature 主线交付使用固定 FeatureScope 与完整验收。
- 冻结目标、预期目标 SHA、候选 SHA、候选真实父关系和来源回执。
- 候选测试配方、相关需求/设计/Spec、源交付证据及当前合入权限。

## 必需交付内容

### 候选来源

说明源交付、目标基线、候选 SHA 和实际父关系，引用候选构造及 Git 回执；不能只相信模型返回的候选字符串。

### 候选验证

在同一候选 SHA 上运行约定测试，记录环境、结果和范围；源分支上的旧 Green 不自动证明候选通过。

### 独立评审

核对差异、范围、AC、源交付、测试和失败恢复，按当前候选给出逐项结论，不把未来阶段要求施加到当前 Task 候选。

### 人工决定

主干推进遵守工作流的人类确认门禁；保留原始模型结论、人工决定及覆盖理由。

### 推进与封存

核对本地 CAS 和远端精确 lease，记录真实推进结果；保存交付快照与资源停止/释放回执。

### 执行顺序

1. 从协调器提供的候选来源证据确认源、目标和父关系，发现不一致先停止依赖该候选的判断。
2. 在候选上取得真实验证并独立评审，确认结论引用同一 SHA 和冻结边界。
3. 等待必要人工确认后由有权协调器推进；Agent 不自行执行合入、改写受保护 Git 元数据或宣称已推进。
4. 出现超时或回执丢失时先核对远端事实；目标或候选变化后重新验证，禁止盲目重发副作用。

## 内容与一致性检查

- 所有验证与评审引用同一源、目标和候选；候选实际父关系和交付来源一致。
- Task 与 Feature 的验收、测试及范围要求没有混淆，精确候选上的结果没有被源分支旧结果替代。
- 必要审批、人类决定、权限、CAS 与远端 lease 均有真实依据。
- 停止、释放和结果未知的处理明确；操作失败、未执行、已执行未确认是不同状态。

## 完成与拒绝标准

只有精确候选验证与独立评审通过、必要人类确认成立且目标仍匹配时才能推进。目标变化、候选不一致、权限不足或结果未知均不得当作成功；先核对事实或重新准备候选。

## 工具与证据

引用候选来源、Git SHA、测试 Run、评审、确认及推进回执；最后说明快照和资源释放事实。只报告已经观察到的状态，保留未确认结果供人工核对。 自动规则仅覆盖已实现的有限检查；traceability、failure_paths、sections 通过不能替代上述内容评审。
