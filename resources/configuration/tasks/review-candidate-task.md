# 独立评审 Task 候选

## 目标与适用边界

只读评价当前 Task 的精确候选、来源和验证事实。

## 输入与前置条件

- 本次 Step 或配方节点冻结的任务、Role/Skill/Spec 与输出合同；先确认对象、阶段、输入修订和职责。
- 已接受源交付；Task 汇合使用当前 TaskScope，Feature 主线交付使用固定 FeatureScope 与完整验收。
- 冻结目标、预期目标 SHA、候选 SHA、候选真实父关系和来源回执。
- 候选测试配方、相关需求/设计/Spec、源交付证据及当前合入权限。

## 必需交付内容

### 本次工作范围

- 核对源 Task 交付、冻结目标、候选 SHA、真实父关系及候选构造回执。
- 只按当前 Task 验收和自身 TestRecipe 检查差异、候选测试、范围及故障路径。
- 不要求未来 Feature 完整套件已存在，不触碰受保护 Git 元数据，不宣称已经合入。

### 内容与定位要求

围绕当前阶段交付具体事实、判断和缺口；引用 AC、Task、材料章节、实际文件或代码版本，说明范围与剩余限制。不能只重复章节标题或声称已检查。

### 返回内容与决策边界

严格输出当前 output_contract 规定的单个 JSON 对象：approve、summary、checks。checks 为 traceability、scope、tests、failure_paths 四类，各项给出 key、passed、evidence；依据当前 Skill 和 Spec 的真实内容填写，不固定为测试版标题或关键词。发现实质内容缺口时 approve=false，并指出具体位置、影响和改进内容。格式正确、外部调用成功或章节齐全均不足以 Approve。模型结论随后仍等待人类 Approve；人类覆盖 Reject 时保留原结论和理由。

## 内容与一致性检查

- 所有验证与评审引用同一源、目标和候选；候选实际父关系和交付来源一致。
- Task 与 Feature 的验收、测试及范围要求没有混淆，精确候选上的结果没有被源分支旧结果替代。
- 必要审批、人类决定、权限、CAS 与远端 lease 均有真实依据。
- 停止、释放和结果未知的处理明确；操作失败、未执行、已执行未确认是不同状态。
- 核对返回内容是否属于当前角色及节点范围，是否如实区分已执行、未运行、失败与未知结果。

## 完成与拒绝标准

本次内容判断已逐项给出证据，才可提交模型建议。存在缺口时明确 Reject，保留返工定位并等待人类决定。 只有精确候选验证与独立评审通过、必要人类确认成立且目标仍匹配时才能推进。目标变化、候选不一致、权限不足或结果未知均不得当作成功；先核对事实或重新准备候选。

## 工具与证据

使用所选 Harness 的原生读取、搜索及获准命令工具，执行以冻结 Permission 和当前节点范围为准；工具出现在目录中不代表已获写入或网络授权。历史经验由应用检索、选择并恢复后提供，须标注来源和适用条件，不能替代当前现场核实。 引用候选来源、Git SHA、测试 Run、评审、确认及推进回执；最后说明快照和资源释放事实。只报告已经观察到的状态，保留未确认结果供人工核对。
