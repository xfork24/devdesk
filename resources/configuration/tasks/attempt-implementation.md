# Task 实现公共任务

## 目标与适用边界

按当前 Task 的固定配方完成独立测试、实现、文档和真实验证。

## 输入与前置条件

- 本次 Step 或配方节点冻结的任务、Role/Skill/Spec 与输出合同；先确认对象、阶段、输入修订和职责。
- 冻结需求、设计、Task 范围、验收、依赖和独立 TestRecipe；确认依赖已满足。
- Task 工作树、基线与当前 SHA、可写路径和只读测试路径，保留用户已有修改。
- 本次执行配方、冻结权限、测试环境与已有评审发现；不把其他 Task 的任务上下文混入本次。

## 必需交付内容

### 本次工作范围

- 遵守测试编写、真实 Red、实现、Green、文档与 verify 的节点顺序，角色各自执行许可工作。
- 保护只读测试和用户改动，核对 Task 范围、设计接口、验收及当前代码版本。
- 汇总实际修改、测试回执、文档和局限；不把其他 Task 或完整 Feature 的结果混作本任务事实。

### 内容与定位要求

围绕当前阶段交付具体事实、判断和缺口；引用 AC、Task、材料章节、实际文件或代码版本，说明范围与剩余限制。不能只重复章节标题或声称已检查。

### 返回内容与决策边界

按当前 output_contract 返回本节点的执行摘要、实际产物与限制；不把执行摘要、结构化提案和内容评审报告混用。没有真实 Run 或回执时不得声称测试、交付或远端操作成功。

## 内容与一致性检查

- 测试断言可以因正确实现通过，并明确覆盖当前 Task 的正常、错误和边界行为。
- Red 是实际断言失败，Green 和 verify 来自当前代码；不存在伪造输出、复用失效报告或绕过测试。
- 实现符合设计接口、不变量与权限，未改写只读测试或混入其他任务变更。
- 只评当前 Task 的验收与配方，不以未来 Feature 完整套件尚不存在作为本任务拒绝理由。
- 核对返回内容是否属于当前角色及节点范围，是否如实区分已执行、未运行、失败与未知结果。

## 完成与拒绝标准

本节点所需材料或动作实际完成、返回结构合法且范围与证据明确后，才可提交下一门禁。 Task 的实现、独立测试、真实 Red/Green/verify、文档和追溯证据齐备后方可提交独立评审。任一关键结果缺失或无法证明对应代码版本时不得宣称完成；环境故障须单独处理。

## 工具与证据

使用所选 Harness 的原生读取、搜索及获准命令工具，执行以冻结 Permission 和当前节点范围为准；工具出现在目录中不代表已获写入或网络授权。历史经验由应用检索、选择并恢复后提供，须标注来源和适用条件，不能替代当前现场核实。 记录本节点真实执行与未执行事实，由协调器保存 Git 和测试回执。文件已修改、测试已调用、测试已通过、交付已接受和合入完成是不同事实，不得互相替代。
