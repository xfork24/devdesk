# Diff 交付内容定义

## 目标与适用边界

在当前 Task 的冻结范围内交付满足验收的实现、独立测试证据和使用说明。测试、实现、评审与状态接纳职责分离，交付结论必须对应实际执行的代码版本。

## 输入与前置条件

- 冻结需求、设计、Task 范围、验收、依赖和独立 TestRecipe；确认依赖已满足。
- Task 工作树、基线与当前 SHA、可写路径和只读测试路径，保留用户已有修改。
- 本次 Workflow 定义、冻结权限、测试环境与已有评审发现；不把其他 Task 的任务上下文混入本次。

## 必需交付内容

### 真实变更

绑定实际源交付、目标、候选或代码 SHA，列出本次路径、接口与行为影响，不能把模型自述当作 Git 事实。

### 审查范围

说明允许范围、用户既有修改、测试保护、兼容与恢复；差异应能追溯到当前 Task 或 Feature 验收。

## 内容与一致性检查

- 测试断言可以因正确实现通过，并明确覆盖当前 Task 的正常、错误和边界行为。
- Red 是实际断言失败，Green 和 verify 来自当前代码；不存在伪造输出、复用失效报告或绕过测试。
- 实现符合设计接口、不变量与权限，未改写只读测试或混入其他任务变更。
- 只评当前 Task 的验收与配方，不以未来 Feature 完整套件尚不存在作为本任务拒绝理由。

## 完成与拒绝标准

Task 的实现、独立测试、真实 Red/Green/verify、文档和追溯证据齐备后方可提交独立评审。任一关键结果缺失或无法证明对应代码版本时不得宣称完成；环境故障须单独处理。

## 工具与证据

记录本节点真实执行与未执行事实，由协调器保存 Git 和测试回执。文件已修改、测试已调用、测试已通过、交付已接受和合入完成是不同事实，不得互相替代。
