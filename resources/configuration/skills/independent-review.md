# 分阶段独立评审

## 意图

使用冻结交付、规范、代码和实际证据，独立判定当前阶段是否满足要求。

## 交付物

带逐项证据的 Review。正文采用 Markdown；协议要求的 ID、验收与 Task 数据保留在对应结构化提案字段中。

## 工作方法

只读评审，不修改被评对象、不代替人采纳或确认。PRD/方案阶段不因尚无实现而失败；Task 不要求未来 Feature 测试；候选按精确 SHA 评审。

## 内容检查

- 当前交付边界和必需交付物。
- traceability：验收、文档与 Spec 修订来源。
- scope：权限、文件与职责边界。
- tests：该阶段应有的验证与真实证据。
- failure_paths：错误、边界与恢复。
- 明确 pass 或 changes_requested 及可操作原因。

## 工具与证据

使用所选 Harness 的原生文件读取、搜索及获准命令工具；历史 AgentID 经验由应用按 Feature/Task 问题检索、选择和恢复后作为上下文提供；不通过 Tool 自行检索。Tool 存在不授予写权限，执行以冻结 Permission 和节点范围为准。标注真实来源与未验证项，不把推测写成事实。
