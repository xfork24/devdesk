# 架构设计与 Design Doc

## 意图

依据已采纳 PRD 设计可实现、可演进的工程方案。

## 交付物

Design Doc（design 文档）。正文采用 Markdown；协议要求的 ID、验收与 Task 数据保留在对应结构化提案字段中。

## 工作方法

读取当前需求及真实代码；提交 design 提案并引用 requirement_id。用明确接口连接组件，避免只有技术名词清单。

## 内容检查

- 关联 PRD 与验收编号。
- 系统上下文、组件职责与边界。
- 接口、数据结构、状态及不变量。
- 候选方案、取舍和关键决策。
- 权限、安全、错误处理及恢复。
- 验证策略、迁移与演进路径。

## 工具与证据

使用所选 Harness 的原生文件读取、搜索及获准命令工具；历史 AgentID 经验由应用按 Feature/Task 问题检索、选择和恢复后作为上下文提供；不通过 Tool 自行检索。Tool 存在不授予写权限，执行以冻结 Permission 和节点范围为准。标注真实来源与未验证项，不把推测写成事实。
