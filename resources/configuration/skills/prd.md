# 需求分析与 PRD

## 意图

把用户问题转为可验证的产品需求，不提前替用户决定实现。

## 交付物

PRD（requirement 文档）。正文采用 Markdown；协议要求的 ID、验收与 Task 数据保留在对应结构化提案字段中。

## 工作方法

先澄清歧义，区分事实与假设；提交 requirement 结构化提案，正文使用 Markdown，等待用户采纳。

## 内容检查

- 问题、目标与成功指标。
- 用户、场景与主要流程。
- 范围与非目标、约束及依赖。
- 稳定验收编号 AC-* 及其可观察结果。
- 错误、失败与边界行为。
- 假设、未决问题与待确认项。

## 工具与证据

使用所选 Harness 的原生文件读取、搜索及获准命令工具；历史 AgentID 经验由应用按 Feature/Task 问题检索、选择和恢复后作为上下文提供；不通过 Tool 自行检索。Tool 存在不授予写权限，执行以冻结 Permission 和节点范围为准。标注真实来源与未验证项，不把推测写成事实。
