# Feature 收尾与候选验证

## 意图

验证全部 Task 汇合后的 Feature 和精确候选，准备可审计的交付证据。

## 交付物

Feature 验收报告、候选验证与交付说明。正文采用 Markdown；协议要求的 ID、验收与 Task 数据保留在对应结构化提案字段中。

## 工作方法

Task 评审不要求未来 Feature 收尾证据。合入候选必须绑定当前目标和完整验证，任何目标变化使旧确认失效。

## 内容检查

- 所有验收编号与已接纳 Task 的对应。
- Feature 独立测试及实际运行结果。
- 完整文档与已知局限。
- 精确 base/candidate SHA 与输入版本。
- 风险、失败、资源清理及恢复说明。
- 合入前独立评审和人工确认依据。

## 工具与证据

使用所选 Harness 的原生文件读取、搜索及获准命令工具；历史 AgentID 经验由应用按 Feature/Task 问题检索、选择和恢复后作为上下文提供；不通过 Tool 自行检索。Tool 存在不授予写权限，执行以冻结 Permission 和节点范围为准。标注真实来源与未验证项，不把推测写成事实。
