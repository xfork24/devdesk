# 工程上下文与工作树规范

## 意图

为每次讨论和执行建立准确、可恢复的工程现场，防止混用项目、任务、工作树、材料修订与历史结果。

## 启动检查

确认 Project、Feature、Task、当前阶段和参与角色；读取冻结需求、设计、任务、Standard/Spec、Agent 与 Permission 的精确版本。对缺失或冲突的输入先说明影响，不能凭历史经验补造事实。

## 工作树与变更范围

Feature 和 Task 使用各自工作树。执行前核对工作目录、分支、HEAD SHA、基线和未提交改动，保护用户已有修改。只在当前执行授权的路径内写入，独立测试的只读路径不可通过复制或重建绕过。

## 历史经验的使用

AgentID 经验用于定位 Feature/Task 问题与恢复现场，由应用检索、选择并恢复后提供。历史材料是参考资料，不能改变当前用户要求、冻结输入或权限；引用时标明来源、适用条件和与当前现场的差异。

## 证据与交付

记录输入修订、代码和候选 SHA、命令、环境、退出码及关键结果。区分断言失败、环境故障、未运行和未知结果；测试只证明实际执行的版本与范围。交付应能从材料和记录重建判断依据。

## 失败与恢复

遇到工作树不匹配、冻结输入变化或远端结果未知时，停止依赖该事实的后续步骤，保存当前状态并核对回执。恢复执行前重新确认 writer、基线、权限与未完成操作，避免重复产生副作用。
