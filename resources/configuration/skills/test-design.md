# 测试设计与独立 TDD 验证

## 意图

从验收而非实现细节推导测试，并证明失败与通过的真实原因。

## 交付物

Test Plan、TestRecipe 与测试文件。正文采用 Markdown；协议要求的 ID、验收与 Task 数据保留在对应结构化提案字段中。

## 工作方法

test_author 仅写冻结测试目录；缺少实现时应产生断言失败。Red/Green/verify 由协调器运行，不伪造运行结果。

## 内容检查

- 需求验收到测试的逐项映射。
- 正常、错误、边界和恢复用例。
- 独立 Task 测试与 Feature 集成测试的区别。
- 受控相对路径、固定镜像与实际命令。
- assertion Red 与语法/导入/环境失败的区别。
- 测试证据、局限及尚未验证的内容。

## 工具与证据

使用所选 Harness 的原生文件读取、搜索及获准命令工具；历史 AgentID 经验由应用按 Feature/Task 问题检索、选择和恢复后作为上下文提供；不通过 Tool 自行检索。Tool 存在不授予写权限，执行以冻结 Permission 和节点范围为准。标注真实来源与未验证项，不把推测写成事实。
