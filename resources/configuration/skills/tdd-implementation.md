# Task 实现、验证与文档方法

## 目标与适用边界

遵循真实 Red、受限实现、Green、回归与 verify 顺序，把代码行为、测试事实和使用说明连接起来。

## 输入与前置条件

- 冻结需求、设计、Task 范围、验收、依赖和独立 TestRecipe；确认依赖已满足。
- Task 工作树、基线与当前 SHA、可写路径和只读测试路径，保留用户已有修改。
- 本次 Workflow 定义、冻结权限、测试环境与已有评审发现；不把其他 Task 的任务上下文混入本次。

## 必需交付内容

### 独立测试与 Red

测试职责在授权测试目录编写行为断言，实际运行取得预期断言失败；缺少实现与语法、传递依赖、环境问题必须精确区分。

### 实现

开发职责在允许路径实现设计接口、正常与失败行为，保持独立测试不变，不通过跳过、删除、复制改写测试来取得通过。

### Green 与 verify

使用约定配方在当前实现版本上取得真实 Green，并完成必要回归和交付验证；变更测试、配方或代码后重新确认相关结果有效性。

### 文档与追溯

说明导出接口、使用方式、输入输出、AC 映射、失败示例及限制；引用实际文档和代码位置。

### 交付证据

提供输入修订、测试定义、代码 SHA、执行回执/Artifact、命令、环境、退出码和关键输出，说明未执行及未知范围。

### 执行顺序

1. 核对任务、工作树和权限，读设计、验收与独立测试；发现输入冲突先提出明确修订需求。
2. 按当前 Workflow 声明的测试编写、真实 Red、实现、Green、文档、verify 顺序推进，角色只完成本节点授权工作。
3. 检查差异是否仅属于当前 Task，处理本任务内缺陷并记录范围外问题。
4. 把实现及实际证据交给独立 Reviewer；未完成正式 Review 或人类门禁前不宣布交付已接受或已合入。

## 内容与一致性检查

- 测试断言可以因正确实现通过，并明确覆盖当前 Task 的正常、错误和边界行为。
- Red 是实际断言失败，Green 和 verify 来自当前代码；不存在伪造输出、复用失效报告或绕过测试。
- 实现符合设计接口、不变量与权限，未改写只读测试或混入其他任务变更。
- 只评当前 Task 的验收与配方，不以未来 Feature 完整套件尚不存在作为本任务拒绝理由。

## 完成与拒绝标准

Task 的实现、独立测试、真实 Red/Green/verify、文档和追溯证据齐备后方可提交独立评审。任一关键结果缺失或无法证明对应代码版本时不得宣称完成；环境故障须单独处理。

## 工具与证据

使用所选 Harness 的原生读取、搜索及获准命令工具，执行以冻结 Permission 和当前节点范围为准；工具出现在目录中不代表已获写入或网络授权。历史经验由应用检索、选择并恢复后提供，须标注来源和适用条件，不能替代当前现场核实。 记录本节点真实执行与未执行事实，由协调器保存 Git 和测试回执。文件已修改、测试已调用、测试已通过、交付已接受和合入完成是不同事实，不得互相替代。

## 当前执行合同

以本次 `task_instructions`、`inputs`、`input_sources`、`outputs` 和 `output_contract` 为执行依据。材料已经通过 Workflow 端口接纳时，不再要求额外的提案采纳或未声明的文档 ID。只在本次任务确实缺少必要事实时请求补充输入。若当前未授予代码视图，明确这一限制，不虚构读取结果；能够基于当前明确事实完成的设计或检查应继续完成。

## 跨步骤证据交付

当前 Step 声明 evidence 输出时，必须提交实际逐次执行的原始日志、退出码、起止时间、命令、目录及该次测试和实现的完整内容快照与 SHA-256。输出值将由平台密封为持久化 Artifact，后续步骤只能通过 Workflow 显式声明的输入引用读取。临时目录、单个摘要、测试通过声明或要求协调方另行保存，均不能代替该输出。Agent 自行记录与平台回执分别标注；缺少历史记录时如实阻塞，不能用重跑补造实现前失败。

当前 Task 或设计明确规定多个 TDD 增量时，必须逐增量执行并保留各自真实 Red/Green，不能把多轮义务改称建议或用一次完整实现替代。独立 tests 目录保持只读；开发职责可以在其他明确授权路径维护自己拥有的增量测试，中间阶段只对该增量的目标用例取得 Green，全部增量完成后再通过独立全量套件。交付前逐项对照冻结计划与实际记录，缺少任一历史阶段即返回 blocked，文档不得宣称已满足。
