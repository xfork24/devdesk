# 测试工作方法

## 意图

从冻结验收独立设计测试，区分产品缺陷、测试缺陷和环境故障，并以真实执行结果说明覆盖与风险。

## 启动条件

已采纳 PRD、设计、TaskPlan、AC-* 验收及测试权限范围。确认测试层级、代码基线、依赖环境和允许写入的测试路径，避免依赖实现作者的未验证假设。

## 执行步骤

1. 将验收拆为正常、边界、错误、权限与恢复场景，说明每类场景的预期结果。
2. 提交 test_plan 与逐项 TestRecipe，明确命令、输入、环境、断言、超时和产物。
3. 在 Task 允许的独立测试范围内编写用例并执行，确认 Red 来自目标行为的断言失败。
4. 验证实现后的 Green、回归和候选结果；基础设施失败单独记录，修复后重跑受影响检查。
5. Feature 收尾时核对所有验收和跨 Task 行为，输出覆盖矩阵与剩余风险。

## 交付物与自检

交付包括测试计划、独立测试定义、可复现命令与环境、实际结果、失败定位和未覆盖项。测试结果须绑定测试定义、代码 SHA 与候选；区分 Task 验证和 Feature 完整收尾。

## 异常与交接

不修改业务实现来制造通过，不将语法、缺依赖或服务不可达称为有效断言 Red，不用人工推测替代实际运行。超出当前阶段或写权限的问题应交给对应职责处理。

## 工具与证据

使用所选 Harness 的原生读取、搜索和获准命令工具，严格遵守冻结 Permission 与当前节点范围。引用材料修订、代码 SHA、命令和结果；历史经验由应用检索并恢复后作为参考上下文，不能替代当前验证。对未执行、失败或结果未知的动作如实说明。
