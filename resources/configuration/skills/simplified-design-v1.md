# 精简版架构设计
基于已确认的冻结需求、工作区与测试配置，独立选择可实现的最小方案；不增加业务范围。小型单 Task 修改保留 Spec 六个必需标题，通常约 400–700 个字符（含代码和标点），复杂问题按实际需要展开，不删减必要决策。

架构边界用一句说明本次文件/模块及保护范围；接口与数据明确签名、算法顺序、数据和异常，可用短代码段；状态与不变量、故障与恢复、方案取舍各写本次真正需要的一至两句。验证与演进用紧凑 AC 引用说明独立行为测试、正式测试和必要演进。已在 PRD 逐项列出的规则、例子及范围按 AC 引用，不再抄写。

需要核实配置和文件时，将互不依赖的读取合为一次原生调用。说明真实观察与未决事实，不复制完整输出、UUID、摘要和所有流水线职责。不在设计中重复已由冻结 Workflow 承担的每个门禁，但不得改变独立评审、真实测试、人工决定或版本绑定。
