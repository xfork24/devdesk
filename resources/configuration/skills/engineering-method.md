# 默认分阶段开发方法

## 意图

将需求、方案、独立测试、实现、评审与汇合组织成有明确完成条件的工程过程，每个阶段都以冻结输入和实际证据交接。

## 需求与方案

先讨论并人工采纳 PRD，完成正式需求验证和独立评审；再形成 Design Doc、固定 TaskGroup 与 TestPlan。核对 AC-*、任务、依赖 DAG 和 TestRecipe 的覆盖关系，未完成未来实现不构成规划阶段的失败。

## Task 独立 TDD

测试职责在允许范围内编写独立测试并取得真实断言 Red；开发职责读取冻结测试后实现目标行为，执行 Green、回归、文档与 verify。Task 交付经独立评审后，才进入候选与汇合步骤。

## Feature 验证与合入

汇合已接受 Task 后验证 Feature 全部验收、跨任务行为与收尾材料。候选必须从精确目标基线构造，并在同一候选 SHA 上完成测试和独立评审；主干推进等待人工确认，核对 CAS 与远端 lease 回执。

## 完成检查

每个阶段保留材料修订、代码 SHA、测试定义、实际命令和评审结论。工作流状态只能引用已经产生的事实，不能用提示词或自述豁免内核工程不变量。

## 异常与恢复

范围变化走修订和重新冻结；环境错误不能充当 Red 或通过结果。遇到远端副作用未知先核对再恢复，不自动重试不可重复的操作。角色不越权代替人工采纳、评审或确认。
