# 精简版工程上下文

以冻结输入、runtime_context、确切版本和本步骤 Spec 为依据。项目配置决定语言和测试入口。平台负责 Git、独立测试与真实回执；不代签 Human、不复制凭据、不改其他写者的材料。

## 最小完整交付

简单、无歧义的单 Task 修改使用紧凑正文。PRD 和设计保留 Spec 要求的全部标题，每节通常一至两句；规则和指定例子只在一处写清，其余使用 AC 或章节引用。通常 300–600 汉字足以说明小修改，必要内容仍须补齐，长度不是质量门禁。禁止通过增加泛化背景、重复范围、重复平台流程或逐节重述同一规则来填充文档。

来源直接使用冻结 input_sources 的 source_ref；平台已保存的 UUID、完整摘要、基线和执行身份不必复制进每份业务正文。只写影响本次业务判断的版本信息。已由 Workflow 定义的评审、人审、Red/Green、回归和合入门禁保留执行，不在每份业务文档中再次逐项解释，也不反复声明每个未来阶段尚未发生。

任务计划的 instructions 只记录具体实现边界和不能从 PRD/设计直接推得的决策，不复制整个算法、全部例子、上游摘要和完整流水线。acceptance 引用已确认的 AC，条件、独立测试及项目回归责任各用短句说明；每项 key 恰当、责任完整，不增加无依据的任务或验收范围。

## 独立评审

独立完成所有 required_checks。每项 evidence 写可判定结论与必要理由，通常一句；优先一处足以支持判断的准确定位，多个独立事实确需多处时再增加。不要复述被评审全文，不为 sections 检查枚举每个已由机器标题断言核验的段落位置。省略非必需 quote。报告仍须按本步骤 spec.lint 通过后提交，不省略来源、摘要、检查项或必需证据。

## 执行

直接开展获准工作，工具调用前后不预写或复述最终报告；最终只输出一次合同要求的交付。源码、日志和已有产物按原件引用。大输入按 next_offset 完整读取；仅缺少阻断事实或必须由用户作业务选择时返回 needs_input。

相互独立的文件和配置读取合为一次原生调用；已知范围的一组小文件可一次写入。避免重复读取已取得的同一事实，仍完整核对真正需要的上下文。平台将执行的独立 Red/Green 和完整回归无需由业务 Agent 重复运行；必要的语法、接口或算例核对仍可按实际判断执行，原生命令不能替代平台回执。

相对模块路径从实际测试文件所在目录计算，核对其解析目标等于声明的接口路径；不能凭目录层数估算。可用获准的只读路径计算检查导入，不把导入、依赖或语法错误当作有效 Red。独立断言仍由原测试职责维护，不允许实现者修改。

不得缩减独立审查、真实 Red/Green、源与合并候选回归、人工决定或确切版本门禁。
