# 默认工程 Standard

## 意图与适用范围

定义从需求到交付的通用工程约束，用于项目、Feature、Task 与合入过程。Standard 选择精确 Spec 修订；工作流可组织步骤，但不能豁免内核的权限、冻结、测试、评审及合入不变量。

## 需求与方案基线

需求先经讨论、人工采纳、正式验证和独立评审。设计、固定 TaskGroup 与测试计划需引用一致的验收编号，说明边界、依赖、错误行为和验证方法；范围变化通过明确修订处理。

## 独立测试与 TDD

测试职责先在授权路径内编写独立测试并取得真实断言 Red，开发职责依据冻结输入实现并取得 Green、回归和 verify。语法、依赖或环境失败不能替代 Red，未经运行不能声称通过。

## 工作树与职责分离

Project、Feature、Task 的上下文和工作树必须准确；冻结 Permission 限定读写、网络和命令范围。保护用户改动与只读测试，执行者不得接受自己的交付，Agent 不能代用户采纳或确认。

## 交付与独立 Review

每次交付引用精确输入、代码 SHA、测试定义、真实执行和文档。Reviewer 根据当前阶段对应 Spec 逐项给出结论。Task 验证本任务；Feature 收尾验证完整验收和跨任务行为，不互相替代。

## 候选验证与合入

已接受源交付基于精确目标构造候选，在同一候选 SHA 上测试和独立评审；主干推进等待人工确认，并核对本地 CAS 与远端精确 lease。目标或候选改变后重新验证，结果未知先核对远端事实。

## 证据、失败与恢复

记录材料修订、环境、命令、退出码和关键输出，标注未运行、失败和未知结果。失败应区分产品、测试及环境原因；恢复前核对现场、writer、冻结输入与回执，避免重复副作用。

## 完成判断

依本 Standard 绑定的 planning、implementation、merge Spec 检查对应阶段；自动检查的通过仅覆盖已实现规则。任何遗漏、例外或剩余风险都需具体说明并交给有权决策者处理，不以模糊“已验证”代替证据。
